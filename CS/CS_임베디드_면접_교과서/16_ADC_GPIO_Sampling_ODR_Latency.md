## 100ms의 의미

100ms는 0.1초입니다. 주파수로는 10Hz입니다.

```text
100ms = 0.1s
1 / 0.1s = 10Hz
```

즉, 100ms마다 sampling한다는 것은 1초에 10번 값을 읽는다는 의미입니다.

## ADC

ADC는 Analog-to-Digital Converter입니다. 아날로그 전압을 디지털 값으로 변환합니다.

예:

- 가변저항 값
- 배터리 전압
- 아날로그 거리 센서
- 전류 센서

ADC를 사용할 때 고려할 것:

- ADC resolution
- sampling time
- conversion time
- reference voltage
- noise
- filtering

## GPIO

GPIO는 General Purpose Input/Output입니다. 디지털 0 또는 1을 읽거나 출력합니다.

예:

- 버튼 입력
- limit switch
- relay 제어
- LED 출력

GPIO 입력에서는 debounce가 중요할 수 있습니다. 버튼이나 스위치는 물리적으로 튀는 신호가 생기기 때문입니다.

## ODR

ODR은 Output Data Rate입니다. 센서가 새 데이터를 제공하는 속도입니다.

예를 들어 센서 ODR이 5Hz라면, 센서는 1초에 5번만 새 값을 제공합니다. 이 센서를 100Hz로 읽어도 같은 값을 반복해서 읽을 수 있습니다.

따라서 sampling 주기를 정할 때 센서 데이터시트의 ODR을 봐야 합니다.

## Latency

Latency는 입력이 들어온 뒤 시스템이 반응하기까지 걸리는 시간입니다.

상태 모니터링에서는 100ms 지연이 허용될 수 있지만, 모터 제어 loop나 충돌 회피에서는 너무 느릴 수 있습니다.

## 너무 빠르게 샘플링하면

- ADC 변환과 filtering 부하가 늘어납니다.
- UART/CAN 전송량이 증가합니다.
- 상위 시스템 parsing 부하가 늘어납니다.
- 의미 없는 중복 데이터를 많이 읽을 수 있습니다.
- 노이즈까지 더 많이 관측될 수 있습니다.

## 너무 느리게 샘플링하면

- 빠른 상태 변화를 놓칠 수 있습니다.
- 이상 감지가 늦어집니다.
- 제어 loop에 필요한 최신성이 부족해집니다.
- 사용자 화면 표시가 둔하게 느껴질 수 있습니다.

## 100ms를 설명하는 좋은 방식

면접에서는 "그냥 적당해서"라고 말하면 약합니다. 아래 근거를 같이 말해야 합니다.

- 센서 ODR
- 측정 대상의 변화 속도
- MCU 처리 부하
- 통신 전송량
- 상위 대시보드 갱신 주기
- 요구 latency

## 면접 답변으로 연결

### 30초 답변

> 100ms는 10Hz sampling 주기입니다. 이 주기는 센서의 output data rate, 측정 대상의 변화 속도, MCU 처리 부하, UART 전송량, 상위 대시보드 갱신 주기를 함께 고려해 정해야 합니다. 상태 모니터링 목적이라면 10Hz로도 충분할 수 있지만, 모터 제어용 encoder나 IMU처럼 빠른 제어에 쓰이는 데이터라면 더 높은 주기가 필요합니다. 너무 빠르면 MCU와 통신 부하가 커지고, 너무 느리면 이상 상태 감지가 늦어질 수 있습니다.

## 내 프로젝트로 연결하는 문장

> STM32 센서 데이터를 웹 대시보드에 표시하는 모니터링 목적이라면 100ms는 화면 갱신과 MCU 부하 사이의 타협값이라고 설명할 수 있고, 근거로 센서 ODR과 UART 전송량을 제시해야 합니다.
