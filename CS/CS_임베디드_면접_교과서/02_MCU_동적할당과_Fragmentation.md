## 핵심 개념

동적 할당은 실행 중 필요한 크기의 메모리를 heap에서 빌려 쓰는 방식입니다. PC 프로그램에서는 흔히 사용하지만, MCU 펌웨어에서는 조심해서 사용해야 합니다.

이유는 크게 네 가지입니다.

1. RAM이 작다.
2. 할당 시간이 일정하지 않다.
3. heap fragmentation이 생길 수 있다.
4. 할당 실패 시 시스템이 불안정해질 수 있다.

## Heap Fragmentation

Fragmentation은 heap 공간이 조각조각 나뉘어, 전체 여유 공간은 충분해 보여도 연속된 큰 공간을 할당하지 못하는 상태입니다.

예를 들어 RAM에 1000 byte가 있고 아래처럼 할당했다고 가정합니다.

```text
[100 사용][200 사용][100 사용][300 사용][300 여유]
```

중간의 200 byte와 300 byte를 해제하면 총 여유 공간은 500 byte입니다.

```text
[100 사용][200 여유][100 사용][300 여유][300 사용]
```

하지만 400 byte짜리 연속 공간이 없으면 400 byte 할당은 실패할 수 있습니다. 이것이 fragmentation 문제입니다.

## 실시간성 문제

임베디드 제어에서는 "언젠가 처리된다"보다 "정해진 시간 안에 처리된다"가 중요합니다.

동적 할당은 다음 이유로 실시간성을 해칠 수 있습니다.

- heap에서 빈 공간을 찾는 시간이 매번 달라질 수 있습니다.
- fragmentation이 심하면 할당 시간이 길어질 수 있습니다.
- 최악의 경우 할당에 실패할 수 있습니다.
- 실패 처리가 부족하면 시스템이 멈출 수 있습니다.

예를 들어 모터 제어 loop가 1ms마다 돌아야 하는데, 중간에 `malloc`이 예상보다 오래 걸리면 제어 주기가 흔들릴 수 있습니다.

## 대안

MCU에서는 아래 방식이 더 안정적입니다.

### 정적 할당

```c
static uint8_t uart_rx_buffer[256];
```

크기가 고정된 buffer를 미리 확보합니다.

### Memory Pool

같은 크기의 block을 미리 여러 개 만들어 두고 빌려 씁니다. 일반 heap보다 예측 가능합니다.

### Ring Buffer

UART 수신처럼 연속 데이터가 들어오는 경우 고정 크기 순환 buffer를 사용합니다.

```text
[0][1][2][3][4][5][6][7]
        read     write
```

## 면접 답변으로 연결

면접에서는 "동적 할당은 절대 안 됩니다"라고 말하기보다, "제약이 큰 MCU와 실시간 제어에서는 조심해야 한다"고 말하는 것이 정확합니다.

### 30초 답변

> MCU에서는 RAM이 제한적이고 실시간성이 중요하기 때문에 동적 할당을 조심해야 합니다. `malloc`, `free`를 반복하면 heap fragmentation이 생겨 전체 여유 메모리는 있어도 연속 공간을 확보하지 못할 수 있습니다. 또 할당 시간이 일정하지 않아 제어 loop의 latency가 흔들릴 수 있습니다. 그래서 UART buffer나 센서 buffer처럼 크기가 예측 가능한 데이터는 정적 할당, ring buffer, memory pool을 사용하는 편이 안전합니다.

## 내 프로젝트로 연결하는 문장

> STM32와 Raspberry Pi 사이 UART 통신에서는 수신 문자열 길이를 제한하고 고정 크기 ring buffer를 쓰는 방식이 동적 할당보다 안정적인 설계라고 설명할 수 있습니다.
