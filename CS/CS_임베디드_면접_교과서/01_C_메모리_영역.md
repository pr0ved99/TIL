## 핵심 개념

C 프로그램의 메모리는 보통 아래 영역으로 나누어 설명합니다.

| 영역 | 저장되는 것 | 특징 |
| --- | --- | --- |
| Code 또는 Text | 실행 코드 | 보통 Flash/ROM에 저장 |
| Data | 초기값이 있는 전역 변수, static 변수 | 프로그램 시작 시 값이 존재 |
| BSS | 초기값이 없는 전역 변수, static 변수 | 시작 시 0으로 초기화 |
| Stack | 함수의 지역 변수, 매개변수, return address | 함수 호출/종료에 따라 자동 관리 |
| Heap | `malloc`, `free`로 할당하는 동적 메모리 | 개발자가 직접 관리 |

임베디드에서는 PC보다 RAM이 작기 때문에 이 구분이 중요합니다. 특히 stack과 heap은 같은 RAM 안에서 사용되는 경우가 많고, 잘못 사용하면 서로 충돌하거나 시스템이 멈출 수 있습니다.

## Stack

Stack은 함수가 호출될 때마다 임시로 필요한 데이터를 저장하는 영역입니다.

예를 들어 아래 코드에서 `x`, `y`, `result`는 보통 stack에 저장됩니다.

```c
int add(int x, int y)
{
    int result = x + y;
    return result;
}
```

Stack의 특징은 다음입니다.

- 함수가 호출되면 자동으로 확보됩니다.
- 함수가 끝나면 자동으로 해제됩니다.
- 접근 속도가 빠릅니다.
- 크기가 제한적입니다.
- 재귀 호출이나 큰 지역 배열을 사용하면 stack overflow가 날 수 있습니다.

임베디드 면접에서는 "큰 배열을 지역 변수로 두는 것은 위험할 수 있다"고 말할 수 있어야 합니다.

```c
void read_sensor(void)
{
    uint8_t buffer[10000]; // 작은 MCU에서는 위험할 수 있음
}
```

## Heap

Heap은 실행 중에 필요한 만큼 메모리를 할당하는 영역입니다.

```c
uint8_t *buffer = malloc(1024);
if (buffer != NULL) {
    // use buffer
    free(buffer);
}
```

Heap은 유연하지만, 임베디드에서는 조심해야 합니다.

- 할당 실패 가능성이 있습니다.
- 할당/해제 시간이 일정하지 않을 수 있습니다.
- 반복 사용 시 fragmentation이 생길 수 있습니다.
- `free`를 빼먹으면 memory leak이 생깁니다.

## Static / Global

전역 변수와 static 변수는 프로그램 실행 중 계속 살아 있습니다.

```c
static int count = 0;
int global_state = 1;
```

특징은 다음입니다.

- 프로그램 시작 시 메모리가 정해집니다.
- 실행 중 주소가 유지됩니다.
- MCU에서는 메모리 사용량을 예측하기 좋습니다.
- 너무 많이 쓰면 RAM을 계속 점유합니다.

임베디드에서는 예측 가능성이 중요하기 때문에, 고정 크기 buffer나 상태 변수는 static/global로 두는 경우가 많습니다.

## 면접 답변으로 연결

면접에서는 아래 순서로 답하면 좋습니다.

1. 영역을 구분한다.
2. 각 영역의 생명주기와 관리 주체를 말한다.
3. MCU에서는 RAM이 작기 때문에 stack/heap 사용에 주의한다고 연결한다.

### 30초 답변

> C 메모리는 code, data/static, stack, heap으로 나눌 수 있습니다. code에는 실행 코드가 있고, static/global 영역에는 전역 변수와 static 변수가 저장됩니다. stack은 함수 호출 시 생기는 지역 변수와 return address가 저장되고 함수가 끝나면 자동 해제됩니다. heap은 `malloc`, `free`로 실행 중 동적으로 관리하는 영역입니다. MCU에서는 RAM이 작기 때문에 큰 지역 변수로 stack overflow가 나거나 heap 사용으로 fragmentation이 생기지 않도록 주의해야 합니다.

## 내 프로젝트로 연결하는 문장

> STM32 프로젝트에서 UART 수신 buffer나 센서 상태값은 실행 중 크기가 자주 변하는 데이터가 아니므로, 동적 할당보다 고정 크기 buffer를 사용하는 방식이 더 안정적이라고 설명할 수 있습니다.
