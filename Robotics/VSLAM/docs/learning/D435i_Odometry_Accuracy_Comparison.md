# D435i Odom Accuracy Comparison

## 결론

- `D435i 단독 RGB-D odom`은 실내 짧은 구간 테스트용으로는 가능하지만, 자율주행 메인 odom으로는 불안정할 수 있다.
- `D435i + 내장 IMU`는 `D435i 단독`보다 회전 시작/끝을 조금 더 안정적으로 볼 가능성은 있지만, **정확도가 크게 뛰는 조합은 아니다**.
- `D435i + wheel encoder + 외부 IMU`가 자율주행용 odom으로는 가장 실용적이다.
- 너희 프로젝트처럼 최종적으로 실외 자율주행까지 가야 한다면, **D435i는 보조**, `wheel odom + IMU + GPS`가 중심이 되는 구조가 맞다.

## 먼저 알아둘 개념

- `odometry`: 직전 상태에서 지금 얼마나 움직였는지 추정하는 값이다.
- `wheel encoder`: 바퀴가 얼마나 돌았는지 측정하는 센서다.
- `IMU`: 가속도계와 자이로를 합친 센서다. 회전과 가속 변화를 본다.
- `drift`: 작은 오차가 시간이 지나며 누적되는 현상이다.
- `VIO`: 카메라와 IMU를 같이 써서 움직임을 추정하는 방식이다.

## 왜 이 비교가 중요한가

실시간으로 화면이 잘 보이는 것과 `odom`이 정확한 것은 다르다.

- `realsense-viewer`는 현재 프레임을 잘 보여주면 된다.
- 자율주행 `odom`은 프레임과 프레임 사이 움직임을 계속 정확히 추정해야 한다.

즉, 센서가 살아 있는 것과 자율주행용 위치추정이 믿을 만한 것은 다른 문제다.

## 항목별 해석

### 1. D435i 단독 RGB-D odom

직관:

- 카메라가 보는 화면의 특징점과 depth를 이용해 움직임을 계산한다.

현실:

- 실내, 짧은 거리, 천천히 움직이는 테스트에는 쓸 만하다.
- 하지만 아래 조건에서 쉽게 흔들린다.
  - 흰 벽
  - 반복 무늬
  - 창문 역광
  - 빠른 손 움직임
  - 실외 햇빛

즉, `학습용`, `초기 bring-up`, `맵핑 성공 경험`에는 좋지만, 최종 주행용 메인 odom으로는 불안정할 수 있다.

### 2. D435i + 내장 IMU

직관:

- 카메라만 쓰는 것보다 회전 정보가 추가되니 더 좋아 보인다.

현실:

- 어느 정도 맞다.
- 하지만 D435i 내장 IMU는 `rate`는 좋아도, `정밀한 주 odom 센서`라고 보기는 어렵다.

왜냐하면:

- bias가 있다.
- 가속도를 적분해서 위치를 얻으면 drift가 빨리 커진다.
- 자이로도 장시간 누적하면 자세 drift가 생긴다.

즉, 내장 IMU는 **보조 정보**로는 의미가 있지만, 이것만 믿고 odom 정확도가 크게 올라가길 기대하면 안 된다.

### 3. D435i + wheel encoder

직관:

- 바퀴가 얼마나 돌았는지는 로봇 이동량과 직접 연결된다.

현실:

- 저속, 평탄한 바닥, 짧은 구간에선 매우 실용적이다.
- 특히 카메라가 특징점을 못 볼 때 버텨주는 역할이 크다.

약점:

- 바퀴가 헛돌면 오차가 누적된다.

즉, camera-only보다 실용성이 훨씬 높다.

### 4. D435i + wheel encoder + 외부 IMU

직관:

- 바퀴는 이동량, IMU는 회전 변화, 카메라는 시각 보정 역할을 한다.

현실:

- 이 조합이 가장 균형이 좋다.
- 자율주행용 `odom`으로는 가장 먼저 추천할 만한 구조다.

다만 전제조건:

- `frame transform(TF)`가 맞아야 한다.
- `timestamp sync`가 맞아야 한다.
- IMU 축 방향이 맞아야 한다.
- 센서 융합 필터 설정이 맞아야 한다.

## 실무 추천 순서

### 지금 단계

- `D435i 단독 RGB-D odom`으로 실내 짧은 구간 테스트
- 목적:
  - 카메라 기반 odom이 어떻게 흔들리는지 체감
  - 맵이 쌓이는 조건과 실패 조건 이해

### 다음 단계

- `wheel encoder + IMU` 준비
- `robot_localization` 같은 필터로 융합 시작

### 최종 자율주행 단계

- 실내/근거리: `wheel + IMU + D435i`
- 실외/전역: `wheel + IMU + GPS`
- D435i는 맵핑, 근거리 장애물, 보조 odom 역할

## 너희 프로젝트 기준 추천

### 지금 당장

- `RTAB-Map`으로 `D435i 단독 RGB-D odom` 한계 확인

### 로봇 하드웨어가 붙으면

- `wheel encoder + IMU`를 메인 odom으로 두기
- D435i는 visual 보조로 추가하기

### 실외 공터 자율주행까지 가면

- `GPS + wheel encoder + IMU`를 중심으로 가기
- D435i는 `근거리 인지`, `맵 보조`, `시각 디버깅` 쪽이 현실적이다

## 한 줄 요약

- `D435i 단독`: 학습용/초기 실험용
- `D435i + 내장 IMU`: 약간 개선될 수 있지만 한계 큼
- `D435i + wheel encoder + 외부 IMU`: 자율주행용 odom으로 가장 현실적
