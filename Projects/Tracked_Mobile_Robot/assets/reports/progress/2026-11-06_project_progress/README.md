## 집계 방법과 한계

1. **선정 단위:** 설계 기준선, 기능 경로의 보드 검증, 제작 단계, 통합 관측, 주요 시연 결과, PCB 설계·학습 묶음 중 대표적인 결과 1건을 1로 센다. 반복 시험·커밋·외부 게시·학습 소절 수를 별도 성과로 늘리지 않는다. 선정에는 편집 판단이 들어가며 전수 집계가 아니다.
2. **날짜:** `docs/progress/YYYY-MM-DD_progress.md`의 작업 날짜를 사용한다. 여러 날에 걸친 작업은 해당 기록일에 묶었다. 6/8은 확인한 진행 기록의 시작이며 실제 프로젝트 착수일이라고 단정하지 않는다. 11/5 학습의 11/6 게시를 별도 성과로 중복 계산하지 않는다.
3. **누적 진도:** 해당 날짜까지 선정 성과의 누적 개수다. 모든 날짜를 같은 간격으로 표시한다. 과거에 관측한 제한된 결과를 누적하며 현재 모든 조건에서 통과한다는 뜻은 아니다.
4. **진행 속도:** 해당 날짜를 포함한 최근 14일, 즉 `[날짜−13일, 날짜]`의 선정 성과 개수 ÷ 2주다. 예를 들어 10/28은 10/15~28의 9건 ÷ 2 = 4.5건/주다. 데이터 시작 직후 13일은 전체 구간이 없어 공란으로 둔다. 하락은 과거 성과가 창 밖으로 빠지는 효과도 포함한다.
5. **비교 경계:** 각 성과의 난이도·공수는 같지 않다. 완료율, 생산성, 실제 노동 시간, 계획 대비 달성률, 예상 완료일로 환산하지 않는다. 월별 첫·마지막 구간도 길이가 달라 단순 월간 속도 비교에는 쓰지 않는다. 기록 없는 날·선정 성과 없는 날을 미작업으로 간주하지 않는다.
6. **증거 종류:** 실물·보드 관측에는 사용자 보고와 보존 로그·계측이 포함된다. 각 행의 `scope`에 적용 범위를 남겼다. CAD 초안·ERC·모의실험·학습 자료는 실물 검증과 별도 색이며 사용자 필기·이해 완료를 뜻하지 않는다. 사용자 필기 완료 보고는 36-19까지다.
7. **현재 상태:** 전체 MVP 인수는 미완료이며 T005A PARTIAL / T007 BLOCKED를 유지한다. PCB 자료는 39-3까지이며 ADC 설정·평균 처리·보정은 검증안이다. 수면 후 CAD 대조와 새 빌드·플래시·실물 시험은 수행하거나 집계하지 않았다.

## 근거와 재현

30개 입력 행의 `anchor`가 해당 진행 기록에 실제로 있는지 검사하고, 원본 문구·행 번호·파일 경로를 CSV에 보존했다. HTML의 근거 링크는 게시된 원본 커밋 `f99c583749337d27551820becf740027f13d54bd`에 고정했다. 원본 근거를 수정하지 않았다. 그래프를 다시 만들 때는 같은 원본 버전의 저장소를 사용한다.

Python과 `matplotlib`, `plotly`가 있는 환경에서 이 폴더의 `build_charts.py`를 실행한다. 최초 생성은 Python, matplotlib 3.11.2, plotly 7.1.0 및 Windows 맑은 고딕을 사용했다. 그래프 라이브러리는 저장소 밖 임시 폴더에 설치했다. 다른 OS에서는 Noto Sans CJK KR 또는 나눔고딕이 필요하다.

HTML에는 Plotly 실행 코드를 포함하여 그래프를 오프라인에서도 열 수 있다. 원본 GitHub 근거 링크를 여는 데에는 네트워크가 필요하다. 생성 시 원본 문구 30건, 날짜·범주·중복, 누적 합계 및 일별 합계를 검사했고 PNG를 시각 확인했다. 이번 그래프와 진행 기록의 후속 추가는 앞선 Git·Calendar·Notion 마감 게시에 포함되지 않는다.
