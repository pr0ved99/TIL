# v5.2 정지 상태 처리 시간 관측 run01

2026-10-24 · ACC-COM-01 A · **정지 상태 계측 정상 / 과거 지연 원인 OPEN**

## 해석과 한계

- v5.2의 실제 브라우저 계측이 이 정지 구간에서 정상 연결됐다. 6,324행 전체가 원본 handler와 짝지어졌으며 순번 1~6324·시각 순서·이력 대응이 일치한다.
- 이 구간의 동기 앱/진단 처리는 1ms 미만이었다. 그러나 과거 200~250ms 수준의 공백이 이번에는 재현되지 않았다. 이 결과만으로 과거 지연 원인을 특정하거나 브라우저 전체를 원인 후보에서 제외하지 않는다.
- 측정은 JS 동기 처리 구간이다. 메시지가 handler에 들어오기 전 이벤트 대기, 나중의 layout/paint, 다른 콜백, 내보내기 비용은 별도다. ESP와 브라우저 절대 시각을 빼서 편도 네트워크 지연을 만들지 않는다.
- 최종 focused=false지만 blur/stop 이벤트는 없다. 화면 전환 때문에 DISARM됐다는 사건을 이번 로그에 추가하지 않는다. 처음부터 끝까지 DISARMED였다.
- count는 이번 구간 안에서 고정됐다. 앞선 회차와 사이에 기록되지 않은 시간이 있으므로 이전 최종 count와 연결해 이동량이나 초기화 원인을 추정하지 않는다.
- 새 전압·전류·3.3V 파형, ACTIVE 명령/응답, 모터 부하 관측은 없다. 통신 원인 조사와 전체 MVP 인수는 미완료다.

## 다음 한 단계

**ACC-COM-01 A의 ARM 속도 0 관측**으로 새 관측기에서 주기 CMD와 명령 응답 처리가 추가됐을 때의 시간을 확인한다. 기존 속도 0 시험의 안전 기능을 새로 인수했다는 의미가 아니다.

현재 로그는 확보했으므로 실제 정지·DISARMED/IDLE에서 페이지를 새로고침하고 v5.2를 다시 설치해 별도 기록을 시작한다. 현재 6,324행을 그대로 이어 쓰면 후속 기록 중 8,192행 상한에 도달할 수 있다. 양쪽 궤도가 바닥에서 떨어져 안정적으로 지지된 상태에서 로봇 페이지에 포커스를 두고 ARM·속도 0으로 30초 관측한다. 방향/거리 버튼은 누르지 않는다. 이후 수동 DISARM→DISARMED/IDLE 확인 후 `copy(g6StopObserve.report())`로 내보낸다.

예상: ACTIVE 유지 중 PWM/CPS 0·count 고정, 종료 시 DISARMED/IDLE. 움직임·통신 경고·자동 DISARM이 나오면 관측을 중단하고 재ARM하지 않은 채 정지 상태에서 로그를 보존한다. 의도치 않은 움직임은 기존 물리 비상정지 절차를 사용한다. 사용자 결과를 받기 전 다음 주행 단계로 진행하지 않는다.
