## 기본 런처 P05 재현

사용자가 TMR 기본 YAML에 위치 허용치 0.15 m, 방향 허용치 0.12 rad, MPPI 목표 방향 비용 적용 거리 0.15 m를 저장했다. 설치된 설정은 소스의 심볼릭 링크였고 YAML 전체가 평가 설정과 일치했다. 평가에 사용한 방 B와 시드 4101을 다시 열고 도메인 63에서 `ros2 launch tmr_sim navigation.launch.py`로 시작했다. 목표를 보내기 전 컨트롤러에서도 세 값을 확인했다.

P05 목표 (1.50, 0.55, 0°)로 이동한 로봇 중심은 벽 중심선 x=1.10 m를 y=0.943 m에서 통과했다. 벽의 +Y 끝은 0.55 m다. 2.370 m를 이동해 31.076초(시뮬레이션 시간)에 성공했고, Gazebo 기준 최종 위치 오차는 5.90 cm, 방향 오차는 3.83°였다. 장애물 접촉과 복구는 모두 0회였고 도착 후 2.04초 연속 정지를 확인했다. 이 재현 1회는 정식 평가 20회와 별도로 기록했다. ## 평가 조건

동일한 TMR을 원점에서 출발시켜 직진, 좌회전, 우회전, 뒤쪽 목표 정렬, 안쪽 벽 우회 경로를 각각 네 번 주행했다. 시드는 Gazebo에 지정했다. AMCL과 MPPI의 내부 난수와 운영체제의 실행 순서까지 고정하지는 않았다. 한 방에서 네 번 반복한 결과이므로 여러 건물과 노면에서의 성능을 추정하는 표본으로 쓰기 어렵다.

목표와 후보 설정은 예비 주행에서 가져왔다. 평가에는 안쪽 벽을 옮기고 남서쪽에 기둥을 둔 새 방과 시드 4101~4104를 사용했다. 점유 지도와 Gazebo 벽은 같은 미터 단위 치수에서 생성했다. 첫 목표 전 지도, 월드, 로봇, 브리지, 설정과 판정 기준의 SHA-256을 저장했다. 각 회차마다 월드·지도 서버·AMCL·Nav2를 새로 시작하고 지도 크기, 정면 스캔 거리, 원점, TF, 물리 접촉 센서, 컨트롤러의 실제 파라미터를 확인한 뒤 목표 하나를 보냈다. 목표 전송 후의 재시험은 허용하지 않았다. [시험 계획](protocol.yaml) · [고정 입력 해시](frozen_inputs.sha256) · [실행 환경](environment.json) · [예비 주행과 접촉 검출 교정](../2026-11-23_tmr_nav03_baseline/p01_contacts/README.md)

- 컨트롤러 도착 허용치는 위치 0.15 m, 방향 0.12 rad이며 MPPI가 목표 방향 비용을 적용하는 거리는 0.15 m다. 진행 판정은 10초에 0.50 m, 속도 상한은 전진 0.10 m/s와 회전 0.39 rad/s다. 후보는 이번 평가 기동 파일에서 적용했다. [평가용 Nav2 설정](inputs/navigation.yaml)
- 정식 20회는 액션 성공 18회 이상, 장애물 접촉 0회, 모든 최종 위치 오차 0.20 m 및 방향 오차 10° 이내를 요구한다. 정지와 물리 접촉 관측 유효성도 확인한다. 45초는 실시간 기준 타임아웃이다. 그때까지 완료되지 않은 액션은 취소하고 원래 결과로 집계한다.
- 위치와 방향은 정지 관측이 끝날 때 Gazebo 월드에서 측정한다. CSV의 `map_*`은 같은 시점 RViz에서 보는 TF 추정값이다. `sim_s`와 `wall_s`는 목표 전송부터 액션 종료까지의 시간이고 `rtf`는 그 비율이다. `path_m`은 정지 관측까지 포함한 Gazebo 평면 궤적 길이다.
- 정지는 액션 종료 0.60초 후부터 2초 이상 관측한 오도메트리 속도 여섯 성분 및 최종 속도 명령으로 확인한다. 성분별 절댓값 허용치는 선속도 0.001 m/s, 각속도 0.001 rad/s다. 접촉은 차체·앞뒤 지지대·좌우 바퀴의 다섯 Gazebo 접촉 센서에서 읽고, 바닥과 장애물을 충돌체 이름으로 구분한다. 같은 장애물의 연속 접촉은 한 건으로 세며 바닥 접촉 시각의 최대 간격도 확인한다.
- 보조 시험은 P05, 별도 시드 4105에서 시행한다. 취소는 이동 중 요청부터, 스캔 단절은 마지막 ROS 스캔부터 0 명령과 정지까지의 시뮬레이션 시간을 잰다. 스캔 브리지만 끄므로 주행 브리지와 시계 및 오도메트리는 계속 관측할 수 있다. 단절 후 4초까지 액션이 진행 중이면 정리용 취소를 보내고 그 시각을 별도로 기록한다.

## 원본과 재현

[원본 압축 파일](runs.tar.gz)은 회차마다 목표 UUID에 연결되는 액션 결과, 목표 전송 조건, Gazebo 자세·오도메트리·속도 명령·스캔 시각 궤적, 충돌체 쌍과 물리 시각, 스택 로그를 담는다. 별도의 대표 bag은 평가 전 P05-4101로 지정했다. [대표 bag 내용 검증](bag_check.json) · [재집계 코드](runner/report.py)

프로젝트의 `05_ROS2_Integration`에서 빌드한 Jazzy 워크스페이스를 준비하고 이 README가 있는 디렉터리에서 아래처럼 실행한다. 기존 측정값을 다시 집계해 보려면 `run_series.py`와 `archive.py` 단계를 건너뛰고 `report.py`부터 실행할 수 있다. 전체 재주행의 결과를 보존하려면 이 평가 폴더와 형제인 예비 주행 폴더를 복사한 곳에서 작업한다. 평가 런처는 GUI 없이 새 Gazebo와 Nav2를 시작하고 회차마다 독립된 ROS 도메인(40~61)과 Gazebo 파티션을 사용한다.

```bash
source /opt/ros/jazzy/setup.bash
source "$HOME/workspace/github-repos/TIL/Projects/Tracked_Mobile_Robot/05_ROS2_Integration/install/local_setup.bash"
sha256sum -c frozen_inputs.sha256
scratch=$(mktemp -d)
python3 runner/run_series.py "$scratch"
python3 runner/archive.py "$scratch"
python3 runner/report.py
python3 runner/check_bag.py
python3 runner/plot.py
```
