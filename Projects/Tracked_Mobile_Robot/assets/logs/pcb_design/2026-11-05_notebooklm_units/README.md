1. 왜 이 설계를 하는지와 이번 단원의 결론이 있는가?
2. 초보자가 놓치기 쉬운 용어·기호·단위·회로 경로를 설명하는가?
3. 데이터시트 조건, 가정, 시뮬레이션, 실측이 구분되는가?
4. 과거 후보를 현재 확정안으로 쓰거나 미완료 검증을 완료했다고 말하지 않는가?
5. 다른 단원과 중복되는 설명 때문에 이번 핵심 계산·관측이 빠지지 않았는가?

수정이 필요할 때는 아래 문구에 실제 오류를 붙여 한 번에 전달한다.

```text
이 메모는 직접 설계하는 학습자의 복습 자료다. 홍보성 결론을 줄이고,
이번 단원의 설계 질문·용어·회로 경로·계산 또는 관측·판단을 연결해 수정하라.
각 수치의 근거와 조건을 유지하고, 가정·시뮬레이션·실측·미검증을 구분하라.
다음 항목을 특히 수정하라:
[여기에 실제 메모의 잘못된 문장과 원하는 수정 방향을 적는다.]
```

생성 후에도 그림의 연결/라벨, 그래프 축/단위, 수치와 완료 상태를 원문과 대조한다. 메모 검토를 통과했다고 영상의 정확성까지 자동 보장되지는 않는다. 실제 영상은 현재 미생성 상태다.

파일명은 `TMR_PCB_01_시스템구조_v01.mp4`처럼 단원 번호·주제·버전을 붙인다. 후속 영상도02~14 번호를 유지하고, 같은 영상의 수정본만v02로 올린다. 사용자가 생성물을 제공하면 실제 경로·검토 결과를 기록한다.

### 업로드 파일과 사용량 안내의 근거

Google 공식 안내는 TXT·PDF·이미지·CSV 입력을 지원하며, 무료 노트북의 소스 한도는50개로 안내한다. 이번39개 묶음은 기존 원문을 보존하면서 한 노트북에 넣기 위한 구성이다. 계정의 영상 생성 횟수 한도와 소스 한도는 별개이므로 한도 안내가 뜨면 이미 만든 결과를 보존하고 다음 생성 가능 시점에 이어간다. [공식 소스 안내](https://support.google.com/notebooklm/answer/16215270?hl=ko)

실제 복제·단원별 선택 목록·원본 및 사본 해시는 [전체 업로드 영수증](single_notebook_receipt.json), 생성 방식은 [재현 스크립트](build_single_notebook_packet.py)에 기록한다. 원문 TXT는 단원별로 합치고25개 근거 사본은 바이트 일치를 확인한다. 원래170파일 묶음의 설명을 새 묶음의 파일 수로 바꿔 쓰지 않는다.
