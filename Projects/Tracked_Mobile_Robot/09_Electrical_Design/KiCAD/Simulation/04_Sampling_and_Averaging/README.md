### A-3 관찰 화면 — 첫 블록의 구성

1. **변화 직후 샘플로 이동**을 눌러 110번째(55.0ms, 약12.6V)와 111번째(55.5ms, 약12.302229V)를 비교한다. 표의 입력 환산값은 `K × VADC`이며 실제 VRAIL과 구분한다.

## 8. B — 안정된 기준값에서 가상 잡음과 일정한 오차 비교

### 목적과 방법

**평균은 이 모델의 흔들림을 줄이지만 일정하게 더해진 오차는 제거하지 않는다.** 이를 분리해 보는 [가상 표본 비교 화면](04_02_noise_model/review.html)을 보조 자료로 준비했다. A의 사용자 CSV를 잡음 실측 자료로 재사용하거나 가상 데이터를 KiCad 결과로 표시하지 않는다. 기존 회로의 물리적 잡음 발생 모델을 추가한 것도 아니다.

사용자는 HTML을 쓰는 이유와 KiCad에서 파형을 보기 번거로운지 질문했다. KiCad도 TRAN 파형/커서 및 `VTRNOISE`/`VTRRANDOM` 같은 가상 신호원을 지원한다. HTML을 선택한 이유는 균일 표본 수집과200개 블록 평균의 비교/표시를 쉽게 구성하기 위해서다. KiCad 파형 관찰의 대체가 필요해서가 아니다. 권고 흐름은 KiCad에서 모델/파형 확인 → CSV의 균일 재표본/평균 후처리 → 보조 화면 비교이며, B의 회로 구성·시뮬레이션은 아직 수행하지 않았다. [KiCad9 공식 문서 — Simulation_SPICE library](https://docs.kicad.org/9.0/en/eeschema/eeschema.html#simulation_spice_library), [결과 내보내기](https://docs.kicad.org/9.0/en/eeschema/eeschema.html#exporting_simulation_results).

기준 입력12V, 정상 `VADC = 12/K = 1.778514434562V`, `K=6.747204164780444`다. 관측 표본을 다음과 같이 가정한다.

`x[n] = 12/K + b + e[n]`

- `x[n]`: ADC 쪽 전압 단위로 표현한 가상 관측 표본.
- `b`: 모든 표본에 동일하게 더하는 오차, 0 또는+5mV.
- `e[n]`: 평균0·표준편차3mV인 독립 정규분포를 가정해 생성한 가상 잡음 표본. 유한 기록의 평균은 정확히0이 아닐 수 있다.
- 수집률2kHz, 200개 비중첩 평균, 결과10Hz. 10초의20,000표본을100블록으로 처리한다. 시드37402로 같은 잡음을 재현한다.

3mV·5mV는 효과를 구분하기 위한 학습 값이며 부품 사양이나 잡음 예산이 아니다. 외부 RC 뒤 관측값에 오차를 더하는 추상 모델이다. 실제 잡음의 대역·상관성·ADC취득·양자화는 포함하지 않는다.

### 직접 관찰할 순서

1. 기본값인 **잡음 켬 / +5mV 끔**에서 원시 표본과 블록 평균의 흔들림을 비교한다.
2. 잡음을 유지하고 **+5mV를 켠다**. 전체 평균은+5mV 이동하지만 두 표준편차는 그대로인지 확인한다.
3. +5mV를 유지하고 **잡음을 끈다**. 흔들림이0이어도 기준보다+5mV 높게 남는지 확인한다.

화면의 표준편차는 각 자료의 자기 평균에서 퍼진 정도이며 분모는 해당 자료 개수다. 세로축과 통계의 mV는 ADC 쪽, 입력 환산 차이는 별도 표시다. 그래프는 처음500ms, 통계는 전체10초다.

| 가상 조건 | 전체 평균의 기준 대비 차이(ADC mV) | 원시 표준편차(mV) | 블록 평균들의 표준편차(mV) |
| --- | ---: | ---: | ---: |
| 잡음만 | -0.003004 | 3.008050 | 0.193135 |
| 같은 잡음 +5mV | 4.996996 | 3.008050 | 0.193135 |
| 잡음 없이 +5mV | 5.000000 | 0 | 0 |

표는 가상 데이터의 계산 결과다. 사용자가 관찰한 결과로 기록하지 않는다. 이론상의 `3/sqrt(200) ≈ 0.212132mV`는 가정한 독립 표본 모델에서 블록 평균의 모집단 표준편차이며, 100개 블록으로 계산한 위 값과 정확히 같아야 하는 목표가 아니다. 실제 회로에 이 감소율을 그대로 적용하지 않는다.

### 필기할 식과 판단

`블록 평균 = 12/K + b + (e[1]+…+e[200])/200`

일정한 오차는200번 더한 뒤200으로 나누므로 그대로 남는다. +5mV의 입력 환산 차이는 `K×0.005 = 0.033736020824V`, 잡음 없이 표시되는 값은 약12.033736V다. 따라서 평균 후 표준편차만 보고 정확도 통과로 판단하지 않고 기준 대비 평균 차이도 함께 본다.

[생성 코드](build_noise_bias_demo.py) · [가상 데이터/조건](04_02_noise_model/data.json) · [수치/브라우저 검증](04_02_noise_model/verification.json). 브라우저의 체크박스4조합과 평균값·표준편차·그래프 생성을 확인했다. 사용자 B 관찰·필기·이해 완료는 아직 보고되지 않았으며 다음 C는 그 뒤의 주기성 성분/alias 비교다.

## 9. B의 KiCad 실습 — B-1 고정 입력 구성

2026-11-14. 사용자가 직접 저장/구성/실행하고 Codex가 저장본과 CSV를 확인하는 흐름으로 진행한다. 이번 안내는 **A의 복사본에서 입력 전압과 VDDA를 고정하는 단계**까지다.

### 목적과 관측 구성

12V 기준의 정상 VADC에 가상 관측 오차를 더해 평균의 효과를 비교한다. 후속 구성에서는 한 잡음원을 공유하는 두 관측용 노드를 만들 예정이다.

| 관측값 | 뜻 |
| --- | --- |
| VADC | 기존 분압/RC 회로의 정상 출력 |
| VRAW | VADC + 가상 잡음 |
| VRAW_BIAS | 같은 VRAW + 5mV |

같은 잡음을 사용하면 두 관측값의 차이가 언제나5mV이므로, 잡음이 매 실행마다 달라지는 효과와 일정한 오차를 혼동하지 않는다. 추가 관측용 신호원은 측정 오차를 가정하는 수학 모델이며 제작 PCB의 부품 추가나 실제 소자 잡음 재현이 아니다. RC 자체의 잡음 감쇠를 새로 측정하는 실습과도 구분한다. 평균은 저장 CSV를2kHz/200개/100ms로 후처리할 계획이다.

### B-1 사용자 작업

1. [실습 A 회로](04_01_Voltage_BlockAverage_Step.kicad_sch)를 연다.
2. **파일 → 다른 이름으로 저장**으로 같은 폴더에 `04_02_Voltage_Noise_Average.kicad_sch`를 만든다. 아직 생성 확인 전인 예정 파일명이다.
3. V1 심벌의 시뮬레이션 모델에서 기존 PWL 값을 아래로 교체한다. 표시 Value만 바꾸지 않는다.

```text
0 12 10 12
```

시각0초에12V, 시각10초에도12V이므로 전 구간 일정하다. 이전55.25ms의 하강을 제거한다. 이 줄의 `10`은10초다.

4. V3 심벌의 기존 PWL 값도 같은 구간을 명시하도록 바꾼다.

```text
0 3.3 10 3.3
```

VDDA를3.3V로 유지해 기존 B1/S1 제어가 ON인 정상 측정 상태를 만든다. R1~R5/C1/C2/S1/B1 및 배선은 유지한다. 입력 변경 뒤 새 파일을 저장한다.

5. 저장본의 두 PWL과 기존 연결을 확인한 뒤 가상 잡음원/관측 노드 구성을 안내한다. 아직 TRAN 실행이나 새 워크북/CSV 저장 단계가 아니다.

### 첫 확인 기준과 후속

고정 입력에서 정상값의 명목 예상은 `VADC = 12/6.747204164780444 = 1.778514434562V`다. 사용자 관측값이 아니라 다음 기준선 확인에 쓸 계산값이다. 두 PWL/기존 배선 유지 확인 → 잡음과 일정한 오차 관측 노드 구성 → 모델/연결 확인 → 새 TRAN/CSV → 평균 비교 순서다.

설치된 KiCad10.0의 `Simulation_SPICE:VTRRANDOM` 존재를 확인했다. 기본 모델은 `RANDUNIFORM`이므로 후속 Gaussian 모델을 안내할 때 분포/표준편차 항목을 다시 대조해야 한다. 현재는 잡음원 값을 설정하거나 시뮬레이션한 상태가 아니다. 준비된 HTML의 시드/계산 수치를 새 KiCad 실행 결과로 복사하지 않는다.

## 10. B-2 — 가상 잡음원 하나 구성

### B-1 저장본 확인

[04_02 사용자 회로](04_02_Voltage_Noise_Average.kicad_sch)를 읽었다. A와 비교해 참조 집합이 같고30개 배선·5개 접합점·6개 라벨·내장 라이브러리가 동일하다. 부품 속성은 V1/V3의 PWL 두 개만 변경됐다. 실제 입력은 V1=`0 12 10 12`, V3=`0 3.3 10 3.3`이다. V1의 표시 Value=16은 남아 있으나 시뮬레이션 입력은 PWL의12V다. 원본 A/CSV는 유지됐다. B 저장본 SHA-256: `fbbd7b55e185825cf450d5632794c6a5de337a0f5a7f1dd4abb84cef68e99ae0`.

### 사용자 구성

1. 기존 회로 아래에 관측 모델을 위한 새 줄을 잡는다. 왼쪽에 `A` → `Simulation_SPICE:VTRRANDOM`을 추가하고 참조를 `V4`로 맞춘다. 오른쪽은 후속 VRAW/VRAW_BIAS용으로 둔다.
2. V4 속성 → 시뮬레이션 모델에서 전압원 **Random Gaussian**(RANDGAUSSIAN)을 선택한다. 기본 Random uniform은 이번 분포와 다르다.
3. 다음 모델 항목을 설정한다. 값은 모두 학습 가정이다.

| 항목 | 입력값 | 의미 |
| --- | --- | --- |
| ts | 500u | 새로운 난수 값의 유지 시간0.5ms |
| td | 250u | 난수 변동 시작 지연0.25ms |
| stddev | 3m | 표준편차3mV |
| mean | 0 | 가정한 분포의 평균0V |

0.25/0.75/1.25ms…에서 잡음 값이 바뀌게 하고 후속 ADC 상당 표본은0.5/1.0/1.5ms…에서 읽는다. 표본이 불연속 경계에 놓이지 않도록 정한 위상이다. ts는 잡음원 갱신 조건이며2kHz 정현파 주파수 설정이 아니다. 평균0은 유한 CSV의 평균을 정확히0으로 강제한다는 뜻이 아니고, 표준편차3mV는 최대치±3mV가 아니다.

4. V4의 `+`에서 짧은 선을 빼 로컬 라벨 `VNOISE`를 붙이고, `−`는 기존과 같은 SPICE 기준 노드 `0`에 연결한다. 기존 Simulation_SPICE:0 심벌을 복사해 사용할 수 있다. V4를 VADC와 직접 연결하지 않는다. 다음 단계의 관측용 식에서 `V(VADC)+V(VNOISE)`를 만들 예정이다.
5. 저장 후 실제 모델/핀/라벨을 확인한다. 이번 단계에는 +5mV를 V4의 mean에 넣지 않는다. 같은 잡음을 공유하는 별도 관측 노드에 더해야 두 조건을 정확히 비교할 수 있다.

### 근거와 다음 작업

KiCad10.0 공식 소스의 [모델 유형](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sim/sim_model.cpp)에서 RANDGAUSSIAN/Random Gaussian을, [전압원 파라미터](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sim/sim_model_source.cpp)에서 ts/td/stddev/mean 및 TRRANDOM의 TYPE=2 매핑을 확인했다. ngspice User's Manual **Version47+, 2026-09-28, 인쇄/PDF101~102쪽 §4.1.8 Random voltage source, TYPE=2 Gaussian 행**에서 각 항목의 의미를 대조했다. [공식 매뉴얼](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf#page=101). 매뉴얼 판본은 설치 엔진 판본을 뜻하지 않는다.

저장본에서 예상 모델은 `Sim.Device=V`, `Sim.Type=RANDGAUSSIAN`, `ts=500u td=250u stddev=3m mean=0`이다. 실제 저장 문자열의 단위 표기는 동등한 수치로 달라질 수 있다. 확인 뒤 B2/B3 관측원으로 VRAW와 VRAW_BIAS를 구성하고, 그다음 사용자 TRAN/CSV를 진행한다. 잡음원 추가·사용자 파형 관찰은 아직 확인 전이다.

## 11. B-3 — 같은 잡음을 공유하는 관측값 두 개

### B-2 저장본 확인

V4의 실제 저장 설정은 `Sim.Device=V`, `Sim.Type=RANDGAUSSIAN`, `ts=500u td=250u stddev=3m mean=0`으로 안내와 같다. +핀1 위치(143.51,58.42)에서 VNOISE 라벨(143.51,54.61)로, -핀2 위치(143.51,68.58)에서 Simulation_SPICE:0(143.51,72.39)으로 선이 연결돼 있다. 기존 A의 배선/접합점/라벨을 모두 유지했고 새 배선2개·라벨1개·V4/0심벌이 추가됐다. 기존 부품 속성은 앞서 변경한 V1/V3 PWL 외에 동일하다. 저장본 SHA-256: `160d44d0b30977b89bdce007424178d801a49398ab52bbfd4e654faa7b010fe8`.

이는 모델/연결 확인이며 TRAN 실행이나 잡음 관측 결과가 아니다.

### 목적과 모델

`VRAW = VADC + VNOISE`

`VRAW_BIAS = VRAW + 0.005V`

두 번째 값이 첫 번째 값을 그대로 참조하므로 잡음이 완전히 공유된다. B2/B3는 기존 B1과 같은 수식 전압원(BSOURCE)으로 만들며, 실제 제작 부품이 아닌 관측용 모델이다. 기존 VADC 노드를 수식으로 읽으므로 전기적 부하를 추가하지 않는다.

### 사용자 작업

1. 기존 `B1` **심벌만** Ctrl+D로 두 개 복제해 참조를 `B2`, `B3`로 맞춘다. 기존 B1과 그 배선은 그대로 둔다. V4 오른쪽에 B2/B3를 나란히 놓고 출력 라벨과 아래0심벌 높이를 맞춘다.
2. B2 속성 → 시뮬레이션 모델에서 복사된 기존 `v=...` 수식 전체를 아래로 교체한다. 기존 SPICE/B 모델 형식은 유지한다.

```text
v=V(/VADC)+V(/VNOISE)
```

3. B3의 같은 수식 입력칸은 아래로 교체한다.

```text
v=V(/VRAW)+0.005
```

`v=`는 출력 전압을 이 식으로 정한다는 뜻이다. `V(/VADC)` 등은 현재 회로의 노드 전압 참조다. `0.005`의 전압 단위는V이므로5mV다.

4. B2의 +핀에서 짧은 선을 빼 로컬 라벨 `VRAW`, B3의 +핀에는 `VRAW_BIAS`를 붙인다. 두 -핀은 각각 기존과 같은 SPICE 기준 `0`에 연결한다. B2/B3 출력선을 VADC/VNOISE 또는 서로의 출력선과 직접 묶지 않는다. 수식 안에서 해당 전압을 읽는다.
5. 새 회로를 저장한다. 두 식과 출력 라벨/접지, 원래 B1/V4 모델을 읽기 확인한 뒤 TRAN으로 진행한다. 이번 단계에서는 시뮬레이션 실행까지 완료했다고 기록하지 않는다.

### 예상 관계와 근거

예를 들어 VADC=1.778514V, 특정 순간 VNOISE=+0.002V라면 VRAW=1.780514V, VRAW_BIAS=1.785514V다. 예시이며 아직 관측값이 아니다. 모든 시점에서 `VRAW_BIAS−VRAW=0.005V`가 되어야 한다. 같은 시각의 표본을 동일한 블록으로 평균하면 평균 차이도5mV다.

표현식 전압원 문법 근거: **ngspice User's Manual Version47+, 2026-09-28, 인쇄/PDF107쪽 §5.1.1 Syntax and usage의 일반형과 B-source 예제**. [공식 매뉴얼](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf#page=107). 현재 저장된 B1도 같은 `v=...` 방식으로 VDDA를 참조한다.

## 12. B-4 — 사용자 TRAN 실행과 CSV 저장

### B-3 확인 결과

사용자가 저장한 B2/B3는 올바른 수식·출력 라벨·0 연결을 갖는다. V4는 위치가 바뀌었으나 VNOISE/0 연결과 Gaussian 설정이 유지됐고, 기존 B1/분압회로도 유지됐다. B2/B3의 저장 Sim.Params가 따옴표 없는 형태지만 KiCad의 SPICE 내보내기에서 정상 해석을 확인했다.

```text
B2 /VRAW 0 v=V(/VADC)+V(/VNOISE)
B3 /VRAW_BIAS 0 v=V(/VRAW)+0.005
V4 /VNOISE 0 TRRANDOM( 2 500u 250u 3m 0 )
```

[내보낸 netlist](../../../../assets/logs/pcb_design/2026-11-14_sampling_average_practice/04_02_b3_check.cir) · [저장본 검토 근거](../../../../assets/logs/pcb_design/2026-11-14_sampling_average_practice/b3_saved_check.json). 저장본 SHA-256: `a65a930acf5ffc6b2ef7335889bf5a823841facded80a07ee8fadc1fc3844ed6`. 내보내기/정적 연결 검토이며 시뮬레이션은 실행하지 않았다. 원본 A와 CSV 해시는 유지됐다.

### 이번 실행 설정

04_02의 시뮬레이터에서 새 TRAN 탭을 만들고 다음을 입력한다. A의 기존 워크북을 덮어쓰지 않는다.

| 항목 | 입력 |
| --- | --- |
| 시간 단계 | 50u |
| 최종 시간 | 10 |
| 초기 시간 | 0 |
| 최대 시간 단계 | 50u |
| 초기 조건 사용(UIC) | 해제 |

동등 명령은 `.tran 50u 10 0 50u`다. 최종시간10은10초이며10ms가 아니다. 정상 동작점에서 시작한다. 이번에는 입력12V/기존RC 정상상태를 유지하고 별도 관측원에0.5ms마다 가상 오차를 더하므로 수치 최대간격은50µs로 잡았다. A의 C1/C2 과도 응답 실습과 설정 목적이 다르다. 후속 표본0.5ms는 잡음 갱신0.25ms와 엇갈리며, 실제 CSV 시간 간격과 모델 항등식을 확인한 뒤 처리한다. 이 TRAN 간격을 실제 ADC 수집주기라고 해석하지 않는다.

### 표시와 예상 관계

실행 뒤 우선 `V(/VADC)`, `V(/VRAW)`, `V(/VRAW_BIAS)` 세 신호를 표시한다. 입력12V나0V 부근의 잡음 단독 신호를 같은 축에 함께 넣으면 작은 차이가 보기 어려우므로 이번 비교에서는 이 세 신호만 선택한다. 필요하면 처음10ms 정도를 확대한다.

- VADC: 명목1.778514V 부근의 일정한 기준선.
- VRAW: 그 기준 주위로 불규칙하게 변한다.
- VRAW_BIAS: VRAW와 같은 모양으로5mV 높다. 이는 모델이 정한 차이다.

표준편차3mV는 진폭 상한이 아니며 파형에±3mV를 넘는 값이 나타나도 그 사실만으로 실패로 판정하지 않는다. 전체 평균이 정확히 명목값이나 명목값+5mV가 될 필요도 없다. 같은 시각에서 두 파형의 차이가5mV라는 관계와 모델/기준선이 확인 기준이다. 수치/CSV 출력 반올림에 따른 작은 차이는 후처리에서 구분한다.

## 14. 11/14 마감 — 왜 잡음을 만들었는가

### 14-1. 목적과 가정

입력12V의 명목 VADC는1.778514434562V다. 이 값을 정답으로 두고, 측정값이 흔들릴 때 디지털 평균이 어떤 변화를 만드는지 관찰한다. 가상 Gaussian 잡음의 표준편차3mV와 일정한 오차5mV는 학습용 설정이며 실제 보드에서 측정한 값이 아니다.

모델은 `VRAW=VADC+VNOISE`, `VRAW_BIAS=VRAW+0.005`다. 잡음이 분압/RC를 통과한 과정이 아니라 VADC 뒤에서 더한 관측값을 사용한다. B3가 B2+5mV이므로 평균 후5mV 유지도 모델의 선형 관계를 관찰한 것이다.

### 14-2. 설명용 계산과 실제 결과

설명용으로1.77551V와1.78151V의 평균은1.77851V다. 양쪽에 각각5mV를 더한1.78051V와1.78651V의 평균은1.78351V다. 흔들림은 상쇄됐지만 일정한5mV는 남는다. 이 두 표본은 설명을 위해 대칭으로 만든 값이며 실제 CSV 관측값으로 기록하지 않는다. 유한한 무작위 표본에서는 상쇄가 정확하지 않아 평균값도 흔들린다.

사용자 CSV에서2kHz/200개 평균의 표준편차는2.995477mV→0.221188mV, 평균 차이는5mV였다. 전체 평균은 VRAW1.778548425V/VRAW_BIAS1.783548425V다. 지정한 모델의 결과이며 실제 보드의13.54배 개선이나 해당 수집 조건의 최종 적합성을 보장하지 않는다.

### 14-3. 판단과 종료 기준

평균은 이 모델의 무작위 변동을 줄이고 일정한 오차는 남긴다. 평균 처리와 보정의 역할을 나누는 것이 B의 학습 결론이다. 실제 RC 감쇠·ADC 잡음 예산·보정 성능은 이번 실습으로 판단하지 않는다. 데이터 수집/계산은 충분하며 같은 결론을 위해 B를 반복하거나 새 HTML/FFT 실습을 자동 추가하지 않는다.

사용자는 목적이 불분명하다고 밝혔고 위 설명 뒤 마감을 요청했다. 따라서 다음은 이 목적과 실제 결과를 짧게 연결해 확인하는 것부터다. 사용자 이해·수기 완료는 미보고다. 이후 기존 C →03_15 감지선 단락 →하네스/보호 정격 검토 순서를 유지한다. 모든 실습에서 질문·관측값·설계 판단·종료 기준을 먼저 밝힌다.
