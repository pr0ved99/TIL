# 실제 엔코더와 전력단 검사 마감 기록

검사 세션: 2026-09-26~27. 문서 마감: 2026-09-27.
근거는 사용자 측정·통과 보고와 보존한 ESP monitor다. 모든 측정의 개별 시각·사진이 있는 것은 아니다.
**실제 전동 구동은 아직 하지 않았다. T004의 기존 PASS, 전체 T005A의 PARTIAL을 유지한다.**

## 1. 이번에 확인한 범위

| 항목 | 결과와 근거 | 포함하지 않는 범위 |
| --- | --- | --- |
| 실제 엔코더 입력 | 네 A/B 입력 LOW 0V, HIGH 약 2.86V 사용자 보고 PASS | 전동 구동 중 파형·노이즈 |
| 손회전 | 양쪽 정지 10초 이상 CPS0, 양방향 변화·채널 독립성·정지 복귀 사용자 보고 PASS | 실제 RPM 정확도·전동 구동 방향 |
| STM 단독 warm reset | TEL 169개/16.8초, 300/400ms 포함 CPS0 | cold boot, 최초 0~200ms |
| 차량 좌우 정정 | A=왼쪽/M1/JENC_1/TIM3, B=오른쪽/M2/JENC_2/TIM5; 교환 후 손회전 PASS | M2 동력선 연결·구동 |
| S1 전환 시 CPS | OFF 때 양쪽 −10, ON 때 +10이 잠깐 보이고 바로 0으로 복귀했다는 사용자 보고 | 원인 파형 규명·필터 검증 |
| 전력단 | 아래 S0/S2 전압 관측과 무명령 정지 사용자 보고 | rail-off 전체 수용·실모터 정지 |
| M1 수동 시험 코드 | 안내 문서 작성, 사용자 입력 도중 중단 | 빌드·플래시·HELP·구동 검증 |

## 2. 배선과 엔코더 확인

- 두 모터 모두 섀시에서 분리한 상태로 검사했다. 과거 손회전도 분리 상태였으며 이번 검사도 같다.
- 영구 입력 조정부는 A/B 각각 1kΩ 직렬 + MCU 측 15kΩ GND 풀다운이다.
  [report 28](28_Encoder_Conditioning_Assembly_and_Electrical_Check_Report_2026-09-23_ko.md)의 저항 8곳·전원 6검사·양쪽 +5.05V 완료를 반복하지 않았다.
- STM32를 분리하고 실제 엔코더를 공급한 조건으로 안내한 검사에서 LOW 0V/HIGH 약 2.86V를 보고했다.
  돌리는 중 약 1.4V는 DMM 평균 관측이다. 정지시킨 상의 HIGH 전압과 구분한다.
- 보드 복원 후 두 모터 각각 정지 10초 이상 CPS0, 양방향 변화·정지 복귀·독립성 검사에 사용자 통과 보고가 있었다.
- 최종 좌우와 교환 후 전진 부호 검사는 [report 29](29_Vehicle_Side_Mapping_Correction_and_Hand_Rotation_Check_2026-09-26_ko.md)가 정본이다.
  A Motor+→M1A, Motor−→M1B 연결 확인. B 동력선은 분리·절연 유지, M2 연결은 계획이다.
- JENC_1/2 Pin1~4는 GND/B raw/A raw/AUX_5V다. A는 JENC_1, B는 JENC_2에 연결했다.
  모터의 6핀에는 동력선도 포함되지만 JENC의 4핀에는 엔코더 신호·전원만 연결한다.
- 모터 PCB 자석/실크 면을 정면으로 보고 6핀 커넥터가 위에 있을 때 왼쪽부터
  Motor+, Encoder GND, B, A, Encoder 5V, Motor−다. 임의의 사진 위/아래 방향으로 치환하지 않는다.
- 보정 상수는 **1560 counts/output-shaft rev**를 유지한다. 1650이 아니다.
  기존 50회전 A=77998/78001, B=78000/78000 기록을 소급 변경하거나 다시 보정하지 않았다.

## 3. warm reset 원본 로그

[원본과 분석 요약](../../assets/logs/encoder/2026-09-26_actual_encoder_warm_reset/README.md)을 저장했다.
원본 첨부 ID는 `2118519a-3775-4bec-842a-6d3da93f9cb1`이며 저장본과 첨부의 SHA-256을 대조했다.

사용자 보고 조건: 엔코더 전원 유지, 양쪽 정지, S0 잠금, ESP 모니터를 유지한 채 STM32만 RESET.

| 항목 | 원본에서 확인한 값 |
| --- | --- |
| TEL 수 / STM 시간 | 169개 / t_ms=200~17000, 16.8초 |
| 연속성 | 모든 STM 시간 간격 100ms; ESP tel_count=4139~4307, 증가폭 1 |
| left/right CPS | 모두 0, t_ms=300/400도 0 |
| left/right PWM 보고값 | 모두 0 |
| state / reason | 전 구간 FAULT / ESTOP_ACTIVE |
| command_age_ms / last_seq | 4294967295 / 0 |
| vx / w / STM err | 모두 0 |

`command_age_ms=4294967295`는 유효한 CMD를 아직 수락하지 않은 sentinel이다.
로그 시작에는 ESP 시각 413406~413416ms에 제어문자 `0x0e/00/15/19/14` 거부 5회,
413426ms에 embedded CR 거부 1회가 있고 첫 정상 TEL은 ESP 415446ms에 나타난다.
이후 정상 프레임 처리가 이어졌지만 바이트 오류 원인은 미확정이다.
STM err=0과 ESP parser 경고는 별개이며, 원본 경고를 삭제하거나 무오류 통신 PASS로 바꾸지 않는다.

9/23 monitor에는 부팅 후 4.2초부터만 있었고, 이번 로그는 warm reset 후 200ms부터를 추가 확인한다.
완전 전원 재인가의 최초 0~200ms 또는 구동 중 노이즈 검증 완료로 확대하지 않는다.

## 4. 전력단과 S0/S2 관측

현재 +/− 분배는 커버형 버스바 두 개다. MDD B+=K1 87, B−=GND 버스바 16 AWG,
K1 주선=14 AWG다. 사용자는 이 선재로 진행하기로 결정했으며 같은 결정을 반복해서 묻지 않는다.
이 사용자 결정 자체가 단자의 제조사 선재 범위 적합성 또는 부하·발열 시험 증거를 대신하지는 않는다.

사용자는 퓨즈 제조사를 Littelfuse, 정격을 1A와 10A로 확인했다(F2=1A, F1=10A).
과거 정확한 시리즈 식별·rail-off 수용 기준 등의 이력은 [report 27](27_T_ESTOP_005A_Motor_Disconnected_Rail_and_Safe_Restore_Report_2026-09-23_ko.md)에 보존한다.

아래 값은 MDD10A B+−B− 사이 DC 전압을 확인하도록 안내한 순서의 사용자 보고다.
전동 구동 명령은 보내지 않았고, 초기 rail 관측 때 모터 동력선은 분리돼 있었다.

| 조건·조작 | 사용자 보고 | 해석 |
| --- | --- | --- |
| 전원 분리 후 잔류 | 0.12V, 천천히 감소 | 잔류 전압 관측 |
| 무전원 상태의 임시 1kΩ 방전 후 | 0V | 해당 시점의 DMM 관측; 저항은 다음 전원 인가 전에 제거 |
| S0 잠금/S2 미조작, S1 ON | 0.24V → 0.23V | 두 값의 개별 측정 경과시간은 제공되지 않음 |
| S0 해제 후, S2 누르기 전 → 누른 후 | 0.23V → 11.78V | S0 해제만으로 rail이 올라가지 않고 S2 조작 후 상승한 하위 기능 확인 |
| S0 다시 누름·잠금 후 | 5초 1.28V, 30초 0.59V | 전압 감소 관측; 임의의 rail-off PASS로 처리하지 않음 |

대화 중 전원 인가 상태에서 임시 1kΩ을 다시 붙이자는 안내는 사용자 지적 뒤 철회했다.
그 재연결을 실행한 기록으로 남기지 않는다. 임시 저항의 1/4W 정격도 외관·저항값만으로 확정하지 않았다.
과거 9/22의 12.09V, 5초 1.58V/30초 0.55V와 이번 값을 섞지 않는다.

이후 A를 M1에 연결하고 S0 잠금 부팅 및 S0 해제/S2 수동 복구 후 무명령 상태를 확인하는
단계에 사용자는 `다음`으로 진행을 확인했다. 모터 정지·PWM0·CPS0의 사용자 보고 범위로 기록한다.
그 단계의 rail 전압은 별도 숫자가 없으므로 예상 배터리 전압을 측정값으로 채우지 않는다.

## 5. 배터리 관측 이력

3S LiPo와 iMAX B6를 사용했다. 아래는 검사 중 보고한 셀 값이며 종료 순간의 배터리 전압은 아니다.

| 순서 | 셀1 / 셀2 / 셀3 (V) | 합계 / 최대 차이 | 측정·조작 맥락 |
| --- | --- | --- | --- |
| 충전 전 | 3.84 / 3.98 / 3.95 | 11.77 / 0.14V | 총전압 약 11.8V 보고 뒤 셀 확인 |
| 이후 알람 표시 | 4.11 / 4.22 / 4.22 | 12.55 / 0.11V | 사용자 LiPo 알람 표시임을 확인 |
| 후속 확인 | 4.13 / 4.20 / 4.22 | 12.55 / 0.09V | DMM 교차 확인 안내 뒤 보고; 계측 정확도 검증은 없음 |
| 마지막 보고 | 4.12 / 4.16 / 4.16 | 12.44 / 0.04V | 사용자가 값을 맞췄다고 보고하고 원래 검사 재개 요청 |

추가 BALANCE 충전을 이어가기보다 B6 STORAGE 0.2A/3S로 전압을 낮추는 절차를 안내했다.
마지막 보고는 셀 전압에 대한 것이며 충전기 설정·전류·종료 로그 전체를 검증했다는 뜻은 아니다.
알람의 4.22V 표시만으로 실제 과충전이나 계측 오차 중 하나를 확정하지 않았다.

## 6. S1 전환 순간의 CPS

사용자는 S1 OFF에서 양쪽 CPS −10, ON에서 +10이 잠깐 나타났으며 **바로 0으로 돌아온다**고 확인했다.
지속적인 정지 CPS 이상으로 다시 취급하지 않고 다음 단계로 진행했다.
100ms 계산 구간에서 1 count 변화는 10 CPS에 해당하지만, 이번 값이 발생한 전기적 원인을
파형으로 확정한 것은 아니다. 이번 관측 때문에 pull-down·필터·CPS 계산을 수정하지 않았다.

## 7. 중단 지점과 남은 검증

- [M1 코드 안내](../plans/2026-09-27_M1_One_Shot_Console_Code_Guide_ko.md)에 수동 명령 4개,
  M1 5%/M2 0%, CMD 한 번/STM timeout 300ms, 완료·실패 뒤 재시도 잠금을 설계했다.
- 실제 ESP 파일은 사용자 입력 중이다. `bridge_bench_command()`까지 입력,
  `advance/init/poll`은 빈 함수, app_main의 호출 두 곳은 미추가다. 입력 오타는 안내 문서의 재개 메모를 따른다.
- 설명은 목적·상태 흐름·시간 상수·enum과 `s_bench_state`까지 진행했다. 다음 학습은 나머지 상태 변수부터다.
- 새 코드의 빌드·플래시·HELP·M1 구동은 미실행이다. 과거 30/30을 새 미완성 코드의 PASS로 사용하지 않는다.
- 현재 전원 분리 완료는 사용자가 마지막으로 따로 보고하지 않았다. 재개할 때 실제 상태를 확인한다.
- 첫 실모터 방향·CPS·구동 중 노이즈·실모터 정지, 전체 T005A 수용과 주행은 미완료다.
