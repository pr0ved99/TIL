# MVP의 사전 설계·구현·검증 과정 평가

기준일: 2026-10-27. 사용자 요청은 “철저히 설계한 뒤 구현한다”는 동일한 철학으로 현재 MVP를 평가하는 것이다. **본 문서는 기존 설계/코드/시험 기록의 분석이며 새 시험 결과나 인수 판정 변경이 아니다.**

## 1. 종합 판단

현재 MVP는 **안전 책임과 출력 규칙을 먼저 설계하고 단계적으로 구현·측정했으며, 실제 통합에서 발견한 문제를 보완한 시스템**이다. 모든 상세 조건을 제작 전에 확정한 뒤 한 번에 성공한 개발 과정은 아니다.

- 강점: STM32의 최종 출력 책임, 명령과 출력의 분리, 재시작 방지, 하드웨어/소프트웨어 정지 경로, 모터 분리 상태의 신호 검증, 요구사항과 근거 연결.
- 부족: 일부 실물 핀/관점 대조, 통신 전체 경로의 지연 여유와 관측 가능성, 정량 인수 조건 및 최종 실행 구성과 근거의 연결.
- 완료한 것: 제한된 저속 주행·정지·통신 유실 복구·엔코더 전달·거리/오차 기록과 시연의 해당 범위.
- 미완료: 현행 검증표가 정한 전체 MUST 인수. 센서/ADC·CAN·PID 등 후속 기능의 미구현과 혼동하지 않는다.

수정 횟수나 문서 분량으로 완성도를 점수화하지 않는다. 설계가 어떤 가정에 의존하며, 그 가정과 요구를 어떤 증거로 확인했는지가 평가 기준이다. 모든 설계 결정이 최초 구현 전에 완료됐다는 시점 주장은 하지 않는다.

## 2. 현재 MVP의 목적과 실제 구현

[최종 MVP 계획](../plans/00_Project_Master_Plan_To_Final_MVP_ko.md)의 종료선은 무선 명령으로 저속 주행·정지하고 엔코더 이동량을 기록/검증하는 궤도형 하위 플랫폼이다. 현재 경로는 브라우저→ESP32-S3→UART→STM32F446→MDD10A다. 엔코더·최종 출력·timeout은 STM32가 담당한다.

전류·온도·전압 ADC, 확장 쉴드, CAN, 폐루프 PID, ROS 2·SLAM·Nav2는 후속 범위다. 이들의 미구현을 현재 MVP의 설계 실패로 평가하지 않는다. 동시에 후속 분리는 장시간 운전·열적 적합성·정밀 속도 제어의 검증 완료를 뜻하지 않는다.

현재 `drive_command_mapper.c`는 요청을 좌우 PWM으로 변환하고 제한한다. 직진 시 왼쪽 gain은 전진960‰·후진930‰다. **속도 단위의 요청이 실제 해당 속도를 유지하는 폐루프 제어를 뜻하지 않는다.** 해당 제한을 화면/운용 자료에 표시한 것은 올바르다. [현재 mapper](../../03_Firmware/stm32_uart_mvp/Core/Src/drive_command_mapper.c), [운용 문서](../handoff/CURRENT_MVP_OPERATION_RUNBOOK_ko.md)

## 3. 사전 설계가 실제로 효과를 낸 부분

### 3.1 명령과 출력의 책임 분리

[상태 모델](../../01_System_Architecture/16_Control_Loop_and_State_Machine_ko.md)은 통신은 동작을 요청하고, 상태가 허용 여부를 판단하며, 출력 계층이 PWM을 쓰도록 정한다. 현재 구현은 DISARMED/ARMED/FAULT와 별도 reason으로 표현한다. 문서의 확장 상태 이름을 모두 구현했다고 해석하지 않는다.

현재 `uart_mvp_protocol.c`의 timeout 경로는 거리 동작 취소·출력 정지·요청0·DISARMED/CMD_TIMEOUT을 함께 처리한다. E-stop 경로도 출력 정지와 요청0 후 FAULT 및 래치를 유지한다. 통신이 회복됐다고 이전 비영 명령을 자동 복원하는 것을 허용하지 않는 설계가 핵심이다. [코드](../../03_Firmware/stm32_uart_mvp/Core/Src/uart_mvp_protocol.c)

이는 “움직여 본 뒤 정지 기능을 덧붙인다”는 흐름과 달리 동작 허가 조건을 구조에 포함한 근거다. 코드 확인만으로 실제 정지 시간이나 모든 고장 조건을 PASS 처리하지 않는다.

### 3.2 정지·복구의 역할 구분

[E-stop 기능 회로](../../01_System_Architecture/25_Physical_EStop_RevB_Circuit_Architecture_ko.md)는 hazard/FMEA→요구사항→회로 블록→부품→도면→시험의 연결을 명시한다. K1 모터 공급 경로와 PC7 감지/STM 래치는 별개다. S0 해제, S2 전원 재인가, STM 래치 해제와 새 ARM은 서로 다른 동작이다.

이 구분은 통신이나 MCU의 정상 동작에만 정지를 의존하지 않으려는 설계 의도를 보여준다. 현재 일반 릴레이 구성에 안전 인증·단일고장 내성·완전 절연을 부여하지 않는다. 소프트웨어 PWM0, K1 공급 차단, 물리 정지는 각각 해당 근거가 필요하다.

### 3.3 모터를 연결하기 전 신호부터 검증

[8/3 PWM/방향 시험](07_STM32_Motor_Output_Waveform_and_Direction_Timing_Test_Report_2026-08-03_ko.md)은 모터와 MDD10A 전력단을 분리하고 MCU 핀 파형·출력0·방향 전환의 비활성 구간을 확인했다. 이후 제한 구동, 양 궤도, 지상 주행 근거가 연결된다. 초기 보고서의 주파수/설정을 현재 설정으로 소급하지 않는다.

이러한 측정은 사전 설계를 포기한 것이 아니라, 실제 모터에 적용하기 전에 하위 설계가 의도대로 구현됐는지 확인하는 단계였다.

## 4. 사전 검토로 더 줄일 수 있었던 문제

### 4.1 K2 릴레이의 도면 시점과 실물 방향

[9/5 기록](../progress/2026-09-05_progress.md#k2-bottom-view-correction)은 TX2-12V bottom-view 핀 도면을 부품면 좌표에 그대로 적용해 행과 코일 극성을 반대로 해석한 문제를 기록한다. 실물 dimple/pin1을 대조해 수정했다.

이는 모터 마찰처럼 계산만으로 예측하기 어려운 특성이 아니다. **데이터시트의 관점→실물 pin1→부품면/납땜면→접속 net**을 조립 승인 전에 대조했으면 줄일 수 있었던 오류다. 공동 설계 검토 과정의 부족으로 평가한다. 뒤에 수정하고 기록한 점은 긍정적이지만 최초 대조의 부족까지 없어지는 것은 아니다.

이번 분석은 이미 교정한 K2를 다시 검사하라는 지시가 아니다. 후속 PCB에서는 footprint 검토와 조립 관점 대조에 이 교훈을 적용하면 된다.

### 4.2 일부 정량 합격 조건이 통합 뒤에도 미정

정지·재시작 방지 원칙은 명확하지만, [인수 판정41](41_MVP_Acceptance_Disposition_2026-10-24_ko.md)은 T005A/T007의 전체 수용에 필요한 일부 정량 기준과 근거가 미완료임을 남긴다. 관측값을 얻었다는 사실과 그 값이 요구를 만족한다는 판정은 다르다.

설계 우선 철학에서는 **어떤 고장을 배제할 것인지, 무엇을 측정해 어느 조건이면 합격인지**를 해당 시험 전에 최대한 명확히 해야 한다. 이 지점에서 현재 MVP의 설계·검증 계약은 완전히 닫히지 않았다.

이미 얻은 값에 맞춰 합격선을 만들거나 사용자 제외 조사를 복원하지 않는다. T005A PARTIAL/T007 BLOCKED와 기존 제외/후속 경계를 유지한다.

## 5. 구현과 실측을 통해 확인해야 했던 부분

### 5.1 통신 지연 — 정지 정책과 연속 운용 품질을 분리

현재 브라우저의 control 신선도200ms·TEL250ms, STM 명령 timeout300ms는 서로 다른 단계의 조건이다. 이 수치가 물리 정지 시간 상한을 증명하지 않는다.

기존 로그에서 TEL/control 나이가 해당 한계를 넘어 정지한 사건은 **정해진 차단 정책이 작동한 근거**다. 동시에 정상적인 버튼 유지 중 명령 지속을 방해한 지연은 운용 품질의 문제로 남는다.

[경로 검토40](40_WS_Delivery_Path_and_Minimal_Observation_2026-10-23_ko.md)은 ESP 작업 큐·잠금·socket send·TCP/Wi-Fi·브라우저 전달/처리를 구분한다. 설정된 socket 대기 가능 시간과 제어 신선도 조건 사이의 차이도 확인했다. 실제 사건에서 특정 호출이 원인이었다는 증거는 없다.

설계 개선점은 새 기능을 늘리는 것이 아니라 **정상 운용 조건에서 허용하는 지연/정지 빈도와 각 경로의 여유, 원인을 구분할 최소 관측 항목**을 연결하는 것이다. 무선 경로의 모든 지연을 사전 계산으로 확정할 수는 없으므로 해당 운용 환경의 표본도 필요하다. 이 분석만으로 기존200/250/300ms를 늘리지 않는다.

전원 조정 후/이후 관측에서 정상 표본을 확보했지만 재부팅과 환경 변화가 함께 있어 원인을 전압으로 확정하지 않았다. UI 개편 전 v5.2의 짧은 JS 처리 시간도 네트워크 전체나 개편 후 UI 성능 보증은 아니다. ACC-COM-01/ACC-UI-01은 OPEN 유지다.

### 5.2 구동 편차·거리 모델

좌우 PWM gain 조정은 제한된 운용 조건에서의 조정이다. 배터리·부하·바닥·장력 등이 달라져도 같은 속도를 유지한다고 보장하지 않는다. 이 영향 자체는 실제 구동에서 확인할 필요가 있다.

지상1m의 실제/엔코더 추정·오차를 기록한 요구는 PASS다. 두 회차의 근접한 결과를 일반적인 거리 정확도·직진성·자동1m 정지의 근거로 확대하지 않는 점은 적절하다.

이러한 조정/검증은 제작 전 설계가 없었다는 증거가 아니다. 반면 잘못된 pin map 같은 결정적 오류까지 같은 종류의 불가피한 튜닝으로 묶어서는 안 된다.

| 관점 | 현재 판단 | 근거/한계 |
| --- | --- | --- |
| 기능·책임의 구조 | 사전 설계가 잘 반영됨 | STM 최종 출력, ESP 전달, 명령/허가/출력 분리 |
| 상세 설계 완결성 | 일부 부족 | K2 관점 대조 오류 이력, 일부 정량 인수 조건 미정 |
| 제한된 기능 통합 | 실제 성과 있음 | 저속4방향·정지·유실 복구·count 전달·거리 기록·시연 |
| 안전 기능의 관측 | 다수 근거 있으나 전체 수용 아님 | MCU 핀·제한 구동·영상의 범위를 구분; T005A/T007 남음 |
| 통신 연속 운용 | 정상 표본 있으나 원인 미결 | 과거 지연/UI 원인OPEN, 전체 지연 여유 미확정 |
| 재현·증거 관리 | 근거를 연결한 점이 강점 | 원본·설정·한계 존재. 최종 구성과 모든 증거 연결은 미완료 |
| 전체 MVP 인수 | 미완료 | 현행 MUST 종료 규칙상 PARTIAL/BLOCKED 잔존 |

[검증표](05_Final_MVP_Requirements_and_Verification_Matrix_ko.md)는 요구↔설계↔구현↔시험의 V-model 연결과 모든 적용 MUST의 PASS를 종료 조건으로 둔다. 감독하 저속 기능 시연이 성립한 것과 그 규칙상 전체 완료는 다른 판단이다. 현재 근거가 다른 제품보다 우수하다거나 산업용 신뢰성을 확보했다고 평가하지 않는다.

## 7. 설계 철학을 이어가기 위한 권고

1. **완료하려는 범위와 주장 범위를 함께 유지한다.** 저속 감독하 기능의 완료와 전체 인수 미완료를 각각 표기한다. PCB·센서·CAN·PID를 MVP 선행 조건으로 추가하지 않는다.
2. **미결을 원인별로 분리한다.** 설계 결정 미정, 실제 측정 미실시, 기존 증거 연결 부족, 원인 미재현을 같은 재시험 목록으로 만들지 않는다.
3. **다음 변경의 통과 조건을 구현 전에 정한다.** 입력/출력·전원/복구·시간 조건·관측 방법과 해당 검증 범위를 먼저 정의한다. 기준 미정인 채 반복 구현하지 않는다.
4. **이미 확인한 결과는 보존한다.** 같은 정상 주행/IDLE 표본의 자동 반복, 완료한 단절 시험·rail-off 조사 재개는 이번 평가의 결론이 아니다. 새 질문을 구분할 수 있는 측정만 후속으로 검토한다.

Codex 진행 지원의 개선점도 같다. 일부 문서의 미결을 새 필수 작업으로 되돌린 과거 진행은 이미 판정41에서 정정했다. 설계 깊이와 범위를 지키려면 현재 승인 범위·완료 근거·새 질문을 확인한 뒤 다음 일을 지정해야 한다.

## 8. 이번 범위

현재 상태/운용 문서·검증표·설계·실제 mapper/정지 코드와 필요한 역사 기록을 읽고 평가했다. 새 MCU 빌드/플래시·하드웨어 시험·코드/도면 변경·요구사항 판정 변경은 없다. 신규 분석과 진행 진입점만 저장하며 Git/Calendar/Notion의 새 게시 작업은 수행하지 않았다.
