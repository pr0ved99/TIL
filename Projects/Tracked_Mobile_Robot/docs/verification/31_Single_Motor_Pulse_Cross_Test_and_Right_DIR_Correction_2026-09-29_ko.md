# 단일 모터 구동·교차시험과 오른쪽 방향 보정

시험 세션: 2026-09-28~29. 문서 마감: 2026-09-29.
근거는 [원본 로그 12개와 요약](../../assets/logs/motor_output/2026-09-29_single_motor_bench/README.md), 사용자 육안 관찰과 저장된 소스다.
로그의 시간은 부팅 후 상대 시간이다. 날짜는 대화 세션 기준이며 원본에 없는 절대 시각을 부여하지 않는다.

## 결과와 범위

**B/M2는 DIR 보정 후 정방향·역방향 각각 10%·300ms 단발 구동, 엔코더 부호, timeout 이후 0 복귀를 확인했다.**
두 시험에서 A는 움직이지 않았다는 사용자 보고가 있다.
A/M1도 양수·음수 10% 명령의 회전과 CPS 부호·0 복귀를 확인했지만, 양수 시험의 실제 전진 방향은 사용자가 보지 못했다.
따라서 왼쪽 실제 전진 방향 확인을 다음 작업으로 남긴다.

이 결과는 섀시에서 분리한 단일 모터의 짧은 구동 범위다.
차량 주행, 부하·온도·전류·반복 기동 신뢰성, 모터 구동 중 물리 S0 차단, 전체 T005A PASS로 확대하지 않는다.
기존 T004 PASS와 T005A 전체 PARTIAL을 유지한다.
기존 T-MOTOR-003의 선행 조건인 전체 T005A는 이 실행 시점에도 PARTIAL이었다.
실행된 단발 관측을 보존하되 선행 gate 충족이나 전체 T-MOTOR-003 통과로 소급하지 않는다.

## 시험 구성

| 항목 | 구성 |
| --- | --- |
| 최종 연결 | A=왼쪽/M1/JENC_1/TIM3/left, B=오른쪽/M2/JENC_2/TIM5/right |
| 동력선 | A Motor+→M1A, Motor−→M1B; B Motor+→M2A, Motor−→M2B |
| STM32 | NUCLEO-F446RE는 만능기판에 장착, ST-LINK USB 공급; JP5=U5V, JP1=OPEN |
| ESP32 | UART USB 포트가 STM과 간섭하여 만능기판에서 분리; PC의 UART 표기 USB로 전원·콘솔 공급 |
| ESP 연장 | GPIO17·GPIO18·GND 세 가닥만 만능기판의 대응 ESP 헤더에 연결; 5V/3.3V 연장 없음 |
| 콘솔 / 보드 간 UART | ESP UART0, COM5/115200/8N1; UART1 GPIO17 TX/GPIO18 RX ↔ STM PA10 RX/PA9 TX |
| USB 시험 전원 | XL4015 #1 보드용 2P 두 개 분리·절연; #2는 AUX5V/엔코더/S0-B, GND 공통 |
| 모터 상태 | 두 모터는 섀시에서 분리. 몸체 고정·축 간섭 제거를 안내하고 단계별 사용자 보고로 진행 |
| 계측 범위 | ESP가 수신한 STM TEL와 사용자 육안 관찰. 이번 구동의 별도 전류·로직 파형 캡처는 없음 |

S0 잠금 → 전원 인가 → ESTOP_ACTIVE 확인 → S0 해제 → ESTOP_LATCHED →
RESET_ESTOP → DISARMED/ESTOP_RESET → S2 순간 조작 → 무동작 확인 → 단발 명령 순서로 진행했다.
첫 M1 준비에서 사용자가 MDD 전압 12.48V와 모터 무동작을 보고했다. 모든 후속 시험의 전압을 12.48V로 간주하지 않는다.

## 준비·펌웨어 작업

- 사용자가 ESP 수동 콘솔을 완성하고 빌드·플래시·HELP 응답을 확인했다.
- COM4 열기 실패 후 CP210x 드라이버 설치와 COM5 선택으로 UART 콘솔을 사용했다.
  ESP 단독 상태의 no matching DISARM ACK는 STM 미연결 조건이었다. 세 가닥 연결 후 startup READY를 확인했다.
- 원본 01에는 초기 line sync의 RX_DESYNC 1회 뒤 DISARM ACK/PONG/READY와 PWM/CPS0이 남아 있다.
  이를 모든 이후 오류의 원인으로 일반화하지 않는다.
- 원본 02의 수동 ESTOP_RESET은 matching ACK/TEL과 DISARMED/ESTOP_RESET을 확인했다.
- 코드 입력·빌드·플래시는 사용자 수행. Codex는 저장 소스 검토, Python 검사와 문서화를 수행했다.

## 오른쪽 DIR 수정과 확인

[motor_output.c](../../03_Firmware/stm32_uart_mvp/Core/Src/motor_output.c)의 오른쪽 정의만 변경했다.

| 채널 | 정방향 | 역방향 | 상태 |
| --- | --- | --- | --- |
| 왼쪽 M1 | GPIO_PIN_RESET / LOW | GPIO_PIN_SET / HIGH | 기존 유지. A의 실제 양수 전진 방향 관찰은 남음 |
| 오른쪽 M2 | GPIO_PIN_SET / HIGH | GPIO_PIN_RESET / LOW | 원본11/12와 사용자 육안 관찰로 양방향 확인 |

보정 전에는 양수 M2 명령에서 실제 역회전과 right_cps 음수가 일치했다.
엔코더는 손회전으로 정한 방향을 보고하므로 TIM3 부호 반전/TIM5 유지, A/B 신호선과 1560 counts/rev는 바꾸지 않았다.
원래 Motor+→M2A 배선을 유지하고 signed command→DIR 정의를 수정했다.
사용자가 STM32 빌드·실행 성공을 보고했고, 이후 새 TEL의 STM uptime/err 기준도 초기화된 것으로 관측됐다.
이번 시험에서 DIR 전압을 별도로 계측한 것은 아니다.

## 종료 동작과 관측의 한계

- 원본03~12는 각각 ARM/CMD/DISARM ACK와 CMD_TIMEOUT 후 PWM0을 포함한다.
  TEL의 PWM은 STM 소프트웨어 적용값이며 MDD 출력의 직접 전압·파형 측정값이 아니다.
- 원본11의 첫 timeout TEL은 command_age_ms=368, 원본12는372다.
  약100ms 주기 TEL이므로 정확한 PWM 차단 지연 또는 모터 정지 시간을 이 숫자로 주장하지 않는다.
- 원본12는49TEL/4.8초이고 최종 CPS0 유지 구간은4.1초다.
  요청한5~10초 로그보다 짧으므로5초 이상 정지 증거로 확대하지 않는다.
- 종료 부근에는08의+20,09의−30,10의+40,11의−50,12의+30 같은 반대 부호 단발 샘플이 있다.
  이어서0으로 유지됐다. 실제 미세 반동·입력 노이즈 등의 원인을 이 로그만으로 특정하지 않는다.
- 원본11은err=0 일정, 원본12는err=1439 일정이다.
  이전 원본들의22790→23192→23798→25149→27069→27419→30057→30661 역시 각 로그 안에서는 일정하다.
  증가 구간은 첨부 사이의 공백에 있어 원인·정확한 시점이 미확정이다.
  구동 중 오류 증가가 없다는 판정과 전체 세션 통신 무오류 주장은 다르다.

## 마감 시 코드·검사 상태

- ESP 현재 이미지: M2 역방향 10%/300ms. M2_PULSE는 CMD(-50,-250,300) 한 번을 보낸다.
  BRIDGE_M2_PULSE_TEST_ENABLED=1U, 기존 자동 시험 네 hook=0U.
- HELP: one M2 reverse 10% / 300ms timeout pulse per boot.
  성공·실패·STOP 후 BENCH_FINISHED이며 RESET_ESTOP도 거부한다. 다음 시도에는 ESP 재부팅이 필요하다.
  STM ESTOP latch와 이 ESP 잠금은 별개다.
- STM은 위 오른쪽 DIR 보정 상태. 단발 timeout/안전 게이트 자체는 유지했다.
- Python 함수 추출기의 if(!function(...)) 오인식을 수정하고 회귀 검사1개를 추가했다.
  오른쪽 DIR 검사 기대값도 새 정의로 맞췄다.
- 마지막 검사:31개 중30개 PASS, 시험 hook을 모두0으로 요구하는1개 FAIL.
  현재 수동 시험1U이므로 safe/default 이미지로 복구한 상태가 아니다. 공백 검사는 PASS.
- [manifest](../../assets/logs/motor_output/2026-09-29_single_motor_bench/manifest.json)는 원본 SHA-256와 마감 소스 SHA-256를 보존한다.
  중간 시험마다 ELF/BIN을 보관하지 않았으므로 과거 모든 시험의 바이너리 동일성을 증명하지 않는다.
- 이번 마감의 Git 커밋·푸시는 요청되지 않았다.
