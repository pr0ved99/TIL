# 2026-07-20 Progress

## Summary

- ESP32 UART bridge에 공통 frame 송신 helper와 `ARM`, `CMD`, `DISARM` frame builder를 추가했다.
- `CMD before ARM -> ARM -> valid CMD -> invalid CMD -> DISARM` 순서의 one-shot state machine을 구현했다.
- ESP-IDF build, flash, COM4 monitor를 완료하고 실제 STM32 USART1 link에서 `ACK/ERR/TEL`을 검증했다.
- valid CMD 이후 추가 명령을 보내지 않았을 때 약 300 ms 뒤 velocity가 zero로 복귀하는 timeout 동작을 확인했다.
- ESP32-STM32 board-only UART bridge MVP를 PASS로 판정하고 screenshot과 raw log를 저장했다.

## Today Work Log

1. UART 송신 경로 공통화
   - `bridge_uart_send_frame()`에서 빈 frame과 최대 길이를 검사했다.
   - frame 본문과 newline을 분리해 전송하고 실제 write 길이를 확인했다.
   - 각 command builder가 newline을 중복해서 붙이지 않도록 했다.

2. command frame builder 추가
   - `bridge_uart_send_ping()`을 공통 송신 helper 기반으로 변경했다.
   - `bridge_uart_send_arm()`, `bridge_uart_send_disarm()`, `bridge_uart_send_cmd()`를 추가했다.
   - signed velocity에는 `int32_t`/`PRId32`, sequence와 timeout에는 `uint32_t`/`PRIu32`를 사용했다.

3. scripted safety sequence 구현
   - `bridge_test_step_t`로 test step을 명시했다.
   - `bridge_uart_run_test_step()`이 한 번 호출될 때 command 하나를 전송하고 다음 상태를 반환하도록 했다.
   - `app_main()`에서 최초 `PING,seq=1` 이후 1초 간격으로 sequence 2-6을 한 번씩 실행했다.

4. build / flash / monitor
   - ESP-IDF v6.0.2 환경에서 build 성공을 확인했다.
   - ESP32-S3에 flash한 뒤 COM4 monitor에서 ESP32 TX와 STM32 RX response를 확인했다.

5. precondition 오류 분리
   - 첫 실행 당시 STM32가 이전 세션의 `ARMED` 상태로 남아 있어 `CMD,seq=2`가 ACK로 수락됐다.
   - 구현 오류가 아니라 `CMD before ARM` 시험의 시작 상태가 맞지 않은 것으로 판단했다.
   - STM32가 `DISARMED`인 것을 확인한 뒤 ESP32 script를 다시 실행했다.

6. 최종 scripted sequence 검증
   - `CMD,seq=2` -> `ERR,code=NOT_ARMED`
   - `ARM,seq=3` -> `ACK,type=ARM`, `TEL,state=ARMED`
   - valid `CMD,seq=4` -> `ACK,type=CMD`, `TEL,vx=50,w=0`
   - 약 300 ms 뒤 `TEL,vx=0,w=0`
   - invalid `CMD,seq=5` -> `ERR,code=OUT_OF_RANGE`, `last_seq=4` 유지
   - `DISARM,seq=6` -> `ACK,type=DISARM`, `TEL,state=DISARMED`

## Decisions

- ESP32-STM32 board-only UART bridge MVP는 PASS로 종료한다.
- ESP32는 command source / relay / logger이며 STM32의 safety 판단을 대신하지 않는다.
- state-dependent test는 실행 전 초기 상태를 telemetry로 확인해야 한다.
- 다음 low-level hardware 단계는 MDD10A logic input test다.

## Blockers

- UART bridge 범위의 blocker는 없다.
- 실제 motor output path는 아직 연결하거나 검증하지 않았다.
