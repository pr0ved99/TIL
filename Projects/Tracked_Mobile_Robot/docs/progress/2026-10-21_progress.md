## 공중 거리 실측 정리 — 20cm 미실시

사용자가 `20은 하지말자`로 다음 20cm 시험을 진행하지 않기로 했다. 이번 측정은 5·10·15cm 각 1회 보고까지로 정리하며 20cm는 **미실시**다. 거리 계수 `1687/19500 mm/count`와 기존 출력/gain은 유지한다.

| 목표 | 왼쪽 실제 링크 이동 | 오른쪽 실제 링크 이동 | 최종 엔코더 환산 좌/우 | 증거 범위 |
|---|---:|---:|---:|---|
| 50mm | 52mm | 52mm | 미확보 | 사용자 실측 보고, 당시 JSON은 빈 회차 |
| 100mm | 102mm | 101~102mm | 102.69 / 101.83mm | 원시 JSON·실측 보고 |
| 150mm | 151~152mm | 151~152mm | 152.26 / 152.09mm | 원시 JSON·실측 보고 |
| 200mm | 미실시 | 미실시 | 미실시 | 사용자 요청으로 이번 측정에서 제외 |

10cm는 boot1070385225/control2/ARM1201006582, 최종 count1187/1177이다. 15cm는 같은 ESP boot/control4/ARM1201006635, 최종 count1760/1758이다. 두 회차 모두 `DISTANCE_REACHED → DISARMED/DISARM`, 양쪽 요청/PWM/CPS0, drop/err0과 연속100ms TEL을 확인했다. 정지 관측 이후 count 유지 구간은 각각1.8초/4.1초다. [10cm 분석](../../assets/logs/wifi_link/2026-10-21_distance_100mm_air_run01/observations.json)·[원본](../../assets/logs/wifi_link/2026-10-21_distance_100mm_air_run01/browser_report.json), [15cm 분석](../../assets/logs/wifi_link/2026-10-21_distance_150mm_air_run01/observations.json)·[원본](../../assets/logs/wifi_link/2026-10-21_distance_150mm_air_run01/browser_report.json).

15cm 첨부에는 오래된10cm 항목도 포함된다. 그 항목은 이후 count 변화 flag와 오래된 sample 삭제가 있으나 최초10cm의 baseline/cutoff/final은 보존돼 있다. 최초 원본과 이번15cm 회차를 구분해 판정했다. 회차 사이 STM 시각이 감소하므로 서로 다른 ARM의 시간축을 합치지 않는다. 리셋/후속 count 변화 원인은 미확인이다. 출력 차단 관측 후 오른쪽 count는10cm에서3, 15cm에서2 감소한 뒤 고정됐으며 물리 원인은 단정하지 않는다.

이는 공중 링크 이동의 단일 회차 비교와 TEL상 목표 도달·정지 근거다. 반복 정밀도, 정확한 전기적 차단/물리 정지 시각, 지상 차체 거리·슬립 또는 전체 MVP PASS로 확대하지 않는다. 마지막 제공 로그는 DISARMED·출력/CPS0이며 종료 전원 분리는 미보고다. 추가 거리 구동은 안내하지 않고, 다음 작업은 사용자 지시에 따른다.

## 거리 기록 복사 버튼 적용

사용자가 공중 5cm 목표 시험에서 좌우 링크가 각각 52mm 이동했다고 보고했다. 목표 대비 각각 +2mm(+4%)이며 단일 회차 사용자 실측이다. 거리 JSON은 아직 제공되지 않아 목표 차단 count·관성 이동과 실측 오차 원인은 미판정이다. 직전 짧은 움직임은 사용자가 버튼을 유지하지 않았다고 정정했으며 ACK 경고 자체의 발생 원인을 로그로 확정한 것은 아니다.

요청에 따라 실제 ESP `wifi_link_main.c` PAGE의 `거리 기록 보기`를 `거리 기록 복사`로 바꿨다. 전체 기존 JSON을 복사하고 성공 안내를 표시한다. 보안 컨텍스트에서는 Clipboard API를 사용하며 일반 HTTP 또는 API 거부 시 선택된 textarea의 copy 명령을 시도한다. 이것도 실패하면 전체 선택된 6줄 입력칸과 Ctrl+C/복사 메뉴 안내를 남긴다. 주행 의도가 있을 때는 복사를 시작하지 않으며 비동기 권한 실패 후 새 ARM이 시작됐으면 입력칸으로 포커스를 옮기지 않는다.

## 타이밍 저장본 오류와 교정 후보

사용자가 입력한5개 파일을 직접 읽었다.6개 문제를 확인했다: `encoder_speed.c`의 snapshot if 닫는 괄호 누락, `uart_mvp_protocol.h`의 `UART_HandelTypeDef` 오타, `main.c`의 `s_encoder_last_publishh_ms` 선언과 사용 불일치·CPS 상한 비교 부호 반대·`left_raw_coutn` 오타·옛 helper/로그 함수 잔존에 따른 두 함수 중복 정의다. 특히 CPS 상한 `<`는 정상값도INT32_MAX로 바꾸는 논리 오류다.

[실제 저장본 검사](../../assets/logs/wifi_link/2026-10-21_distance_timing_saved_review/saved_validation.json)는 중복 함수 구조 검사에서 FAIL이며 아직 native 컴파일까지 진행하지 않았다. 검사기는 중복 정의를 명시적으로 검출하고 상수 정렬 공백 차이는 허용하도록 개선했다.3개 파일의4개 범위를 한 번에 고칠 [전체 교정 블록](../../assets/logs/wifi_link/2026-10-21_distance_timing_saved_review/stm_distance_timing_correction_ko.md)을 준비했다. 실제 생산 파일은 수정하지 않았다.

현재 입력본에서 해당4개 범위를 메모리상으로 교정한 [후보 native 검사](../../assets/logs/wifi_link/2026-10-21_distance_timing_saved_review/corrected_candidate.json)는 기존 출력/정지 회귀와 비동기 TX·빠른 count 검사를 통과했다. 이 결과는 교정 후보 PASS이며 현재 저장본은 FAIL로 유지한다. 다음은 사용자 전체 교정·저장 → 실제 파일 재검토/`--saved` 재검사다. 보드 build/flash/새 구동은 없다.

## 빠른 count와 비동기 UART 입력 준비

`TK-MVP-03-06` 두 번째 입력 묶음을 준비했다. [전체 입력 안내](../../assets/logs/wifi_link/2026-10-21_distance_timing_candidate_review/stm_distance_timing_typing_ko.md)는 기존5개 STM 파일의12개 지정 범위를 다룬다. 생산 파일에는 적용하지 않았으며 사용자 입력·저장본 검토가 다음이다.

후보는 CPS100ms 시간창을 유지하면서 raw counter snapshot을5ms 목표 주기로 발행한다. 반복 ENC3/ENC5 USB 출력을 제거하고, USART1은 고정 전송 버퍼와 응답 FIFO4개·최신 대기 TEL1개로 `HAL_UART_Transmit_IT()` 송신한다. 기존 USART1 IRQ를 사용한다. 응답 우선·stale pending TEL 폐기·RX64byte 처리 예산을 적용한다. 송신 실패/100ms 완료 누락/응답 포화 시 출력0과 재부팅까지 ARM/CMD 차단을 설계했다. 기존300ms CMD timeout·E-stop·PWM 제한/gain은 유지한다.

[native 후보 검사](../../assets/logs/wifi_link/2026-10-21_distance_timing_candidate_review/validation.json)는 기존 출력/정지 회귀, snapshot/wrap/overflow,5ms count/100ms CPS, ARM 이후 기준점, 비동기 버퍼 수명/응답 우선/TEL 합치기, 큐 포화·송신 실패·완료 누락과 TX 중 timeout/E-stop 정지, RX 예산을 통과했다. 실제 MCU build/flash·IRQ 지연·제어 주기·거리 정확도는 검증하지 않았다.

아직 목표 명령·`distance_move_update()`·PWM 차단·ESP UI는 연결 전이다. 입력 후 `test_distance_timing_candidate.py --saved`로 실제 저장본을 검사하고 그 연결 단계로 이동한다. 기존 동기 TX mock 검사는 비동기 adapter가 필요하며 이전 PASS를 새 경로의 통합 PASS로 사용하지 않는다.
