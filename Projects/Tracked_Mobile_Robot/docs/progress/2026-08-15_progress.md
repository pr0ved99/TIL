# 2026-08-15 Progress

## What changed

- 실제 만능기판 실사와 Onshape Top View를 교차 검토해 fixed-header 예비 좌표, module/service
  경계와 ESP32 antenna 보수적 keep-out을 문서화했다.
- 사진 추정이었던 BNO085 socket 열을 Onshape 정투영과 대조해 `C33`으로 정정했다.
- R9~R12 `10 kΩ` pull-down의 우측 상단 dry-placement candidate A를 작성했다.
- 실물 dry placement 전에 `55 x 37홀` digital component/solder-side layout, KiCad-net-to-hole
  review와 1:1 실물 대조를 수행하는 Gate를 채택했다.
- 전용 도구 후보를 검토해 VeroRoute 2.40을 1순위 파일럿으로 선택했다. Windows portable
  package를 압축 해제해 빈 main window가 정상 실행되는 것을 사용자 화면으로 확인했다.
  KiCad 10 import 호환성 검증은 아직 수행하지 않았다.
- VeroRoute 내장 Tutorial 3에서 100 mil grid, 전체 layout 이동, 자동 grid 확장/축소와
  zoom 조작을 사용자 화면 및 완료 보고로 확인했다.
- 실제 작업 파일을 위한 `09_Electrical_Design/VeroRoute/` 폴더와 좌표·범위·안전 경계
  README를 추가했다.
- 빈 작업 파일 `Tracked_Mobile_Robot_Perfboard_RevB_WIP.vrt`를 생성하고 실제 파일 크기
  12,748 bytes로 저장된 것을 확인했다.
- 초기 파일에서 target-dimension `54 x 36` 저장을 확인했으나, 이는 55 x 37홀의 중심
  interval 수를 VeroRoute target size로 잘못 해석한 값이었다. 사용자 화면 검토에서 흰
  영역이 `C55/R37`을 포함하지 않는 것을 발견해 해당 target-area PASS를 취소했다.
- KiCad 10.0.5 CLI의 `orcadpcb2` export가 실제 RevB-WIP에서 생성되는 것을 확인했다.
  R9~R12의 net은 정본과 일치했지만 모든 미지정 footprint가 `$noname`으로 합쳐져 전체
  direct import는 아직 부적합하다고 판정했다.
- 정본을 수정하지 않고 parser/layout 호환성만 확인하도록 J5와 R9~R12를 분리한
  `Tracked_Mobile_Robot_R9_R12_OrcadPCB2_Pilot.net`을 추가했다.
- VeroRoute 2.40에서 pilot을 import해 J5 5개 pad, R9~R12와 예상 `Broken Nets 1..5`가
  생성되는 것을 사용자 화면으로 확인했다. 저장 artifact는 54,765 bytes, SHA-256
  `76BB23E80BFF967574B678ADEC6E65FF30EB1D46F8CB66CBC84A66E625D6F0C1`이며 OrcadPCB2
  parser/import는 PASS다. 당시 유지된 target `54 x 36`은 별도 화면 검토에서 부적합으로
  판정됐으며 import PASS의 근거로 사용하지 않는다.
- PASS pilot을 메인 `Tracked_Mobile_Robot_Perfboard_RevB_WIP.vrt`로 승격하고 두 파일의
  크기와 SHA-256이 동일한 것을 확인했다. 이후 pilot은 고정 증빙, WIP만 편집 대상으로 둔다.
- WIP에 외곽 C1..C55/R1..R37 number guides와 NUCLEO, ESP32, BNO085 fixed socket을
  배치했다. 사용자가 실제 BNO085 socket을 다시 세어 `10 pin`임을 확인했으므로 기존
  photo/Onshape 추정 `C33/R1..R11, 1 x 11`을 `C33/R1..R10, 1 x 10`으로 정정했다.
- 저장된 WIP는 74,122 bytes, SHA-256
  `384C431E3E7962BCE2407E763F17C8AA36F5C61CA9A85506AC1438382AEAD394`다. 위치는 화면상
  목표 범위와 일치하지만 일부 reference name은 아직 위치 기준 명칭으로 정리해야 한다.
- fixed socket reference cleanup을 완료했다. `H_NUC_UP_R4/R5`, `H_NUC_LOW_R28/R29`,
  `H_BNO_C33`, `H_ESP_UP_R26`, `H_ESP_LOW_R35`와 세 socket value가 저장 파일에 존재하며
  `IC1~IC3`, 잘못된 `H_ESP_LOW_R26`는 제거됐다. 현재 WIP는 74,164 bytes, SHA-256
  `7F73ECEF50B32A83B6B56AC55BD44FDB5367908650E75637C3CD224E37F4E6D3`다.
- WHEELTEC 공식 공유 archive 전체 다운로드를 사용자가 시작했다. 사용자 화면 기준
  `1.48 GB / 5.90 GB`, 약 `125.16 KB/s`였으며 완료 전 파일은 motor evidence로 판정하지 않는다.
- VeroRoute WIP에서 provisional `J5_MDD10A_LOGIC`, R9~R12와 common-GND local routing을
  입력했다. 각 DIR/PWM/GND 경로가 서로 다른 Net 색으로 유지되고 빨간 floating Wire가 없는
  사용자 화면을 확인했다. STM32 측이 아직 열려 있으므로 `Broken Nets 1...5`는 예상 상태다.
- VeroRoute에서는 일반 component pin과 Wire 끝이 같은 홀을 공유할 수 없음을 실제 red-floating
  사례와 배치 규칙으로 확인했다. 부품 핀은 인접 빈 홀의 Wire endpoint와 one-pitch solder
  bridge로 연결하도록 규칙을 고정했다.
- STM32의 PC8/PB6/PC9/PB7/GND에서 우측 local block까지 이어지는 5-Net 전체 경로를
  `09_Electrical_Design/08_Perfboard_STM32_to_MDD10A_Routing_Plan_ko.md`에 고정했다.
- 문서에 고정한 순서대로 STM32 측 Net 1, 2, 3, 5, 4를 모두 입력했다. 사용자 화면에서
  `Broken Nets` 목록이 비어 있고 빨간 floating Wire/안내선이 없는 것을 확인해 VeroRoute
  디지털 connectivity를 PASS 처리했다. 저장 WIP는 99,971 bytes, SHA-256
  `52F03CC17CAD1A832D94D2BE5FD2FB4D27FC879ECF83E3A2A57C35FC9D969630`이다.
- KiCad 10.0.5 CLI로 RevB 정본의 XML netlist를 새로 내보내 J5/J6/R9~R12 핀 topology를
  다시 추출했다. ST UM1724의 CN10/CN7 pin table과 VeroRoute C/R 좌표를 대조해 5개 Net을
  모두 PASS 처리했다. XML은 70,532 bytes, SHA-256
  `D1CF041915EFF160F44DC3551DB84CCA77F1A650699A920696DF44C6327978B8`이다.
- 정밀 대조 결과 Net4 `C46` 세로선은 다른 signal 가로선과 교차하지 않고 R9의 GND bus만
  절연 교차함을 확인했다. 이전의 Net1~3/5 교차 설명은 좌표상 부정확했으며 문서에는
  실제 교차점만 기록했다.

## Why

- Component/solder-side 좌우 반전, 한 홀 오차, open/short와 module removal 간섭을 납땜 전에
  발견해 기존 영구 header의 재작업 위험을 줄이기 위함이다.
- 이 단계는 새 대단원이 아니라 대단원 2 permanent pull-down/Physical E-stop 저전류 배선의
  기존 hole-coordinate/underside-wiring 산출물을 구현하는 방법이다.
