## 결정과 미완료

- `batt_mv=null`, `battery_available=false`로 미구현 배터리를 명시한다. ADC 배터리 전압·잔량, RPM·누적 tick, 1ms PID·무선 실시간 보장을 새 성과로 기록하지 않는다.
- STARTUP 결과는 RX 태스크에서 공개 문자열로 변환하고 mutex로 전달한다. READY는 현재 STM 세션이나 모터 구동 허가를 대신하지 않는다.
- W5 브라우저 명령은 아직 없다. Wi-Fi 앱은 상태 전달과 부팅 DISARM/PING만 실행한다. 기존 `esp32_uart_bridge`의 M2_RUN 수동 시험 설정은 별도 소스/이력이다.
- STM PONG 누락 시험 hook은 0U로 복원했고 사용자 빌드·실행 뒤 READY를 확인했다. PA10 pull-up은 USER CODE 영역에 남겼다.
- 마지막 `err=1`은 이번 ESP 재부팅 후 관측한 누적값이다. 단일 화면으로 지속 증가 여부나 특정 UART 하드웨어 오류 종류를 확정하지 않는다. 소프트웨어 거부와 하드웨어 UART 오류가 함께 계수된다.
- 모니터 재실행 전후 boot_id가 달랐고 err은 증가하지 않았다는 사용자 정정을 반영한다. 모든 재기동에 err 증가가 필수라는 주장·재기동이 없었다는 해석은 사용하지 않는다.
- 전류·열·양쪽 동시 구동·주행·전체 물리 비상정지 수용·배터리 ADC·PCB는 기존 미완료 범위를 유지한다.

## 상세 작업 기록

### 실제 STM UART와 상태 전달

두 보드가 만능기판에 장착돼 있어 Dummy Task는 만들지 않았다. 실제 TEL 14필드를 검토하고 RX line assembly·parser·snapshot·age·JSON·WebSocket을 결합했다. STM `t_ms`와 ESP uptime을 직접 빼지 않고 ESP 유효 수신 시각으로 age를 계산한다. invalid line 뒤 LF까지 폐기하고 유효 TEL에서 복구하는 관측도 보존했다.

### 리셋·부팅 응답 누락

리셋 때 err 증가를 로직 분석기로 조사하고 PA10 내부 pull-up을 추가했다. 원본3개 모두 4MHz·100M samples·25초이며 수치와 해석 한계는 보고서33을 따른다. 기동 LOW는 디지털로 확인했으나 핀 부동/아날로그 원인을 단정하지 않았다.

STM RESET 유지 중 ESP를 재기동해 DISARM ACK 누락, PONG 시험 hook으로 PONG 누락을 각각 확인했다. 두 경우 최대3회 실패 뒤 TEL 수신은 계속했다. hook 복원 후 정상 부팅으로 돌아왔다.

### 부팅 결과와 TEL 상태의 독립 표시

사용자가 완전한 연결 블록 두 개를 입력했다. Codex가 실제 저장 파일을 다시 읽고 브라우저 테스트 25개를 실행했으며 사용자가 빌드·플래시했다. 처음 화면은 새 READY JSON만 보였으나 브라우저 새로고침 뒤 새 안내 문구도 확인됐다.
