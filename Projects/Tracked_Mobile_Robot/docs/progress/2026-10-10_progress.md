## 결정과 미완료

- W5 PING/DISARM은 진단·비구동 명령 범위다. READY·PING OK를 구동 허가로 쓰지 않는다. FAULT/ESTOP_ACTIVE 유지와 응답 OK는 모순이 아니다.
- 요청4 TIMEOUT 이후의 요청5는 사용자가 PING을 다시 누른 별도 요청이었다. 빠른 연속 클릭이 두 요청을 통과시켰다는 근거로 쓰지 않는다.
- 브라우저 결과 대기3000ms 만료는 ‘결과 확인 불가’이며 STM 응답500ms TIMEOUT과 구분한다. 재접속/결과 만료 뒤 자동 재전송하지 않는다.
- 리셋 invalid-line/err의 전기 원인·구동 중 재기동 안전은 미완료. 새 로직 분석기/전압/모터 관측 없음.
- 별도 `esp32_uart_bridge`의 수동 hook1U·default-off30 PASS/1 FAIL은 유지된다. W5 테스트를 전체 기존 검사 PASS로 합치지 않는다.
- MVP-002/T-COM-002·전체 T005A/모터 수용/주행의 기존 PARTIAL 또는 미검증 상태를 유지한다.

## 후속 ARM/CMD 설계 — 2026-10-10

- ESP W5와 STM parser/state/timeout/mapper/PC7 설정을 대조하고 [초기 계약과 검증 계획](../plans/2026-10-10_WiFi_ARM_CMD_Control_Contract_ko.md)을 작성했다. 설계 기준 Git HEAD는 `d9bf801`, ESP C hash는 W5 마감과 동일하다.
- W5 요청500ms는 STM 기본300ms timeout과 맞지 않는다. CMD 목표100ms, 제어 TEL age250ms, 일회용ticket150ms·CMD 큐50ms·ACK150ms를 첫 구현 기준으로 정했다. 실시간/실제 정지 보장은 아니며 실측 후 조정한다.
- 요청 완료 때 해제하는 W5 owner와 제어를 지속하는 controller를 분리한다. ARM ACK 뒤 새 zero CMD·TEL 확인, owner의 새 CMD만 유지, 끊김/만료 시 세대·미송신 큐 폐기와 priority DISARM, 자동 재허가 없음으로 설계했다.
- 첫 모드는 zero-only다. STM PC7 pull-up/HIGH=active와 FAULT 조건을 우회하지 않는다. AC-H는 실제 함수 host 검사, AC-B는 낱개 보드 거부 경로, AC-S는 정상 conditioned sense 조건의 비구동 실측으로 구분했다. 모든 새 ID는 미실행이다.
- STM은 UART seq/session freshness·RX purge가 없으므로 ESP ticket을 이미 송신된 프레임 회수나 STM UART replay 차단으로 설명하지 않는다. 기존 전체 안전 PARTIAL·nonzero 정지/구동 미검증을 유지한다.
- 초기 설계안을 canonical UART 문서에서 연결하고 진행/계획/로드맵·handoff를 갱신했다. 펌웨어·기존 증거·Hello World build 변경은 보존한다. 새 코드 검사·빌드·플래시·물리 동작을 실행한 것으로 기록하지 않는다.
- 문서 검사:9개 Markdown의 상대 파일 링크209개, 새 계획 ID21개의 중복 없음, 최대 ARM62/CMD111byte가128byte 이내임을 확인했다. 새 계획의 fence/공백과 문서 범위 `git diff --check` 통과, ESP C SHA256 유지·STM/ESP main 소스 diff 없음. 계획 ID 검사는 보드 시험 PASS가 아니다.
