## Confirmed Results

- `PING,seq=1` -> `PONG,seq=1`
- `CMD` before `ARM` -> `ERR,code=NOT_ARMED`
- `ARM,seq=3` -> `ACK,type=ARM`, later `TEL,state=ARMED`
- `CMD,seq=20,vx_mmps=50,w_mradps=0,timeout_ms=500` -> `ACK,type=CMD`
- `TEL,last_seq=20,vx_mmps=50` -> `TEL,last_seq=20,vx_mmps=0` after timeout
- `CMD,vx_mmps=9999` -> `ERR,code=OUT_OF_RANGE`
- `CMD,timeout_ms=3000` -> `ERR,code=TIMEOUT_OUT_OF_RANGE`
- `DISARM,seq=26` -> `ACK,type=DISARM`, later `TEL,state=DISARMED`

## Notes

- `LAST CODE` in the dashboard can keep the previous error code even after later ACKs. Verification should use `LAST TX`, `LAST ACK`, `LAST ERR`, `LAST RX`, Raw Log, and CSV together.
- `timeout_ms=3000` is allowed by the dashboard input field but rejected by firmware range validation. This is acceptable because STM32 remains the final safety authority.
- This validation does not prove motor output yet. It proves UART protocol, parser, safety state gate, and command timeout behavior.
