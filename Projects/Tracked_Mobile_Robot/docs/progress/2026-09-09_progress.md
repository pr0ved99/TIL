# 2026-09-09 Progress — T-ESTOP-004 Coordinator Preparation Paused

## Summary

- `T-ESTOP-004`의 motor-disconnected firmware/PWM 시험을 준비하기 위해 STM32의 기존
  E-stop 경로와 ESP32의 P-03/P-04B 시험 runner를 다시 확인했다.
- STM32 production E-stop 구현은 변경하지 않고, ESP32에서 기존 runner를
  `DRIVE -> RESET -> POST_RESET -> DONE/FAILED`로 연결하는 최소 시험 coordinator를
  사용하기로 확정했다.
- Firmware는 사용자가 직접 입력했다. 현재 `app_main()` scheduler 전문 입력 중 두 오류가
  남아 있어 source는 **교정 전 일시정지** 상태다.
- Build, flash, 전원 인가, logic capture와 새 runtime 시험은 수행하지 않았다.

## Implemented And Preserved

- default-`0U` `BRIDGE_T004_ESTOP_PWM_TEST_ENABLED`와 네 ESP test hook의 상호배타
  compile guard를 추가했다.
- T004 시험값을 `CMD refresh=100 ms`, `timeout=500 ms`, `vx=50 mm/s`,
  `w=0 mrad/s`로 고정했다.
- 과도했던 ACK/ERR snapshot/parser와 25-state FSM 안은 폐기하고 입력한 scaffold를 제거했다.
- 5-state coordinator `DRIVE/RESET/POST_RESET/DONE/FAILED`를 추가했다.
- 기존 P-03 `RECOVERY_HOLD`에는 다음 시험 전용 분기를 추가했다.
  - DRIVE 중 `CMD(50,0,500)` refresh
  - `FAULT/ESTOP_ACTIVE/PWM 0/0` 확인 시 refresh 중단 및 RESET 전이
  - POST_RESET 중 fresh CMD 뒤 `ARMED/vx=50/w=0/PWM 50/50` 확인
  - unexpected FAULT 시 FAILED, 성공 시 기존 final DISARM 재사용
- T004 활성 시 P-03 preamble을 건너뛰고 `BRIDGE_TEST_RECOVERY_ARM`부터 시작하도록
  `test_step` 초기값을 분기했다.
- P-04B DONE 뒤 POST_RESET/recovery ARM/tick 재설정과 P-04B FAILED terminal mapping은
  입력돼 있으나 전체 scheduler 교정 뒤 다시 검증해야 한다.

## Design Decisions

- ESP coordinator는 E-stop 기능을 새로 구현하지 않고 시험 자극 순서만 만든다.
- active command부터 reset 뒤 fresh command까지 같은 STM32 boot/capture로 연결해
  stale command가 reset 뒤 재생되지 않음을 확인한다.
- ACK/ERR의 exact `seq/type/code`는 ESP parser를 확장하지 않고 Saleae D4/D5 UART
  decode로 판정한다.
- PWM 정지 provisional bound는 `T_PWM_ZERO_MAX=200 ms`다. 같은 4 MHz capture에서
  `t0=PC7 stable HIGH`, `t1=PB6/PB7 중 늦은 final falling edge`로 측정하고 이후
  500 ms 동안 두 PWM에 edge가 없어야 한다.
- 서로 연결된 firmware 수정은 한 문자씩 나누지 않는다. Codex가 정확한 교체 범위와 검증된
  전문, 동작 이유를 함께 제시하고 사용자가 전체 블록을 직접 입력한 뒤 actual source를 검토한다.

1. P-03/T004 scheduler가 잘못된 P-04B helper를 호출한다.

   ~~~c
   test_step =
       bridge_uart_run_p04b_estop_reset_test_step(test_step, &test_seq);
   ~~~

   이 위치는 `bridge_uart_run_test_step(test_step, &test_seq)` 호출이어야 한다.

2. POST_RESET 종료가 비교식이며 enum도 잘못됐다.

   ~~~c
   s_t004_coordinator_state == BRIDGE_TEST_DONE;
   ~~~

