# 2026-11-22 진행 기록

## SIM-04 가상 2D LiDAR

사용자가 Xacro에 `laser_frame` 기준 GPU LiDAR를 추가하고, Gazebo 월드의 Sensors 플러그인과 브리지 설정을 연결했다. 도메인 85에서 `/model/tmr/scan`과 ROS `/scan`을 확인했다. 사용자 ROS 표본의 프레임은 `laser_frame`, 시뮬레이션 시각은 39.900초였다.

가상 LiDAR 정면 1.000m에 놓은 벽을 `/scan`의 180번 표본이 0.999870m로 측정했다. 한 스캔에 360개 거리값이 들어왔고 그중 33개가 벽에 닿았다. `odom → laser_frame` 변환의 위치는 (0.065, 0, 0.095)m였다. 사용자는 RViz에서 벽 위치의 스캔을 확인했다. 이 결과는 가상 LiDAR의 측정, 브리지 전달, TF 및 시각화에 한정한다. 가상 IMU와 실물 센서 검증은 후속이다.

## NAV-01 고정 지도 시작

실행 중인 월드에 방 경계 네 면을 배치했다. 방 내부는 X −1.5~2.5m, Y −1.5~1.5m이고 안쪽 벽 중심은 (1.115, 0)m다. 같은 형상을 점유격자로 변환해 `map_server`에서 발행했다. 도메인 85의 `/map`은 `map` 프레임에서 100×80셀, 셀당 0.05m, 원점 (−2, −2)m로 수신됐다. 점유 600셀, 자유 4776셀, 미확인 2624셀이다.

월드 경계와 지도는 실습용이다. 마감에서 방 SDF와 PGM/YAML을 저장소에 보존했다. [원본과 재현 순서](../../assets/logs/ros2/2026-11-22_tmr_lidar_amcl/README.md). [NAV-01 계획](../plans/2026-11-17_Ubuntu_Nav2_Simulation_and_RL_Roadmap_ko.md)

RViz에서 `map`을 Fixed Frame으로 선택했을 때 사용자가 프레임 오류를 보고했다. `/map`은 수신됐고 TF에서 `map`을 찾을 수 없었다. 같은 도메인에서 임시 AMCL 서비스 `tmr-nav01-amcl`을 활성화했다. Gazebo에서 확인한 정지 시작 위치와 방향을 초기 추정값 (0, 0, 0)으로 입력했다. `/amcl_pose`가 `map` 프레임으로 수신됐고 `map → odom`, `map → laser_frame`을 조회했다. 다음은 RViz에서 지도와 스캔을 겹쳐 보고 이동 후 위치 추정을 비교하는 것이다.

RViz의 `Map`에서 `/map` 구독의 내구성을 `Transient Local`로 바꿨다. 사용자 화면에서 Global Status, Map 및 LaserScan이 OK이고, 빨간 스캔 점이 방 벽과 안쪽 벽의 지도 윤곽을 따른다. 이동 비교 전 Gazebo 위치, `/odom`, `/amcl_pose`의 X/Y는 표시 정밀도에서 0m였다. 현재 AMCL의 위치 갱신 거리 설정은 0.25m다.

사용자가 `forward_stop` 두 번을 실행한 뒤에도 RViz에서 벽과 스캔의 정렬을 확인했다. 최종 X는 Gazebo 0.396308m, `/odom` 0.396900m, 현재 `map → base_footprint` 0.390475m였다. 지도 기준 추정의 Y는 0.002481m, yaw는 +0.66178°였다. 시뮬레이터 위치와 지도 기준 현재 추정의 평면 차이는 약 6.3mm다. `/amcl_pose`는 시뮬레이션 836.000초에서 1342.100초로 갱신됐고, 마지막 갱신의 X는 0.243785m였다. 현재 지도 기준 TF는 그 보정과 이후 오도메트리를 합성한다. 정지 시 선속도와 각속도는 0, 정면 벽 거리는 0.603931m였다. 정지 초기화와 한 차례 전진의 위치·스캔 확인을 마쳤다. 다음은 이 지도에서 TMR의 첫 Nav2 목표 이동이다.
