## 결정과 미완료

- 사용자 보유 계측기는 XL830L뿐이며10A 입력이 무퓨즈, 측정선을 고정할 절연 악어클립/전류 리드는 없다.

- 20A/50mV 션트는2.5mΩ, XL830L200mV 범위0.1mV 분해능 가정에서1자리0.04A.
  공개 Excel 설명서 ±(0.5%+2자리)를 적용하면0.1A에서 미터만 약±0.081A이므로 작은 무부하 전류 정밀 측정에는 부족하다.
  실물 미터 사양·교정과 판매 션트 등급이 확정된 전체 오차 보증은 아니다.
- K1 후단/B+ 측정은 드라이버 공급전류다. PWM 권선 전류·순간 기동 피크·I²R 열 평가와 같다고 쓰지 않는다.
- RC 와트미터의 표시 분해능과 정확도 표기가 혼재하고 제조사/내부 측정 근거가 부족해 확정 구매 추천 보류.
  TM-902C9,220원 검색 가격은 실제 제조사·센서 포함·재고 미확인. 앞선2만~3만원 완성 세트 추천은 조건부 후보로 정정.
- 장비 구매·전류/온도 측정은 아직 없다. 작은 전류 측정 가능성과 총구매비를 확인하기 전 자동 구매하지 않는다.
- Wi-Fi 읽기 전용 TEL 표시는 다음 소프트웨어 후보로 제안했다. 무선 제어는 wired 구동/정지 기준 후 단계적으로 검증하고,
  연결 유실 시 과거 PC 명령을 재전송해 STM timeout을 무력화하지 않도록 설계한다. 아직 사용자 착수 결정·구현 없음.

## PCB 전환 검토 의견

사용자는 추가 만능기판 대신 PCB 제작이 어떨지 물었다. 즉시 설계/발주 지시가 아니다.
추천은 **기존 MVP 만능기판·납땜 부품을 보존하고, 미뤄 둔 확장 기판을 소형 PCB로 만드는 단계적 접근**이다.
후보 범위는 PA4/PB0 전압 감지, CAN 모듈/커넥터와 필요한 신호·로직 전원/시험점이다.
CAN/ADC 회로 값·보호·커넥터·실측이 미정이므로 확정된 회로부터 작은 Rev A로 제작한다.
MDD10A·XL4015·K1/퓨즈·모터 전류 하네스를 첫 PCB에 통합하는 것은 별도 전력 설계 범위로 남긴다.

전체 MCU 캐리어 PCB는 핀·전원·USB 간섭·실물 크기·안테나/장착 접근성을 고정한 뒤 검토한다.
PCB의 반복 제작성·실크·배선 고정은 장점이지만 잘못된 풋프린트/핀 방향도 고정된다.
과거 K2 bottom-view 오해와 ESP UART USB 간섭은 실측·1:1 출력·3D 점검에서 다시 확인해야 할 항목이다.
2층 구상/PCB 둘 다 아직 제안이며, 사용자 동의 없이 MVP 종료 조건이나 제작 우선순위를 바꾸지 않았다.

## Wi-Fi 입력본 검토와 빌드 경로 안내

- 사용자가 저장한 앱198줄과 개인 header를 확인했다. C 헤더/매크로·함수명 오타, `status_get()` 전체 누락, IP 로그 누락과 JavaScript 오타4곳을 발견했다.

- 코드 안내8번에 수정 위치와 전체 기준 소스, 새 `esp32_wifi_link` 루트의 VS Code/터미널 빌드 방법을 추가했다.
- 실제 펌웨어/header는 수정하지 않았고 빌드도 실행하지 않았다. 사용자 수정·재검토 대기다. 현재 입력본은 HTTP 폴링 버전이다.

## Wi-Fi AP 실측 — W1/W2/W3 결과

앞 절은 입력·검토 당시 이력이다. 이후 사용자가 앱의 오타/누락과 설정 header의 `#pragma once`, `WIFI_LINK_PASSWORD` 이름을 수정하고 빌드 성공을 보고했다.
사용자가 플래시·모니터를 진행했고 [부팅 로그 원본](../../assets/logs/wifi_link/2026-10-01_ap_http/boot_ap_http.txt)에서 `esp32_wifi_link`, ESP-IDF 6.0.2, AP와 HTTP 서버 시작을 확인했다.
COM5/115200, 최초 로그 boot_id=564440014, DHCP/HTTP 주소=192.168.4.1이다. 이 로그의 ELF SHA256은 접두부 `b9d7c5129...`만 있어 전체 해시로 사용하지 않는다.

| 항목 | 확인 결과 | 근거·범위 |
| --- | --- | --- |
| 사용자 빌드·실행 | 성공 | 사용자 빌드 성공 보고와 새 앱의 부팅 로그. Codex가 빌드·플래시하지 않음 |
| W1 AP/HTTP | 통과 | 브라우저 화면의 수신 정상·JSON, mode=AP/source=ESP_ONLY. 최초 화면 uptime_ms=214352, free_heap_bytes=279744, boot_id는 위 로그와 일치 |
| W2 자동 갱신 | 통과 | uptime_ms·수신 시각 반복 갱신, boot_id=564440014 유지라는 사용자 확인 |
| W3 연결 해제·복구 | 통과 | 응답 없음·마지막 값 보존·재접속 자동 복구 절차에 대해 사용자 통과 보고. 같은 부팅의 해제·재접속에서 boot_id 유지 |
| 재플래시 뒤 식별값 | 변경 확인 | 사용자가 시험 사이 재플래시하여 boot_id가 바뀌었다고 보고. 변경 후 숫자와 바이너리 해시는 미제공. 처음 boot_id가 현재도 유지된다고 기록하지 않음 |
| STM 데이터 | 미연결 표시 정상 | stm_connected=false, state/reason/PWM/CPS=null. 실제 STM TEL·모터 상태 검증이 아님 |

- 원본 로그는 저장소에 보관했다. 브라우저 화면은 대화 첨부이고 연속 갱신/재접속 결과는 사용자 관찰 보고이며 자동 수집 로그나 계측 수치가 아니다.
- 재플래시는 재부팅을 동반하므로 boot_id 변경은 정상이다. 별도 전원 재인가 시험과 재부팅 직후 uptime 초기화 수치는 미기록이다.
- 로그의 감지 용량16 MB/이미지 설정2 MB 경고는 남아 있으나 앱/AP/HTTP 시작은 확인됐다. 전체16 MB 사용 설정·파티션 변경은 하지 않았다.
- 현재 휴대한 ESP 실행 앱은 `esp32_wifi_link`다. 기존 `esp32_uart_bridge`의 M2_RUN1U는 별도 소스/이전 시험 상태이며 로봇 시험 재개 시 대상 앱을 다시 확인한다.
- 이번 결과는 AP HTTP 폴링 범위다. 공유기/노트북 핫스폿 STA·WebSocket·STM 통합·무선 구동 명령을 완료로 확대하지 않는다.
- 다음은 동작한 HTTP 코드 흐름 이해다. WebSocket 상태 전송/STA 접속은 노트북·ESP로 가능한 후속 후보이며 PCB 설계는 독립적으로 진행할 수 있다.
