## 코드 분석과 검증

수정 전 `uart_mvp_process()`는 일반 부분 줄을 LF까지 유지했다. `command_timeout_enforce()`는 출력과 상태를 정지시키지만 부분 줄은 지우지 않는다. 수정 전 ESP executor는 short write 때만 선행LF를 준비해, 실제 신호선이 끊겨도 UART write가 전부 수락되면 그 조건을 감지하지 못했다.

[reproduce_uart_reconnect.py](../../03_Firmware/tests/reproduce_uart_reconnect.py)와 C fixture는 실제 STM protocol/parser/ring/mapper·ESP control 모듈을 PC에서 사용한다. HAL·모터·IRQ는 mock, 실제 보드 IO는 없다. 기존 로컬 TCC0.9.27로 컴파일/실행해 exit0을 확인했다. 보드용 빌드가 아니다. 정상 분할 프레임,300ms timeout 경계/CMD-only 거부, HAL 오류 후LF 재동기화도 진단했다.

수정 전 결과와 소스 식별값은 [증거 묶음](../../assets/logs/wifi_link/2026-10-15_zero_control_bench/README.md), 해석은 [보고서35](../verification/35_WiFi_Zero_Control_Fault_Recovery_2026-10-15_ko.md#4-1016-실제-c-코드의-pc-재현)에 있다. 물리 실패의 유일한 원인은 확정하지 않았다.

후속으로 STM에 ASCII CAN 수신 시 줄 폐기, ESP 모든 DISARM 앞에 CAN+LF를 반영했다. 사용자 입력 오류를 두 차례 실제 파일에서 확인하고 수정 후 `test_uart_recovery.py --saved`를 실행했다. [저장본 출력](../../assets/logs/wifi_link/2026-10-16_uart_cancel_saved/saved_pc.txt)과 [manifest](../../assets/logs/wifi_link/2026-10-16_uart_cancel_saved/source_manifest.json)에 검사 대상 SHA256을 보존했다. 두 보드 빌드 성공은 사용자 보고, 새 부팅 line cancel/DISARM ACK/PONG과 READY/IDLE은 로그·사용자 확인이다. 전체 원본 빌드 로그와 실행 바이너리 hash는 미확보다.

## 다음 작업의 시작 조건

현재 Wi-Fi 앱은 raw UART 주입 콘솔을 제공하지 않는다. 별도 3.3V USB–UART도 없는 것으로 진행한다. 따라서 다음은 바로 실물 주입이 아니라 ESP 기존 UART 송신 태스크를 사용하는 수동·제한 시험 경로의 설계/PC 검토다. 기본 비활성, fresh/IDLE/zero 확인, 송신 경합 방지, 정지 확인 실패 시 BLOCKED를 유지해야 한다. 그 후 사용자 코드 입력·빌드·플래시, 미완성 CMD와 LF 없는 ARM의 폐기를 각각 캡처한다. 기존 정상 재연결 시험을 이유 없이 반복하지 않는다.

## 주간 작업 재개 — UR-02 수동 부분 명령 주입 후보

사용자가 오늘 작업 재개를 요청했다. 새벽 캡처에 실제 부분 줄이 없었던 미완료 조건을 위해,
기존 ESP UART 태스크에 연결하는 **기본 비활성·수동 POST·부팅당 한 번**의 시험 후보를 준비했다.
`CMD,seq=` 또는 LF 없는 `ARM,seq=번호`를 보낸 뒤 약100ms 후 기존 CAN+LF/DISARM과 ACK/새 TEL 확인을 사용한다.
시험 이미지에서는 일반 PING/ARM/CMD와 ticket 발급을 차단하고 수동 DISARM은 유지한다.

- [입력 가이드](../plans/2026-10-16_UART_Partial_Command_Test_Code_Guide_ko.md): 이유·상태 흐름도·실패 경로·정확한 추가 위치와 완전한 함수 교체 블록 8개.
- [후보 C·PC 출력·manifest](../../assets/logs/wifi_link/2026-10-16_uart_partial_candidate/README.md): 실제 STM stream/parser와 ESP executor를 native TCC로 연결. mode0 비활성 및 기존 W5/main 42개, mode1/2 입력·시작 조건·50ms 기한·수동 정지 경합·부분 쓰기·ACK 유실·번호 소진 검사 PASS.
- LF-only 반례에서 최종 DISARM이 성공해도 중간에 오래된 ARM ACK가 발생함을 검출했다. 실물에서도 최종 화면뿐 아니라 해당 ACK/실행 흔적 부재를 확인해야 한다.
- 가이드 8개 블록을 원본에 적용한 문자열이 검토 후보와 일치함을 확인했다. 기존 main host 검사기는 시험 블록이 있을 때만 HTTP mock을 추가하도록 확장했다.

`test_uart_partial_test.py --saved`. 현재 열린 executor 파일을 변경하는 단계가 아니다.
실물 작업 전에는 마지막 보고 이후 전원·배선 변경 여부를 확인한다. UR-02 전체/AC-S PARTIAL 유지,
