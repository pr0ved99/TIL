## T-BRIDGE-008A Duplicate-Seq Subvector

The user added a one-shot STM32 hook that emits this response for the first DISARM request and
returns to the normal response on retry:

```text
ACK,seq=S,seq=S,type=DISARM,t_ms=T
```

The first draft had a different identifier in the `#if` expression than in its `#define`. A clean
build still passed because the undefined preprocessor identifier evaluated to zero. Checking the
compiled object/ELF for the malformed ACK format string exposed the disabled branch. The identifier
was corrected before flashing; the string was then confirmed in both artifacts.

## Evidence Boundary

- The raw logs prove the observed UART order and telemetry values only.
- The logs do not independently record LiPo/MDD10A/motor-power separation or UART rewiring conditions.
- The logs do not contain a flash transcript or embedded binary identity, so exact ELF-to-board linkage remains pending.
- The controlled and safe flash console outputs were observed sequentially and both reported successful download verification, but the UART logs still do not embed the ELF hash.
- This result does not verify MDD10A power output, actual motor stop, reset-marked boot, Physical E-stop or electrical timing.
