# 2026-07-31 Progress

## Summary

- STM32 UART 입력을 엄격하게 검사하는 `uart_frame_parser`와 RX desynchronization 복구 경로를 board-only 환경에서 점검했다.
- 모터와 MDD10A motor power를 시험 범위에서 제외하고 ESP32-S3와 NUCLEO-F446RE UART link만 사용했다.
- 첫 실행은 STM32가 이전 세션의 `ARMED,last_seq=3` 상태를 유지해 scripted sequence의 선행조건을 만족하지 못했다.
- 이 실행에서 `CMD,seq=2`가 승인된 뒤 timeout-zero, range rejection과 final DISARM은 동작했지만 PING/PONG과 CMD-before-ARM 시험은 무효였다.
- STM32를 clean reset한 다음 실행에서는 `DISARMED,last_seq=0,err=0`에서 시작했고 NOT_ARMED, ARM, valid CMD, 약 300 ms timeout-zero, OUT_OF_RANGE와 final DISARM이 모두 예상대로 동작했다.
- ESP가 STM32보다 먼저 시작한 실행에서는 즉시 전송한 PING이 유실됐다.
- STM32를 먼저 준비한 뒤 ESP만 reset한 실행에서도 ESP reset 구간에 STM32 UART error가 `err=23`까지 증가했고, RX resynchronization이 첫 PING line을 discard boundary로 사용했다. 이후 모든 scripted frame은 정상 처리되고 final DISARMED가 유지됐다.
- 결과적으로 strict parser는 손상된 입력을 명령으로 실행하지 않고 fail-closed로 거부·복구했지만, ESP의 one-shot immediate PING startup 방식은 재시작 순서와 UART desync에 취약하다는 것을 확인했다.

## Decisions

- 이번 세 실행은 current strict parser의 fail-closed/recovery evidence로 보존한다.
- 현재 실행만으로 current firmware의 PING/PONG 회귀를 PASS로 판정하지 않는다.
- ESP startup은 장기적으로 `UART settle -> newline synchronization -> explicit DISARM -> ACK 확인 -> PING/retry -> PONG 확인` 순서의 session handshake로 변경한다.
- STM32 timeout은 현재 velocity/output zero만 수행하고 ARMED state는 유지한다. 따라서 ESP 재시작이 STM32 session reset을 의미한다고 가정하지 않는다.
- Sequence number는 현재 response correlation용이며 monotonic/replay protection을 제공하지 않는다.

## Limitations / Open Items

- 실제 PA9/PA10 raw byte와 reset 구간의 electrical waveform을 캡처하지 않아 `err=23`을 만든 개별 UART 오류 원인은 확정하지 않았다.
- TEL 100 ms telemetry로 확인한 timeout-zero는 실제 PWM shutdown latency 측정이 아니다.
- `UART_MVP_OUTPUT_TEST_ENABLED=0U`이므로 이번 로그는 실제 motor output 또는 motor stop 증거가 아니다.
- ESP source의 `BRIDGE_SCRIPTED_TEST_ENABLED`가 controlled bench를 위해 아직 `1U`다. 안전 기본값 복구 전 commit/일반 운용을 금지한다.
- Strict parser와 ring-buffer 변경은 아직 WIP이며 commit하지 않았다.

## Next Actions

1. ESP source의 `BRIDGE_SCRIPTED_TEST_ENABLED`를 `0U`로 복구하고 build/flash하여 자동 command가 없는 기본 boot 상태를 확인한다.
2. ESP startup session handshake를 작은 단계로 설계·구현한다: settle, newline sync, explicit DISARM/ACK, PING retry/PONG.
3. Motor-disconnected 상태에서 handshake와 전체 scripted sequence를 다시 실행해 current PING/PONG evidence를 확보한다.
4. Strict malformed-frame vector와 마지막 정상 PING을 실행해 reject/recovery를 검증한다.
5. Contract test, isolated STM32/ESP32 build와 board runtime evidence를 모두 통과한 뒤 문서화하고 commit한다.
