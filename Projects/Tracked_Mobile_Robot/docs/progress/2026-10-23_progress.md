## ESP–STM CAN 목표 구성 채택

사용자가 현실적 구성 제안을 채택했다. STM32는 센서6채널·기존 IMU/엔코더·구동/안전 판단, ESP32는 Wi-Fi–CAN 게이트웨이, CANable은 개발용 관측/시험을 맡는다. 별도 센서 MCU는 추가하지 않는다.

- 요구조건·전체 신호/전원 블록도·정식 CAN 계획에 반영했다. STM 측 보유 MCU-230과 ESP 측 별도 트랜시버는 공통 CAN 버스의 서로 다른 노드다. 실제 실장 위치·ESP GPIO·품번은 미정이다.
- 기존 UART 유지 → CAN 상태 송수신 → 명령/타임아웃/오류·복구 검증 → 제어 입력 전환 순서다. 기존 MVP 이후 후속 경계를 유지하며 UART/CAN 동시 제어를 자동 허용하지 않는다.

- 기존 제어/IMU 유지, 쉴드에는 ADC 입력6채널과 CAN 접속/종단/보호를 두는 구성이다. #5241 주전류 단자·모터 전력선과 NTC는 외부에 둔다. STM32가 수집·환산·유효성·CAN 처리를 맡으며 추가 MCU를 요구하지 않는다.
- 기존 핀 계약 대조: PC0~3/CN7-38·36·35·37, PA4/PB0/CN7-32·34, PA12/PA11/CN10-12·14 후보. PC0/PC1 bridge와 기존 IMU 예약 보존 조건을 유지했다. 전원/GND 접점, RS 추가 제어 필요성·실물 커넥터 순서는 미정이다.
- 3.3V는 NUCLEO 공급 후보로 표시했으며 부하 예산 미확정이다. K1 전단/후단 감지와 모터 주전류를 구분하고, STM OFF/감지선 ON·USB/buck 전환·CAN PC 접지/절연의 후속 검토를 명시했다. LiDAR 데이터는 모델 미정의 별도 상위 연결이다.
- 문서 연결과 인수인계를 갱신했다. 다음은 같은2단계의3.3V 부하/전원 순서·핀 충돌/접근·커넥터 계약 검토다. 회로/PCB/BOM·MCU 코드·빌드/플래시·실물 배선 변경과 Git/Calendar/Notion 추가 게시 없음.

## PCB CAN 환경과 전원 제작 조건 제안

요구사항1단계의 [CAN 환경·전원 이상·제작 조건](../../09_Electrical_Design/15_Expansion_PCB_Requirements_2026-10-23_ko.md#can-사용-환경-제안)을 추가해1차 검토본을 작성했다. 기존 CAN/전원 계약과 TI/ST 원문을 대조했다.

- 초기 환경 제안: STM32+보유 MCU-230 ↔ 노트북+보유 CANable, 두 노드·Classical500kbit/s·11bit ID·1m 이내 실내 버스. 모듈 내장 종단을 먼저 확인하고 양 끝120Ω 적용/해제를 식별한다. 실제 모듈·RS·절연·접지/PC USB 귀환 경로는 미정이다.
- 기존 XL4015/USB 전환과 레일 분리를 보존한다. 추가3.3V 부하는 예산 검토 후 공급 방식을 정한다. STM OFF/전압감지 ON과 센서 전원 순서 차이의 역급전·유효성, 단선/단락·외부 포트 보호를 요구사항에 포함했다. 보호 내성 수치는 회로 확정 전에 정한다.
- 2층 PCB·손납땜·보유 모듈 탈착·NUCLEO 상면 쉴드 우선 검토를 제안했다. 기존 IMU/배선/디버그 접근을 유지하고 외곽·높이·지지·실제 커넥터와 제작비/수량은 미정으로 관리한다.
- 다음은 요구조건 대조 후2단계 블록도·전원/핀/커넥터 계약이다. 회로/PCB/BOM·펌웨어 변경, 통전/시험, Git/Calendar/Notion 추가 게시 없음.1차 검토본은 전체 기능·보호·제작 확정이나 실측 완료가 아니다.

## PCB 요구사항 정의 시작

사용자가 기능·조건을 먼저 정하고 단계별로 설계하도록 요청했다. [요구사항 초안](../../09_Electrical_Design/15_Expansion_PCB_Requirements_2026-10-23_ko.md)에 보드 목적, 기존 확정 구성, 포함 기능 후보, 미정 성능과 후속 확인 방법을 저장했다. 전류는 기존 평균/추세 관측 목적을 계승하고 ADC6채널+CAN을 RevA 포함 후보로 관리한다. 기존 IMU 배치와 제어 기판을 보존한다.

- 현재는 1단계 초안 검토 중이다. 전류·온도·전압의 범위/허용 오차/갱신 주기, CAN 환경, 전원 이상 조건, 최종 기구/제작 사양은 미정이다. 기존 CAD·BOM·검사 결과는 변경하지 않았다.
- 다음은 사용 목적에 맞는 관측 성능과 RevA 기능 범위 검토다. 기존 부품값·외곽을 요구사항으로 확정하지 않는다. 이번 작업은 로컬 문서와 진행상황 갱신이며 Git/Calendar/Notion 추가 게시나 실물 시험은 수행하지 않았다.

## 확장 PCB 기능 범위 정정과 기존 IMU 유지

사용자가 전류·온도 외 CAN·향후 LiDAR 관련 기능도 대조하도록 요청했고, IMU는 기존 만능기판에 이미 자리를 배치했음을 재확인했다. 기존 핀 배정·CAN 계획·확장 배치 문서를 대조해 센서4채널만으로 범위를 좁힌 초기 안내를 정정했다.

- 전체 주요 검토 범위는 **전류2·온도2·K1 전단/후단 전압2의 ADC6채널 + CAN**이다. CAN·전압2채널은 현재 CAD에 없으며, 기존 KiCad 파일은 센서 부분 초안으로 표시했다.
- IMU 위치와 PB8/PB9·PB1/PC4, 기존 UART/엔코더/제어/SWD·측정 접근을 보존한다. 새 IMU 실장 자리·중복 커넥터를 기본 요구로 추가하지 않는다. 보유 MCU-230과 PC 측 CANable의 역할을 구분하고 중복 구매를 요구하지 않는다.
- 전원 부하 예산·디커플링/보호·역급전·시험점과 기구 접근을 전체 기능 기준으로 검토한다. LiDAR는 모델·전원/기동 전류·데이터 인터페이스·장착이 미정이므로 PCB 포함 여부와 추가 부품은 미확정으로 관리한다. 기존 별도 전력부와 PC5/PC6 선택 기능을 새 PCB 필수 실장으로 확대하지 않는다.
- [쉴드 README의 범위표](../../09_Electrical_Design/KiCAD/TMR_Monitor_Shield_RevA/README.md#전체-기능-범위-재대조--2026-10-23), 전기설계 색인과 현재/다음 인수인계를 갱신했다. 이번 변경은 문서 범위 정정이며 CAD·BOM·기존 검사 결과는 변경하지 않았다.
- 다음은 전체 핀·전원·커넥터 계약 → CAN·전압 회로 검토 → 전체 배치 산정이다. 기존 센서 부분 ERC/DRC 결과를 전체 확장 보드 완료로 해석하지 않는다. 저녁 이후 MVP 재개와 분리하며 Git/Calendar/Notion 추가 게시 없음.
