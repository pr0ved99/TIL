## 후속 T-ESTOP-005A 전압 관측 마감

목적은 제어 하네스를 제외한 조건의 MDD 입력 전압과 S2 재투입/S0 차단/해제·전원 재투입 후 상태를 관측하는 것이었다. 기존 보고서27·30 및 10/2 값은 해당 회차의 이력으로 유지한다. 이번에는 새 펌웨어 수정·빌드·플래시·명령 송신·모터 구동을 하지 않았다.

### 구성과 측정 근거

- 사용자 확인: 두 모터 전력선 4개 분리·각각 절연, MDD 제어 5핀 분리, **K1 87→MDD B+ 공급선 복원**. MDD B− 공통 GND는 유지하도록 안내했다.
- 두 보드 USB·LA USB와 XL4015 #1의 보드 전원용 두 2핀은 분리 상태로 진행했다. #2·엔코더·sense 배선 변경은 보고되지 않았다. MCU VDD를 별도 측정하지 않았으므로 보드의 완전 무급전을 실측한 것으로 쓰지 않는다.
- 계측 안내: DC 20V, 빨강 + / 검정 −. Bar는 Bar+↔Bar−, MDD는 **드라이버 본체 B+↔B−**다. 분리된 공급선 끝을 MDD 입력 측정값으로 쓰지 않았다.
- 근거는 대화의 사용자 수치·조작 완료 보고다. 화면 사진·연속 파형·동기화된 시각은 없으며 LA는 USB 분리 상태였다. 5초/30초는 수동 측정 안내 시점이다. 소수 자릿수는 보고값을 보존하며 `0.005V` 등의 표기가 계측기의 mV 분해능·정확도를 검증한 것은 아니다.

### 종료 상태와 다음 작업

사용자는 **S0 잠금→S1 OFF→LiPo 분리** 안내 뒤 “전원 분리 완료”를 보고했다. 두 보드 USB·LA USB도 분리 상태다. **MDD B+는 이번에 복원한 연결 상태**, B−는 공통 GND 유지이며, 모터 전력선 4개는 분리·절연, 제어 5핀과 보드 전원용 두 2핀은 분리 상태로 종료했다. 종료 뒤 잔류 전압을 추가 측정한 것은 아니다.

사용자는 확인 절차가 너무 빡빡하다고 지적했다. Codex가 준비·측정을 여러 대화로 과도하게 나누고 미결 판정 기준을 먼저 정리하지 않은 점을 인정했다. 이후에는 다음 원칙으로 진행한다.

- 이번 조건의 관측은 마감한다. 전압 소수점 감소를 계속 추적하거나 같은 조건의 시험을 자동 반복하지 않는다.
- 다음은 Codex의 자료 검토다. MVP에서 필요한 전압 판정 근거·단자 적합성 조치와 후속 정밀 진단을 구분하고, 추가 측정이 필요하면 어떤 미결 항목을 닫는지와 종료 조건을 먼저 정한다.
- 함께 수행할 수 있는 준비·측정은 한 조작 묶음으로 안내한다. 다음 조작이 앞선 결과에 달릴 때만 결과를 기다리고, 이미 확인된 상태는 반복 질문하지 않는다.
- `T-ESTOP-006` 정밀 파형/시간·ADC 진단과 `005B` 단일고장 확장은 기존 계획대로 post-MVP다. 전체 T005A 미결은 무전원 장착·설계·소프트웨어 작업을 일괄 중단할 이유가 아니다. 실제 구동 확대의 선행 조건은 별도로 유지한다.

### 제조사 자료 검토 후속

TE 공식 자료로 280756-4의 지정 범위 12–10 AWG와 현재 14 AWG의 압착 조합 편차를 재확인했다. 14 AWG를 포함하는 962835-3(17–13 AWG, 9.53×1.22mm)을 후보로 찾았으나 VCF7-1000 걸림·삽입 깊이, 실제 피복 외경, 공구와 전류 적합성은 미확정이다. 구매·재배선 승인이 아니다.

Cytron 공식 제품 페이지와 연결된 MDD10A V2.0 매뉴얼을 검토했다. 입력 범위 5–30V는 출력 차단·방전 수용 기준이 아니며, 검토 자료만으로 rail-off 수치 기준을 확정하지 못했다. 0.58V 관측에 임의 임계값을 적용하지 않고 T005A PARTIAL을 유지한다. 근거 URL과 잔여 대조 항목은 [부품 선정 문서](../../01_System_Architecture/26_Physical_EStop_Component_and_Rating_Selection_ko.md#2026-10-17-제조사-자료-재검토)에 기록했다. 추가 물리 조작·빌드·플래시는 수행하지 않았다. 당시 제시한 후속 도면 대조는 아래 사용자 결정으로 취소했다.

### 진행 범위 정정과 G4C 재개

사용자는 이미 넘어가기로 한 항목을 다시 꺼낸 점을 지적하고 재언급하지 말라고 명시했다. Codex가 미결 문구를 최신 사용자 결정보다 우선해 잘못 재개한 것을 인정했다. 인수인계·전체 계획·직전 검토 절에 이 결정을 반영했다. 과거 증거와 판정은 유지하며, 사용자 요청 없이 해당 조사를 재개하거나 진행 조건으로 걸지 않는다.

다음 작업으로 기존 계획의 G4C 무전원 플레이트 fit을 안내했다. 이후 사용자 보고 결과는 아래 완료 기록으로 갱신한다.

### G4C 장착 확인 묶음 완료

- 사용자 “가조립 맞음”: 섀시용 홀 정렬·자연스러운 체결·휨/프레임 간섭 확인 완료.
- 사용자 “모두 문제 없어”: 만능기판·XL4015 2개·MDD10A 고정과 휨, 스페이서 간격과 납땜부/도체 접촉 없음, STM/ESP USB 및 단자 공구 접근 공간 확인 완료.
- 사용자 가조립·육안 확인 범위로 [기존 검사표](../../02_Hardware_Validation/08_Adapter_Plate_Fit_Check.md)에 반영했다. 정밀 치수·재료/제작 revision 식별·절연저항 계측·전체 기구/통전 수용을 대신하지 않는다. 이미 완료한 장착 확인은 반복하지 않는다.
- 다음 P-05 준비를 위해 STM 실제 Core 저장본을 검색했다. `uart_mvp_protocol.c` TEL의 `batt_mv=0` 고정과 ADC 측정 경로 부재를 확인했다. 이를 근거로 즉시 ADC 회로/구현을 다음 작업으로 안내했으나, 아래 문서 대조로 정정했다. 이번에 firmware 수정·빌드·플래시는 하지 않았다.

### ADC/확장 PCB 일정 정정

사용자는 ADC 회로를 PCB 단계에서 구성하고 MVP 이후 진행하기로 한 기록을 지적했다. [10/1 계획](../plans/2026-10-01_Laptop_ESP_WiFi_PCB_and_Project_Review_Plan_ko.md#2-기존-부품을-유지하는-확장-pcb)은 PA4/PB0 보호·분압을 확장 PCB에 배정하고, [현재 핀 계약](../../01_System_Architecture/06_MCU_Pin_Allocation_Candidate_ko.md#battery-and-motor-rail-adc)은 두 채널을 post-MVP로 명시한다. 따라서 즉시 ADC 구현 안내는 취소하고 현재 인수인계를 정정했다.

별도로 전원 아키텍처 11절과 REQ-POWER-004에는 첫 주행 전 저전압 경고·정지 기준/입력 경로를 정한다는 요구가 있다. ADC/PCB 제작의 실행 시점과 이 요구를 구분하며, 문서 전체가 배터리 관련 항목을 모두 post-MVP로 넘긴 것으로 해석하지 않는다. 자리표시자 발견만으로 후속 회로 구현을 앞당기지 않는다.

### MVP 배터리 운영 방침 승인·다음 통합 범위

사용자는 “오케이 리포알람있고 계속 진행해보자”라고 답했다. 감독하의 짧은 MVP 주행에는 셀 알람과 경고 시 작업자의 즉시 수동 정지·시험 종료를 사용하고, ADC/자동 저전압 정지는 후속 PCB 단계로 두는 재판단을 승인했다. 매트릭스 REQ-POWER-004/T-PWR-004, 마스터 플랜과 전원/핀 아키텍처·인수인계에 반영했다. 알람 보유 확인은 설정·정상 동작·회차 적용 PASS를 의미하지 않는다. 별도 과방전 유발 시험을 추가하지 않는다.

다음 Wi-Fi nonzero 통합을 위해 실제 contract/state/executor/PAGE를 대조했다. 기존 숫자 범위는 정의돼 있지만 허용 검사와 FSM은 nonzero를 거부하며 UART/PAGE 명령값도 zero 고정이다. [실행 범위](../plans/2026-10-17_WiFi_Nonzero_Control_Integration_Plan_ko.md)에 zero 준비→ACTIVE→현재 입력→정지 흐름, 변경 지점과 PC/모터 동력 차단/실모터의 검증 순서를 기록했다. firmware 수정·빌드·플래시·실물 전원 조작은 아직 하지 않았다.

### core 플래시 사용자 보고·PAGE 방향 입력 후보

사용자는 core 변경 후 “플래시까지 완료”라고 보고했다. ESP 빌드·플래시 사용자 확인으로 기록하며 원본 빌드 로그/바이너리 readback·새 보드 UART/PWM 검증으로 확대하지 않는다. 플래시 이후 USB/전원 상세 상태는 미보고다.

ESP의 zero_only JSON을 실제 설정에서 생성한다. 기본 header mode1은 유지하며 실제 main은 편집하지 않았다. [입력 가이드](../plans/2026-10-17_WiFi_Nonzero_PAGE_Code_Guide_ko.md)에 정확한 두 교체 범위와 함수별 변경 전후를 기록했다.

### PAGE mode1 화면 사용자 확인 완료

사용자는 ESP 빌드·플래시/강력 새로고침 후 `속도 0 전용` 및 방향 버튼4개 표시·비활성 확인 안내에 “확인 완료”라고 보고했다. 해당 화면 확인 범위의 사용자 보고이며 새 UART/PWM·실모터 검증으로 확대하지 않는다. 소스 hash는 직전 저장본 PC PASS와 같고 ZERO_ONLY=1U/시험 mode0이다. 동일 검사를 반복 실행하지 않았다.

다음은 사용자가 contract.h의 ZERO_ONLY를0U로 저장하는 단계다. ACTIVE의 nonzero 허용과 모드 표시를 켜되 ARM/첫 zero ACK/TEL 조건은 유지된다. 실제 저장본 검토/PC 검사 뒤 사용자 빌드·플래시로 진행한다. 이 기록 시점에는 설정을 바꾸지 않았다.

### USB-only FAULT 설명·mode0 저장본 PC 검사

사용자는 화면의 fresh STM TEL `FAULT / ESTOP_ACTIVE`가 STM RESET/DISARM 후에도 유지된다고 보고했고, STM·ESP USB 연결/LiPo 분리 상태를 확인했다. 기록된 #2 AUX_5V·옵토커플러 감지 경로와 PC7 pull-up/HIGH=active 코드를 대조했다. 이 전원 구성에서 예상되는 표시이며 PC7 실측이나 새로운 배선 고장 판정은 아니다. RESET은 입력을 즉시 재검사하고 DISARM은 E-stop 래치를 해제하지 않는다고 설명했다.

이후 actual contract.h의 `WIFI_CONTROL_ZERO_ONLY=0U` 저장을 확인했다. 이전 mode1 저장본 검증 hash와 비교해 firmware 변경은1U→0U 한 줄뿐이며 UART 시험 mode0 유지다. Codex는 firmware를 편집하지 않았다.

검사 도구 두 개를 입력 mode0/1 모두 지원하도록 조정했다. 현재 설정의 복사본은 byte 단위로 그대로 검사하고, 기존 zero-only 회귀는 임시mode1에서 수행한다. 현재mode0 core13개·adapter6개, mode1 회귀59+3+42+6개, 브라우저66개, PAGE C 초기화 PASS. negative control3개 검출 PASS. [core](../../assets/logs/wifi_link/2026-10-17_nonzero_mode0_saved_review/core_validation.json)·[main/PAGE](../../assets/logs/wifi_link/2026-10-17_nonzero_mode0_saved_review/main_validation.json)에 입력 hash/모드/검사 범위와 로그를 보존했다.

다음은 사용자 ESP 빌드·플래시와 강력 새로고침 후 `IDLE · 방향 입력 모드` 확인이다. USB-only/LiPo 분리를 유지하므로 FAULT 및 ARM/방향 비활성은 예상된다. mode0의 실제 플래시·UART/PWM·모터 동작은 아직 확인하지 않았다.
