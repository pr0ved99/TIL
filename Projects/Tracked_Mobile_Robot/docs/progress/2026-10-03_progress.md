## 예제 검토 결과와 근거

- 사용자가 별도 IDE와 만든 예제를 가져와 실제 저장 파일을 검토했다. 제작 과정을 추정하지 않고 저장본 검토와 설정 확인 결과를 남긴다.
- [예제 README](../../03_Firmware/esp32_examples/README.md)는 5단계 학습 순서를 제시한다. 실제 코드와 CMake가 있는 것은 `01_hello_world`뿐이며 02~05의 `main` 폴더는 비어 있다.
- [01 소스](../../03_Firmware/esp32_examples/01_hello_world/main/hello_world_main.c)는 로그 3종을 출력한 뒤 카운터를 증가시키고 `vTaskDelay(pdMS_TO_TICKS(1000))`로 대기한다. `ESP_LOGE` 호출 자체가 실행을 중단시키지는 않는다.
- 로컬 SDK의 `components/freertos/app_startup.c`에서 main 태스크가 `app_main()`을 호출하는 구조를 확인했다. ESP의 `app_main()`은 FreeRTOS 태스크 안에서 실행되며 STM의 bare-metal `main()`과 실행 환경이 다르다.
- 예제 `sdkconfig`의 대상은 `esp32s3`; UART 기본 콘솔과 USB Serial/JTAG 보조 콘솔이 활성화되어 있다. `sdkconfig.defaults`는 없어 설정 재현 방법을 별도로 남겨야 한다.
- 최초 검토 당시 예제 `build` 용량은 약 139.9MiB이고 Git 미추적 후보에 빌드 파일 344개가 포함돼 있었다. 커밋된 파일이라는 뜻은 아니다. 예제용 `.gitignore`와 필요한 재현 설정이 보완 대상이다.
- 후속 예제 README에는 01 빌드 성공이 기록돼 있다. 이 대화에서는 빌드·플래시를 실행하지 않았고 보드 실행 로그도 확인하지 않았다. 코드 검토·빌드 기록·실제 실행을 구분한다.

## 현재 Wi-Fi 앱 상태

- `esp32_wifi_link/main/wifi_link_main.c` 저장본은 HTTP 폴링 방식이다. WebSocket 전체 코드 입력·실행 완료로 기록하지 않는다.
- 사용자가 `CONFIG_HTTPD_WS_SUPPORT=y`를 확인했고 실제 `sdkconfig`와 `sdkconfig.defaults`에서도 재확인했다. 서버 지원 설정과 WebSocket 앱 구현·검증은 별개다.
- `main/CMakeLists.txt`에는 Wi-Fi·HTTP 서버·타이머·NVS·FreeRTOS 의존성이 선언돼 있다.
- 페이지는 `/api/status`를 HTTP로 조회한다. 요청 제한 시간은 2초, 요청 종료 후 다음 조회까지의 대기는 1초다. 현재 앱 소스에 WebSocket 함수는 없다.
- 전체 WebSocket 코드·설정과 시험 기준은 [10/2 입력 안내](../plans/2026-10-02_ESP_Standalone_WebSocket_Code_Guide_ko.md)에 있다. 안내 코드의 브라우저 모의 검사 11개 PASS는 이전 준비 단계의 결과이며 실제 ESP 동작 증거를 대신하지 않는다.
- 예제 01은 로그·반복·대기 학습 단계이며 Wi-Fi 연결 기능을 포함하지 않는다. 02~05와 WebSocket 안내의 함수들은 이후 학습 대상이다.
- 기존 AP 실측과 STA 연결 보고는 [10/1 기록](2026-10-01_progress.md#wi-fi-ap-실측--w1w2w3-결과), [10/2 기록](2026-10-02_progress.md#공유기-sta-연결-확인)을 따른다. STA 재접속·WebSocket·STM 통합·무선 명령은 미검증이다.

## 문서 최신화

- 진행 색인과 현재 인수인계에 설정 확인·예제 검토 범위와 재개 위치를 반영했다.
- 새 대화 시작 프롬프트의 AP 전용 안내를 수정하고 AP 실측과 STA 연결 보고·미검증 항목을 구분했다.
- Wi-Fi 앱 README에는 WebSocket 지원 설정 완료와 앱 소스 미반영을 구분해 적었다.
- 예제 README의 기존 빌드 성공 기록과 이해도 질문을 보존하고 프로젝트 선택·실행 방법과 남은 보완을 추가했다.
- 기능 코드·배선 변경 없이 문서를 정리했다.

## 다음 행동

1. 예제 저장 구성을 보완한다 — 생성 파일 Git 제외와 `sdkconfig.defaults` 등 대상·콘솔 설정 재현을 정리한다.
2. 01을 설명하고 실행 결과를 확인한다 — 로그 수준, TAG, 카운터 증가, 반복과 태스크 대기를 이해하고 사용자 모니터 로그로 카운트 증가·재부팅 후 초기화를 확인한다.
3. 02에서 별도 태스크 생성과 실행 순서를 익힌 뒤 STA 이벤트로 진행한다. 학습 대상 펌웨어 입력과 빌드·플래시는 기존 사용자 진행 방식을 따른다.
