## 저장본 검토와 설명 기준

- [02 소스](../../03_Firmware/esp32_examples/02_freertos_task/main/freertos_task_main.c): fast는 증가·출력 뒤 100ms 대기, slow는 증가·출력 뒤 2000ms 대기. main은 5000ms 대기 뒤 읽기·heartbeat 출력만 수행한다.
- `s_shared_counter`는 정적 저장 기간의 공유 변수로 0에서 시작한다. 각 태스크의 `config`와 `value`는 지역 변수이며, 설정 인자는 전역 `static const` 객체의 주소다.
- 세 접근 경로 모두 같은 Mutex를 사용한다. 증가와 지역 변수 복사 후 Mutex를 해제하므로 로그 순서가 카운터 증가 순서와 항상 같다고 단정하지 않는다.
- `sdkconfig`의 대상은 `esp32s3`, `CONFIG_FREERTOS_HZ=100`. 로컬 SDK에서 `xTaskCreate` 스택 크기 단위가 바이트이고, main 태스크가 `app_main()`을 호출하는 구조를 확인했다.
- `vTaskDelay`는 호출 태스크를 대기 상태로 만든다. 정확한 고정 주기를 보장하는 코드가 아니며 처리 시간과 스케줄링 영향을 받는다.
- 주석 54행의 다른 태스크 기아 단정은 보완이 필요하다. 같은 우선순위의 시간 분할과 낮은 우선순위 태스크·idle 실행 지연을 구분한다. 실험 주석 93행의 100ms는 이미 현재 설정값이다.
- Mutex 생성 실패 시 태스크를 만들지 않고 반환한다. 태스크 일부 생성 뒤 실패할 경우 이미 생성된 태스크를 정리하는 코드는 없다.
