## Today Work Log

오늘 작업은 2026-07-14에 완료한 ESP32 `TEL/PONG` frame 분류 단계에서 이어서, STM32 telemetry의 세부 field를 ESP32 상태로 구조화하는 실습이었다.

1. 기존 parser 흐름 확인
   - `parse_u32_field()`가 전체 line에서 key 위치를 찾고 `strtoul()`로 unsigned 값을 변환하는 흐름을 확인했다.
   - 기존 `TEL` 처리는 `t_ms`만 저장하고 있었으며 `state`, `last_seq`, velocity, error field는 raw frame 안에만 남아 있었다.

2. signed integer parser 추가
   - `parse_i32_field()`를 추가했다.
   - `strtol()`을 사용해 양수와 음수를 모두 처리하도록 했다.
   - 향후 `vx_mmps`와 `w_mradps`가 음수인 후진 또는 회전 command도 저장할 수 있도록 했다.

3. string field parser 추가
   - `parse_string_field()`를 추가했다.
   - key 뒤에서 다음 쉼표 또는 문자열 끝까지의 값을 복사하도록 구현했다.
   - destination buffer 크기를 확인하고 마지막에 null terminator를 추가하도록 했다.
   - 이 parser를 통해 `state=ARMED` 또는 `state=DISARMED` 값을 별도 문자열로 저장할 수 있게 했다.

4. structured telemetry 상태 정의
   - `bridge_telemetry_t` 구조체를 추가했다.
   - 구조체에 `t_ms`, `state`, `last_seq`, `vx_mmps`, `w_mradps`, `err`, `valid`를 포함했다.
   - 실제 최신 telemetry를 보관하는 전역 상태로 `s_telemetry`를 추가했다.

5. `TEL` frame 전체 field parsing 적용
   - 수신한 `TEL` line을 먼저 임시 `parsed` 구조체에 저장하도록 했다.
   - 여섯 개 핵심 field가 모두 성공한 경우에만 `s_telemetry`를 갱신하도록 했다.
   - 일부 field만 파싱된 불완전한 상태가 마지막 정상 telemetry를 덮어쓰지 않도록 했다.
   - 정상 수신 시 구조화된 값과 `tel_count`를 한 줄 summary로 출력하도록 변경했다.

6. 오타 수정과 source 확인

## Decisions

- ESP32 structured telemetry는 `bridge_telemetry_t` 한 개에 최신 정상 값을 저장한다.
- 모든 필수 field가 성공한 경우에만 `s_telemetry`를 갱신한다.
- ESP32는 telemetry를 구조화하고 relay하지만 safety 판단, timeout, final motor output 권한은 계속 STM32가 소유한다.
- detailed `TEL` parser는 2026-07-18 실기 evidence를 기준으로 PASS 처리한다.
- `T-BRIDGE-004`는 `DISARMED` structured telemetry까지만 확인했으므로 `ARMED`, valid `CMD`, timeout 항목이 끝날 때까지 PARTIAL PASS를 유지한다.
- 다음 firmware 단계는 scripted `PING -> CMD before ARM -> ARM -> valid CMD -> invalid CMD -> DISARM` sequence다.
- 실습 중 후보 A는 기존 XL4015 #2, 후보 B는 기존 XL4015 #1로 고정한다.
- XL4015 단자 전압과 USB-side 전압은 배선·단자 전압 강하를 구분하기 위해 별도 기록한다.

## Blockers / Open Items

- 현재 ESP32 firmware는 주기적 `PING`만 송신하며 일반 command frame 송신 helper가 아직 없다.
- ESP32에서 `CMD before ARM`, `ARM`, valid `CMD`, invalid range `CMD`, `DISARM`을 순서대로 전송하는 state machine은 아직 구현하지 않았다.
- `ARMED` telemetry와 valid command 값 반영은 아직 ESP32 command source 경로에서 확인하지 않았다.
- valid `CMD` 이후 command 송신을 중단했을 때 STM32 timeout-zero telemetry가 나타나는지 아직 확인하지 않았다.
- signed parser는 구현됐지만 실제 음수 velocity가 포함된 `TEL` frame은 아직 관찰하지 않았다.
- 일반 PowerShell의 ESP-IDF dependency 환경은 활성화 상태가 불완전하므로 현재 검증된 VS Code ESP-IDF extension build 경로를 유지한다.
- XL4015 #1의 nominal 2 A 시험에서 전자부하 발생기 발열이 관찰됐으며, XL4015 자체 온도는 별도 계측하지 않았다.
- 고부하 USB 경로는 전압 강하가 크므로 실제 board power path로 승인하지 않았다.
