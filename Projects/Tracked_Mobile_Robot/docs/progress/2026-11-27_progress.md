# 11월 26일~27일 새벽 · 집 ADC 벤치 마감

두 채널에서 타이머·DMA와 오류 처리를 확인한 뒤 외부 입력 6개와 내부 기준전압을 한 스캔으로 확장했다. 여섯 핀 모두 1.797 V 분압과 UART 필드가 대응했다. PC2만 바꾼 A/B 시험에서 다음 채널 PC3의 평균 변화는 −0.114 mV였다. E07/M01은 부분 검증 상태다. [시험 결과와 원본](../verification/50_ADC_DMA_7_Channel_Bench_2026-11-27_ko.md)

**종료 상태.** CubeIDE Terminate 후 NUCLEO USB 분리를 사용자가 확인했다. ESP32는 만능기판에서 분리해 두었다. 로봇 배터리와 외부 전원 두 2핀은 이 시험에 사용하지 않았다. 마지막 배선 B에서 PA4·PB0·PC0·PC1은 공통 GND이고, PC2·PC3는 3V3 → 9.95 kΩ → 분압점 → 12 kΩ → GND의 같은 분압점이다.

## 11월 27일 기상 후 집에서 할 일

| 순서 | 할 일과 확인 기준 | 이 순서로 하는 이유 |
|---|---|---|
| 1 | 전원이 분리된 상태에서 B 배선을 눈으로 대조한다. 그대로면 NUCLEO ST-LINK USB만 연결한다. 기존 벤치 이미지를 실행해 USART2 원문을 처음부터 저장한다. 보드 시각 기준 60초 이상, 즉 100 ms 간격 유효 블록 최소 601개에서 순번 +1, 필드 7개와 시각 +100 ms를 확인한다. | 핀 대응은 끝났다. 지금까지 A·B는 각각 30블록이어서 수십 초 동안의 누락이나 간헐 오류는 판단하기 어렵다. 배선을 유지하면 측정 시간이 바뀐 영향만 볼 수 있다. |
| 2 | 1번 통과 뒤 같은 7채널 이미지에서 TIM2 트리거만 중단하고 CPU와 시스템 틱은 실행한다. 마지막 정상 블록 뒤 펌웨어의 300 ms 기준에서 `valid=0,reason=block_timeout`을 한 번 출력하고 정상 블록이 멎는지 본다. 보드를 재시작해 정상 7필드와 100 ms 주기의 복귀를 별도 원본으로 남긴다. | 이전 오류 주입은 두 채널 구성에서 했다. 채널 수와 버퍼 길이를 바꾼 뒤에도 오래된 값이 정상으로 출력되지 않는지 확인해야 한다. 오류 뒤에는 펌웨어가 정지하므로 재시작을 따로 관찰한다. |
| 3 | 정상·중단·재시작 근거를 확보하면 M02 온도 평균의 입력 조건을 정한다. 연속 유효 블록 10개(1초)가 모이면 첫 평균을 내고, 시작 직후와 누락 직후에는 새 창이 찰 때까지 기다리는 안을 검토한다. | 끊어진 100 ms 블록이 섞이면 실제 1초를 대표하지 않는 온도값이 만들어질 수 있다. |

장시간 캡처에서 순번 공백이 보이면 그 원본과 보드 시각을 보존하고 UART 재연결·PC 수신 중단과 펌웨어의 블록 오류를 구분한다. 이 경우 1번부터 원인을 좁힌다. 실제 배터리·모터·센서를 연결하는 시험은 별도다. 노트북만 사용하는 환경에서는 ELEC-01 보호 저항·분기 퓨즈·환산 오차 검토를 이어간다.

## 문서·파생 자료 대조

펌웨어와 CubeMX 설정, 핀·rank 표, UART 원본 두 폴더, 프로젝트 README, 현재 상태·계획·인수인계의 다음 작업을 대조했다. 11/25의 두 채널 폴링을 현재 상태로 안내하던 문구를 갱신했다. 기존 PA4 그래프는 당시 2,218쌍을 나타내므로 그 시험에 연결해 유지했다. 이번 분압 점퍼 시험은 회로도 변경을 포함하지 않았다. 기본 경로의 회로도·PCB·PDF·기존 검사 출력 등을 시작 커밋과 비교했고, Monitor Shield의 KiCad 프로젝트 설정에 이미 있던 작업 사본 차이는 이번 게시에서 제외했다. 이번 마감에서 ERC·DRC와 MCU 빌드·플래시는 다시 수행하지 않았다.
