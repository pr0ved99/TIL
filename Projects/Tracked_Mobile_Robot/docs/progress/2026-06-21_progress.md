## Decisions

- Active motor-driver path: MDD10A dual-channel PWM+DIR driver.
- BTS7960 status: superseded alternative, useful as design-evolution evidence.
- Active firmware output model: `left_pwm`, `left_dir`, `right_pwm`, `right_dir`.
- Active safety rule: ramp PWM to zero before changing DIR.
- Learning notes are not canonical architecture decisions; they become canonical only after being reflected in architecture docs or project memory.
- PC dashboard work should start with fake telemetry parsing before real UART serial control.
- WebSocket/frontend and AI diagnosis are deferred optional extensions.
- AI cannot be the primary emergency-stop or motor safety authority.
- PC and ESP32 use the same UART application frames in the first MVP.
- UART command acceptance uses `ACK`; rejection and parse failure use `ERR`; a separate `NACK` frame is not used.
- UART timeout immediately drives output zero while staying armed first; the later auto-disarm delay still needs confirmation.
- The PC-first UART MVP should use ST-LINK Virtual COM Port / USART2 before wiring ESP32.
- The PC tool records both raw UART logs and parsed CSV logs under `04_PC_Serial_Control/logs`.
- PowerShell dry-run validation passed for frame build and scripted-test generation.
- Web Serial dashboard was served locally through `ServeWebDashboard.ps1` and returned HTTP 200 on `http://localhost:8765/`.
- Ubuntu Bash tool dry-run and syntax validation should be run on a real Ubuntu environment before real `/dev/ttyACM0` validation.
- Web UI uses browser Web Serial API from localhost. WebSocket backend remains optional and is not required for the first web dashboard.
- `05_UART_MVP_Runbook_ko.md` is the primary execution guide.

## Blockers

- Python unit tests could not be run in this local environment because no Python launcher is installed.
