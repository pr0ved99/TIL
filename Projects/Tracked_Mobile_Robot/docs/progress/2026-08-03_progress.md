## Strict-Parser Normal-Sequence Regression

MDD10A/Battery power OFF에서 ESP32 scripted harness를 임시 활성화해 다음 순서를 실행했다.

| Step | Observed response/state | Result |
| --- | --- | --- |
| `PING,seq=1` | `PONG,seq=1`, next TEL `last_seq=1`, `err=0` | PASS |
| `CMD,seq=2` before ARM | `ERR ... NOT_ARMED` | PASS |
| `ARM,seq=3` | ACK, next TEL `ARMED` | PASS |
| valid `CMD,seq=4,vx=50,timeout=300` | ACK, TEL `vx=50`, then first post-timeout sample `vx=0` | PASS |
| invalid `CMD,seq=5,vx=9999` | `ERR ... OUT_OF_RANGE`, accepted `last_seq=4` retained | PASS |
| `DISARM,seq=6` | ACK, final TEL `DISARMED`, velocity zero | PASS |

No `RX_DESYNC`, `RX UNKNOWN` or line overflow appeared in this normal-sequence run. Final `err=2` is expected from the two intentionally rejected commands. This closes the controlled normal-sequence subtest only. Fixed delays and a one-shot PING do not replace a response-gated startup handshake, and malformed-frame recovery injection remains open.

## Decisions

- Exact PWM frequency/duty and DIR transition settle subtests are closed as PASS.
- Current strict-parser normal PING/safety sequence is PASS under the controlled startup preamble; the release-level startup handshake and malformed recovery remain PARTIAL.
- The boot capture is evidence of a sampled all-inactive interval, but it does not contain an external reset marker. It is not treated as independent proof of the complete reset-to-boot window.
- The B1 six-step behavior is a temporary controlled-bench hook, not production behavior.
- A logic analyzer capture proves STM32 pin behavior only. It does not prove MDD10A power output, motor stop, current behavior, or physical E-stop operation.
- RX desynchronization currently rejects contaminated frames and recovers at the next line boundary. Immediate motor stop on desynchronization is not implemented; command timeout remains the fallback and this policy requires a later safety decision.

## Remaining Gates

- Active-output `DISARM`, command timeout and injected software-fault shutdown latency must be measured with trigger-to-PWM-inactive evidence.
- STM32 safe image was reflashed/run and no motor-control signal activity was observed, but the capture has no external reset marker and therefore does not close the final boot-window gate.
- Physical E-stop and real lifted/no-load motor-stop behavior remain unverified.
- UART startup still needs response-gated explicit DISARM/ACK, bounded PING retry/PONG verification and malformed-frame recovery injection.
- ESP source is restored to `BRIDGE_SCRIPTED_TEST_ENABLED=0U`, but the board's last flashed image was the controlled `1U` test image; keep it unpowered until the next build/flash.

## Next Actions

1. With MDD10A/Battery power OFF, implement the response-gated startup state machine: settle -> newline sync -> explicit DISARM/ACK retry -> PING/PONG retry -> READY.
2. Re-run the normal sequence only after READY, then inject malformed PING/CMD/unknown frames and prove fail-closed recovery with a final valid PING/PONG.
3. Restore the ESP test macro to `0U`, rerun contract tests and clean builds, then reflash/run the safe ESP32 image.
4. With the motor disconnected and output limited to 10%, measure shutdown latency in this order: active `DISARM` -> command timeout -> injected software fault.
5. After the latency builds, restore all STM32 hooks to `0U`, rerun tests/build, reflash/run the safe STM32 image, and capture reset-marked PB6/PC8/PB7/PC9 all-inactive boot regression evidence.
6. Close the board power/back-power prerequisites, then complete Physical E-stop `T-ESTOP-001~006` continuity, sense, latch/reset-reject, no-auto-restart and motor-disconnected timing tests.
7. After those safety gates pass, run the lifted/no-load motor test and powered encoder-noise check.
