## Decisions

- Exact PWM frequency/duty and DIR transition settle subtests are closed as PASS.
- The boot capture is evidence of a sampled all-inactive interval, but it does not contain an external reset marker. It is not treated as independent proof of the complete reset-to-boot window.
- The B1 six-step behavior is a temporary controlled-bench hook, not production behavior.
- A logic analyzer capture proves STM32 pin behavior only. It does not prove MDD10A power output, motor stop, current behavior, or physical E-stop operation.
- RX desynchronization currently rejects contaminated frames and recovers at the next line boundary. Immediate motor stop on desynchronization is not implemented; command timeout remains the fallback and this policy requires a later safety decision.

## Remaining Gates

- Active-output `DISARM`, command timeout and injected software-fault shutdown latency must be measured with trigger-to-PWM-inactive evidence.
- The current safe build has not yet been flashed and run after the temporary six-step capture. The board may still contain the temporary test image.
- Physical E-stop and real lifted/no-load motor-stop behavior remain unverified.
- UART startup handshake still needs settle, newline synchronization, explicit DISARM/ACK and PING retry/PONG verification.

## Next Actions

1. Before applying MDD10A or motor power, flash/run the current STM32 source with all test hooks `0U`; this is a protective baseline restore because the board may still contain the temporary B1 six-step image.
2. With the motor disconnected and output limited to 10%, measure shutdown latency in this order: active `DISARM` -> command timeout -> injected software fault.
3. After the controlled latency builds finish, restore all four STM32/ESP32 test-hook macros to `0U`, rerun contract tests and clean builds, reflash both safe images, and capture reset-marked PB6/PC8/PB7/PC9 all-inactive boot regression evidence.
4. Close the board power/back-power prerequisites, then complete Physical E-stop `T-ESTOP-001~006` continuity, sense, latch/reset-reject, no-auto-restart and motor-disconnected timing tests.
5. After those safety gates pass, run the lifted/no-load motor test and powered encoder-noise check.
6. Harden and reverify the ESP32↔STM32 startup session handshake separately from the motor-output gate.
