## 코드와 검사

- 현재 ESP는 **M2 역방향 시험 이미지**: M2_PULSE → CMD(-50,-250,300), hook=1U.
  기존 자동 hook 네 개는0U. 시험 종료 후 BENCH_FINISHED이며 다음 시도는 ESP 재부팅이 필요하다.
- STM 오른쪽DIR는 forward=SET/reverse=RESET. 왼쪽은 기존 forward=RESET/reverse=SET.
  엔코더 부호·1560 counts/rev는 유지했다.
- Codex가 DIR 검사 기대값을 수정했다. 마지막 정적 검사31개 중30개 PASS,
  모든 시험hook=0을 요구하는1개 FAIL. 현재 이미지는 default-off 복구 완료 상태가 아니다.
- 공백 검사 PASS. 빌드·플래시는 사용자가 수행했고, Codex는 실행하지 않았다.
- 문서 마감 검증: 변경·추가 Markdown20개의 로컬 링크638개와 코드 펜스를 확인했다.

- [프로젝트 README](../../README.md)의 기존 개요·역할·사진·설계 판단·대표 사례·문서 안내 구조를 유지하며 현재 판정을 정리했다.
- 대표 성과 5개를 결과·검증 범위·원본 보고서 링크 표로 먼저 제시하고, 기존 문제·방법·측정값·한계는 펼쳐 읽도록 보존했다.
  23.50 μs는 MCU 로직 핀 차단 시간, 엔코더 1,560 counts/rev는 손회전 보정, B 양방향은 섀시 분리 단발 시험이라는 범위를 유지했다.
- 실제 모터 사례에는 보정 전 양수 명령/역회전/음수 CPS와 교차시험, 엔코더 부호를 유지한 오른쪽 DIR 보정의 연결을 보강했다.
- 현재 상태 표에 보드 전원 공급 검증을 추가하고, A 실제 전진 방향·active DISARM·전류/열/노이즈·전체 T005A·S0 정지·기구/주행의 남은 범위를 구분했다.
  #1/#2 보드·감지 전원, T004와 T005A, 실제 엔코더 자료의 근거 링크를 추가했다.
- 시스템 도식은 신호/피드백과 전력/모터 구동 경로를 구분하고, 전력단이 이미 연결·관측됐으나 전체 수용은 미완료임을 표시했다.
  기존 8/14 사진과 촬영 시점·검증 범위 설명은 유지했다.
- STM32CubeIDE 프로젝트·ESP-IDF 빌드 문서·Python 검사 실행 방법을 연결했다.
  ESP 파일명 변경 후 보드 빌드 미확인, 현재 시험 설정과 검사 상태는 기존 인수인계·검사 문서에서 추적한다.
- 후속 FreeRTOS 항목은 STM32 전환으로 명확히 해 ESP-IDF의 기존 FreeRTOS 환경과 구분했다.
- 검증: 기존 링크·사진과 대표 측정값 보존, 수정 문서의 로컬 링크·앵커·표·코드 펜스·접기 구조·공백 확인.
