# W5 두 보드 USB 환경의 무선 PING/DISARM 계획

작성: **2026-10-08**. 사용자 선택: 다음 작업은 STM·ESP 두 보드를 가져가는 조건으로 계획한다.
본문은 **10/8 작성 당시의 계획**이다. 당시 W4의 마지막 실측은 만능기판 장착·각 USB·LiPo 미연결 조건이었다. 후속 수행 결과는 아래 마감과 보고서34를 따른다.

## 2026-10-10 마감 — 수행 결과

**W5 비구동 PING/DISARM 범위 완료.** 정상 왕복·입력 거부·timeout/복구·요청자별 결과·버튼·재접속 후 자동 재전송 없음을 확인했다. [보고서34](../verification/34_W5_PING_DISARM_WebSocket_and_Response_Matching_2026-10-10_ko.md)에 W5-01~24 관측과 한계를 구분했다.
실제 PAGE JS57·실제 C 함수 PC21 PASS이며 물리 UART 주입/동시 태스크 경합/구동 안전 증거가 아니다. **두 USB 분리 완료 사용자 확인**. WS 상태는100ms로 변경했고128byte·요청 간격/응답500ms·동시1개·자동 retry 없음 계약을 적용했다.
다음은 ARM/CMD 세션·freshness·명령 유효시간·재허가 계약 설계이며 실제 구동은 별도 Gate다. 아래 ‘현재/제안/다음’은 계획 작성 당시 표현으로 보존한다.

## 목표와 첫 세션 종료선

브라우저에서 명령을 보내고 실제 STM의 응답이 같은 요청의 결과로 돌아오는 경로를 만든다.

```text
브라우저 PING/DISARM → WebSocket TEXT → ESP 입력 검사
→ UART 담당 태스크 → STM 명령 처리 → PONG/ACK
→ ESP 응답 matching → 요청한 브라우저의 결과 표시
```

첫 세션 목표는 **PING 왕복**이다. 이후 DISARM·무효 입력·timeout·재접속을 순서대로 검증한다.
ARM/CMD·ESTOP_RESET·모터 전원·배터리 ADC·주행은 이번 범위에 넣지 않는다.
PING 응답은 명령 왕복 증거이며 구동 허가가 아니다. DISARM ACK도 물리적 모터 정지 측정을 대신하지 않는다.

## 준비물과 연결

- 노트북, NUCLEO-F446RE, 현재 ESP32-S3, 각각에 맞는 USB 케이블2개.
- 실제 보드 헤더에 맞는 점퍼선3가닥. 보드 탈거·배선 변경은 전원이 없는 상태에서 사용자가 수행한다.
- 신호: ESP GPIO17 TX→STM PA10 RX, STM PA9 TX→ESP GPIO18 RX, GND↔GND. 115200/8N1.
- 각 보드는 USB로 공급한다. 보드 사이 5V/3.3V 전원 핀은 연결하지 않는다. LiPo·MDD10A·모터는 사용하지 않는다.
- 기존 STA 공유기를 사용할 수 있으면 유지한다. 이동 장소에서 사용할 수 없으면 현재 Wi-Fi 앱의 AP 설정으로 접속 경로를 준비한다. DHCP 주소·COM 번호는 그날 실제 로그로 확인한다.

STM의 현재 PA10 내부 pull-up과 시험 hook0U를 유지한다. 안전 입력 회로가 없는 낱개 보드에서
FAULT/ESTOP_ACTIVE 등 상태가 달라질 수 있으므로 실제 TEL을 확인한다. 시험을 위해 안전 입력을 우회하거나 ARM하지 않는다.

## 실제 소스에서 바꿔야 할 경계

- ESP `ws_receive()`는 현재 WebSocket 제어 PONG만 받는다. 애플리케이션 PING/DISARM은 TEXT 데이터로 별도 구현한다. WebSocket 프로토콜 PING과 STM ASCII PING을 구분한다.
- `stm_startup_handle_response()`는 현재 모든 ACK/PONG을 부팅 응답 경로에서 소비한다. 부팅 요청과 사용자 요청의 응답을 구분해 전달하는 구조가 필요하다.
- `stm_uart_rx_task()`가 현재 부팅 순서와 UART 수신을 소유한다. HTTP 핸들러는 제한된 요청만 전달하고, 같은 UART 담당 태스크에서 송신·응답·timeout을 관리한다. HTTP 핸들러에서 STM 응답을 기다리지 않는다.
- STM `uart_mvp_protocol.c`에는 이미 PING→PONG, DISARM→ACK 처리가 있다. 첫 구현은 ESP 중심으로 진행하며 기존 STM 명령 계약을 재사용한다.
- DISARM은 출력/저장 명령을0으로 처리하지만 E-stop fault/latch가 남을 수 있다. ACK를 받았다는 이유로 TEL의 FAULT를 오류로 판정하지 않는다.

## 단계별 실행과 완료 조건

| 순서 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 | W4 실제 함수 흐름 복습·새 연결의 기준점 확인 | RX·snapshot·WS와 역방향 명령 경계를 설명할 수 있고 실제 STM TEL 수신 확인. 기존 W4 전체 회귀는 반복하지 않음 |
| 2 | 입력·응답 규칙 정의 | 요청 식별값, 허용 명령, 최대 길이, 연결 소유권, UART seq, timeout과 중복 처리 규칙이 문서/코드에서 일치 |
| 3 | PING 왕복 구현 | 사용자가 코드 입력·저장 → Codex 저장본/관련 검사 확인 → 사용자 빌드·플래시. 브라우저 요청에 정확한 UART PONG만 성공 표시하고 TEL도 계속 갱신 |
| 4 | DISARM 추가 | 일치하는 seq와 type=DISARM ACK만 성공 표시. PWM0 확인과 fault 유지 여부를 별도로 기록 |
| 5 | 실패·연결 변경 검증 | 무효/과대/중복/과속 입력 거부, 응답 누락 timeout, 오래된 응답 무시, 재접속 뒤 자동 재전송 없음 |
| 6 | 마감 | 코드 기준점·로그·사용자 관측·남은 한계와 다음 구동 Gate를 기록 |

한 단계마다 완전한 연결 코드 블록과 입력 범위를 제시한다. 사용자가 입력·빌드·플래시한다.
실패 시 그 단계에서 원인을 확인하며, 첫 세션에 모든 단계를 끝내는 일정으로 강제하지 않는다.

## 첫 구현의 제한 제안

아래 수치는 **W5 제안이며 현재 실행 설정이 아니다.** 연결 코드를 제시할 때 실제 적용값을 확정한다.

| 항목 | 첫 기준 |
| --- | --- |
| 허용 입력 | PING/DISARM만. 원시 UART 문자열·ARM/CMD/ESTOP_RESET은 받지 않음 |
| 크기·속도 | 최대128byte TEXT, 같은 연결의 요청 간격500ms 이상. 크기 확인 후 수신, 형식·필드·범위 검사 |
| 처리 수 | 전체 보드에서 동시에1개 요청만 진행. 대기 요청을 누적하지 않고 busy 반환 |
| 응답 제한 | 송신 후500ms, 사용자 요청은 첫 단계에서 자동 재시도하지 않음. W4 부팅의500ms·최대3회 순서는 별도 유지 |
| 요청 대응 | 브라우저 request_id와 ESP가 발급한 UART seq를 연결. 부팅 seq와 충돌을 피하고 대기 중인 seq·응답 종류에만 matching |
| 연결 변경 | 요청 소유 연결의 세대와 ESP boot_id를 구분. 끊긴 연결의 결과를 새 연결에 전달하거나 이전 명령을 재전송하지 않음 |
| 응답 표시 | 수신/전송 접수와 STM 성공 응답을 구분. timeout/거부/연결 상실을 성공으로 표시하지 않음 |

부팅 응답 확인 중에는 사용자 명령을 섞지 않는다. READY/FAILED는 부팅 이력으로 유지한다.
그 뒤 PING/DISARM은 비구동 진단 범위이므로 TEL stale만으로 timeout 시험을 막지 않는 방식을 검토한다.
실제 ARM/CMD에서는 최신 TEL·현재 세션·PC 명령 유효시간·명시적 재허가가 별도 필수 조건이다.

## 시험 방법과 경계

- **정상:** PING과 DISARM을 각각 보낸 뒤 브라우저 결과, ESP UART 송수신 로그, TEL을 대조한다. 접수만으로 PASS 처리하지 않는다.
- **무효 입력:** 미허용 op, 누락/중복 필드, 잘못된 자료형·크기, 과속 입력을 모의 검사와 실제 WS 입력으로 확인한다. 거부한 입력은 UART로 나가지 않아야 한다.
- **응답 없음:** 두 보드에서 정상 왕복 확인 후 STM RESET을 유지한 상태로 PING을 요청한다.500ms timeout 표시를 확인하고 버튼을 놓은 뒤 새 요청으로 복구한다. 사람이500ms 안에 버튼을 누르는 시험을 요구하지 않는다.
- **늦은/다른 응답:** 오래된 seq·종류가 다른 ACK/PONG·이전 연결 결과가 새 요청을 성공시키지 않는지 모의 검사로 확인한다. 실제 UART 주입은 별도 필요 시 수행하며 코드 검사와 물리 증거를 구분한다.
- **재접속:** WS 재접속·ESP 재기동 뒤 새 요청만 처리한다. 이미 UART로 보낸 명령은 브라우저 연결을 끊어도 취소됐다고 보장하지 않는다.
- **전원 마감:** 사용자가 두 USB를 분리하고 결과를 보고한다. 계획 작성만으로 전원 분리 완료를 기록하지 않는다.

Wi-Fi 밖으로 원격 공개·인터넷 포트 개방은 이 시험 범위가 아니다. 모터 없는 두 보드의 명령 왕복 PASS를
구동 중 통신 유실 안전·물리 비상정지·전체 MVP 완료로 확대하지 않는다.

## 이후 순서

W5 비구동 범위 완료 → ARM/CMD의 세션·유효시간·재허가 계약 → 로봇/전력단 선행 조건 확인 → 별도 실제 구동 시험.
PCB는 여유 시간에 커넥터·핀·전원 연결표를 정리하되, 이 단계에서 제조 회로가 확정됐다고 가정하지 않는다.
