## 1. 이 문서에서 검토할 결론

**로봇에서 실제 센서 데이터를 얻고, 계측 쉴드를 제작·검증하고, 제어·통신과 ROS 2를 연결해 감독하 저속 자율주행까지 재현하는 것**을 전체 완성 목표로 제안한다. 기존 프로젝트 필수 학습인 CAN·STM32 FreeRTOS·선택 경로 HAL→LL도 완료 목록에 포함한다. 강화학습과 영상 AI는 별도 선택 결과물이다.

이번 전압 회로 논의의 직접 종료선은 **외부 감지선부터 ADC·로그까지 포함한 6채널 계측 시스템의 완성**이다. 아래에서는 이 부분을 가장 상세하게 다루고, 이를 로봇 전체의 최종 완성과 연결한다. 첫 MVP의 기존 범위를 소급해서 확대하지 않는다.

기본 진행 방향은 다음과 같다.

1. 알려진 전원·입력·고장·설치 조건을 한 조건표로 모으고, 처리 방법과 결정 기한을 먼저 정한다.
2. 첫 ADC 채널의 실제 코드→PC 로그 경로를 조기에 만든다. 정밀 보정과 PCB 제작은 이 기능 확인의 선행 조건이 아니다.
3. 전체 전원/보호/측정 설계를 묶어 결정하고, 확정 회로→PCB→조립→정량 검증으로 진행한다.
4. Ubuntu·모델·Nav2 시뮬레이션은 PCB 납기를 기다리지 않는다. 실물 연결 때는 실제 센서·속도 제어·정지 조건을 따로 검증한다.
5. 새로 발견한 항목은 이 문서의 요구사항과 연결해 변경한다. 질문 하나를 자동으로 새 장기 과제나 필수 실습으로 늘리지 않는다.

**검토 순서:** §2 완료 범위 → §4 성능/운영 조건 → §6 미결 결정표 → §7 전기 설계 → §8~12 구현·제작·통합 → §13 시험 기준 → §14 일정/작업량.

이 문서는 계획을 작성한 결과다. 부품 채택, 제작 발주, MCU 빌드/플래시, 실물 전원 인가, Ubuntu 설치 또는 기존 검증 상태 변경을 실행하지 않았다. 사용자가 이 문서를 검토한 뒤 적용 범위를 정한다.

### 3.2 이전 진행 방식의 수정

10/23 요구사항에는 이미 무전원 입력과 입력 이상이 있었고, 10/28 회로안에도 감지선 단락 에너지 제한을 후속으로 적어 두었다. 새로 생긴 요구가 아니라 **알고 있던 조건의 해결을 뒤로 미룬 상태**였다. 앞으로는 미결마다 결정 작업·기한·영향받는 단계가 있어야 한다.

### 4.1 이번 완성 범위의 운영 가정

- 초기 실물은 3S LiPo 기반, 실내 건조 환경, 작업자 감독, 저속 운전이다. 구체적 속도·노면·회차 지속 시간은 G4 전에 결정한다.
- 계측은 평균/추세 관측이다. 19kHz PWM 파형 계측, 정밀 RMS/순간 피크, 안전 인증용 과전류 차단은 별도 요구로 취급한다.
- 배터리 저전압·과전류·온도 **자동 정지 기능은 이번에 자동 추가하지 않는다.** 기존 셀 알람/수동 정지와 STM 안전 경로를 유지한다. 자동화는 임계값·지연·오검출/미검출을 별도 결정한 뒤 도입한다.
- 모든 상상 가능한 고장을 시험하지 않는다. §7.3의 알려진 사용/오접속/전원 조건을 설계 입력으로 만들고, 제외하는 조건도 근거와 함께 사용자 검토에 올린다.
- 상용 EMC/ESD 인증, 실외 방수, 장시간 정격 부하, 고급 배터리 모델, 외부 ADC/추가 MCU는 현재 기본 범위에 넣지 않는다. 성능/안전 요구를 달성하지 못한 근거가 생기면 대안을 검토한다.

의존 경로:

- 전기: A0 → E01~E09 → D01~D04/G2 → P01~P04/G3 → H01~H03 → H04~H12/G5.
- 첫 데이터: A0 → A11~A14/G1. 전기 상세 설계 전체 완료를 기다리지 않되, 사용할 **한 채널의 전원·핀·입력 범위**는 먼저 검토한다.
- 계측 구현: G1 → M01~M05. 저전압 시험 구성에서 먼저 개발하고 완성 PCB의 H04~H12에서 정량 판정한다.
- 임베디드: I01~I03은 IMU·엔코더·제어의 해당 연결 조건을 기준으로 시작한다. 계측·제어의 비교 가능한 bare-metal 기준선을 확보한 뒤 F01~F05에 착수한다. 모터 시험은 G4 적용 조건을 추가로 만족해야 한다.
- 시뮬레이션: S01~S03 → S04(첫 주행에 필요한 scan/TF·odom) → N01~N03/G6. S04의 IMU/EKF 비교, S05 모의 계측과 N04 SLAM은 별도 단계다. PCB·실제 ADC·CAN·RTOS·LL과 독립이다.
- 실물 통합: G4 + I01~I03 + R01~R03 + G6 → R04~R06. CAN 전환 전에는 UART 기반 통합을 먼저 검증할 수 있다. 최종 C3에는 CAN 전환 결과가 필요하다.
- 공개: 적용 H/F/R 시험 + C0 인수 처리 → Z01~Z03/G7.

한 사람이 작업하므로 병행은 **같은 시간에 두 작업을 한다는 뜻이 아니다.** 실물/배송/장비 대기 중 다른 경로를 수행하며 §14의 총시간을 공유한다.

### 7.2 전압 보호 저항을 여기서 어디까지 검토하는가

1. 기존 설계30의 2.2kΩ 비교 결과를 재사용한다. 16V 지속 단락 약0.116W, −1% 저항일 때 약0.118W는 해당 가정의 결과다.
2. 최종 운용 전압·설치 온도·열수축/밀폐·도체 고정 조건에 대해 부품 허용 전력/전압과 여유를 대조한다. 과도·역극성 조건까지 이 계산 하나로 보장하지 않는다.
3. 정상 전류에서의 전압 강하·전체 분압비·공차·TCR 영향을 계산한다. TCR는 예상 온도 범위에서 오차 기여의 상한을 계산해 할당 예산보다 작은지 판단한다.
4. 요구를 만족하면 선정 근거를 남기고 종료한다. 별도 온도 학습·무제한 품번 비교를 자동 추가하지 않는다. 설치/정격이 맞지 않으면 퓨즈 등 기존 대안으로 돌아가 선택한다.
5. Rp=2.2kΩ을 채택하는 경우에만 명목 K≈7.272077이 적용된다. 현재 Rp 없는 회로의 K≈6.747204 및 과거 무부하 K≈6.106383과 혼용하지 않는다. 최종 실물 계수는 별도 보정한다.

### 7.4 오차 예산과 샘플링의 종료 기준

- 전압은 분압/보호 부하·누설·기준전압·ADC·보정 잔차·온도 변화·잡음·정착을 최종 입력단 환산 단위로 모은다. 같은 오차를 TUE와 개별 오차로 중복 합산하지 않는다.
- 전류는 센서 자체와 입력회로/ADC를 구분한다. 입력계4.4mV 목표만 통과해 전체 전류 정확도를 통과시키지 않는다. 기준계·센서 영점·감도·실제 부하 구간을 함께 판정한다.
- 온도는 저항 대입 입력계±1°C와 실제 NTC/접촉 전체계를 나눈다. 기준 전압 비가1인 근거 없이 ratiometric 식을 사용하지 않는다.
- 실제 잡음은 예산 0으로 넣지 않는다. 먼저 측정 기록 길이·출력 지표(최대편차/통계량)·운영 조건을 정하고 H08/H11 결과를 배정한다. 독립성을 확인하지 않은 오차를 자동 RSS 합산하지 않는다.
- 2kHz/200개 및 온도2000개는 설정 후보다. 아날로그 감쇠→원시 표본의 alias→평균→출력 decimation을 함께 확인한다. 샘플률을 높였다는 이유만으로 alias 해결로 처리하지 않는다.
- 과거 학습용 C2=100pF를 실제 ADC 핀·스위치·배선·프로브의 총 정전용량으로 확정하지 않는다. E07에서 적용 가능한 범위/최악 조건을 잡고, 실제 취득과 전원 전이 결과로 확인한다.
- ADC 정밀도 미달이면 원인별 조치 한 번→같은 시험 비교로 판단한다. 설명·필기만 늘리는 대신 RC/취득시간/배선/보정 변경 또는 목표 범위 조정 여부를 결정한다.

초기 점검에서 첫 가상 로봇 이동과 첫 실제 ADC 기록의 달성 여부를 각각 확인한다. 첫 Nav2 목표 이동은 odom·TF·scan 연결 뒤 진행한다. 설치/장비 상태에 따라 실제 검증 날짜를 정한다. 이전 MVP 인수 자료 대조는 마감 이력을 재사용한다. 아래 전체 작업량과 제작·최종 인수 조건은 검토본이다.

### 14.3 이후 작업일 묶음 — 최종 단계까지 빠짐없이 배정

| 순서/착수 조건 | 작업일 묶음의 주 내용 | 다음으로 넘기는 결과 |
| --- | --- | --- |
| G2 후, 약3~6작업일 | P01~P04 PCB 배치/배선·제조/기구 검토 | G3 및 사용자 발주 판단 |
| 발주/납기 대기 중 | S01~S05/N01~N04, M01~M04, I01 준비/허용 시험을 시간 내 교대 | 가상 Nav2/실센서 경로. 장비/배송 대기로 학습 범위 확대 금지 |
| 부품/PCB 도착 후, 약2~4작업일 | H01~H03 입고·조립·제한전원·하네스 | H04부터 계측할 준비 |
| 준비 후, 약4~7작업일 | M01~M05/H04~H12 중 아직 남은 구현·보정·정량 시험 | C2 및 G4 적용 조건 |
| 물리 조건 확보 후, 약3~8작업일 | I01~I03 중 미완료 IMU/속도/odom | 실물 ROS가 사용할 단위/속도 계약 |
| bare-metal 기준선 후, 약5~11작업일 | F01~F05 RTOS→CAN통합→선택LL | C3, 통신·부하·안전 회귀 |
| 가상/물리 조건 확보 후, 약4~10작업일 | R01~R06 중 남은 LiDAR·bridge·실물 Nav2 | C5 결과와 실패/제한 |

위 작업일 묶음은 §14.1 노력 추정의 일부를 표현한다. 납기 중에 끝낸 작업을 도착 후 다시 계산/실행하지 않는다. S1+S2의 총40~68h와 일반 수정 여유25%도 전체 가용시간 안에 들어가야 한다. 매5작업일마다 남은 노력/실제 납기만 재산정하고 완료한 작업의 기준을 소급 변경하지 않는다.

## 15. 작업 운영·변경·문서 관리

역할은 기존 작업 방식을 유지한다. 사용자는 학습 대상 STM32/ESP32 코드 입력·빌드·플래시·실물 배선/계측·설치/구매 판단을 맡는다. Codex는 조건/계산·연결된 코드 단위의 설명/검토·허용된 분석 도구·문서/자료 대조를 맡고, 직접 편집을 위임받은 범위는 실행한다. 각 작업을 시작할 때 목적·이번 결과물·필요한 확인·종료 기준을 한 번에 제시한다.

### 15.1 세부 검토를 끝내는 규칙

- 각 작업은 **설계 결정, 실행 데이터, 해결한 결함** 중 하나를 결과로 남긴다. 필기는 그 결론과 근거를 재구성하는 용도다.
- 학습은 해당 작업을 수행하는 데 필요한 범위로 한다. 하루6시간 예시는 구현/설계 결정/측정4시간, 필요한 학습1.5시간, 기록0.5시간이며 고정 강제 비율은 아니다.
- 새로운 검토 항목은 관련 PLAN-R-ID·실제 위험/성능 영향·필요 근거·예상 시간·끝내는 조건을 적는다. 현재 Gate와 관계가 없으면 후속 목록으로 보낸다.
- 수치상 영향이 할당 예산보다 작고 가정이 적용 범위를 덮으면 해당 검토는 닫는다. 다시 여는 사유는 부품/조건 변경, 실패 관측, 근거 오류 또는 사용자 요청이다.
- 필수 안전 조건이 해결되지 않으면 해당 물리 실행은 보류한다. 관련 없는 코드/시뮬레이션/문서 작업까지 일괄 중단하지 않는다.

### 15.2 변경 시 영향 확인

| 변경 대상 | 함께 다시 확인할 자료/시험 |
| --- | --- |
| Rp/분압/보호/RC/공급 | 전달비·오차·정착·무전원/과도·ADC 설정·회로/BOM·하네스·보정 버전 |
| 커넥터/핀/풋프린트 | 심벌/패드·넷·실물 케이블 방향·기구·입고/조립 검사 |
| 샘플률/평균 | ADC budget·alias·응답·timestamp·CPU/DMA·출력률·시험 결과 |
| CAN/RTOS/LL/ROS 명령 | owner·freshness·timeout·boot/fault·로그·기존 정지 회귀 |
| 제어/로봇 형상/센서 위치 | odom·TF·footprint·속도/정지거리·Nav2 기준선/실물 시험 |

매일 기록은 작업 ID·실행/결정·근거 경로·PASS/FAIL/미실행·다음 행동으로 제한한다. 회차별 로그/사진을 문서마다 복제하지 않고 원본을 링크한다. 필기/이해/실측 완료는 사용자 보고와 실제 증거를 구분한다.

회로가 바뀌면 기본 KiCad exports PDF와 reports/BOM을 함께 갱신한다. 날짜별 applied.pdf·이전 실습·NotebookLM 자료는 역사 자료로 보존한다. 이번 계획 작성만으로 PDF를 다시 내보내지 않는다.

마감 요청 시 기존 규칙대로 문서/진행·관련 파생물 누락 점검/Git/Calendar/Notion의 다섯 항목을 처리한다. 이번에는 **검토용 계획 문서 작성**이며 외부 일정이나 Notion 작업의 상태를 확정하지 않는다.
