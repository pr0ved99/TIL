## 추가 카펫 주행과 S0 복구 자료 — 편집 전 이력

사용자가100×150cm 카펫·1m 이상 주행과 S0→해제→S2→STM reset→수동 재개 영상을 추가했다. [판독](../../assets/logs/wifi_link/2026-10-24_carpet_s0_demo_run01/observations.json)에서 카펫 이동과 두 번의 FAULT_ACTIVE→LATCHED→DISARMED/BOOT, ARM 비활성/재허용 및 후속 주행 표본을 확인했다. 대표 본편은 **카펫 연속 주행→S0 정지→S2 뒤에도 래치/ARM 차단→STM reset 뒤 ARM 재허용→새 ARM/짧은 주행→DISARM 종료** 흐름을 권한다. 두 번째 회차의 화면122~123.6초는 금지 커서에서 활성 버튼으로 바뀌는 구간이 명확하다.

이 절은 편집 전 판독이며 새 통합본 제작 완료는 상단을 따른다. 아래65초 탁상 편집본도 보존한다. 카펫 치수와1m 이상은 사용자 보고이고 거리 정확도·자동 정지/지연 계측으로 소개하지 않는다. READY/IDLE가 FAULT 중에도 유지되므로 STM 상태와 ARM 허가를 함께 보여준다. S0/S2/reset 조작 명칭·순서는 사용자 설명에 연결하고 편집 때 두 파일의 시각을 별도로 정렬한다.

## 자막 기준

- 제목 제안: **STM32·ESP32 궤도 로봇 — 무선 수동 주행·정지와 엔코더 거리 기록**.
- 현재 cap150/200‰, 왼쪽gain960/930, STM timeout300ms를 표시한다.23.50μs는 과거 MCU 로직 핀 출력 차단 계측이며 실제 로봇 정지시간으로 바꾸지 않는다.
- 브라우저 `100mm/s`는 요청값이다. 엔코더 추정 거리·사용자 줄자 실측·물리 정지·통신/JS 처리 시간을 구분한다.
- 물리 S0와 소프트웨어 DISARM을 별도 표시한다. 기존 S0 관측을 전체 정격·단일고장 안전 인증으로 소개하지 않는다.
- 작업자 역할은 요구사항/배선·기구/펌웨어 입력·빌드/실물 검증으로 명시하고, Codex 지원은 검토·로그 분석·검증 코드/문서로 구분한다.

## 제작 재개점

**다음은 위 전후진15.042초·회전21.875초 원본을 재생 검토하고, 기존 자료만으로 편집본을 만드는 단계다.** 이번에는 편집 순서/내레이션까지 준비했으며 새 완성 영상은 없다. 미확인 음성·개인정보와 자막의 회차 일치를 먼저 확인한다. 새 촬영이나 완료 시험의 반복을 먼저 요구하지 않는다. 별도 촬영을 선택할 때만 실제 전원·배선·주변 조건을 확인한 뒤 한 단계씩 진행한다.

최종 게시 전에는 영상 파일과 로그 회차, 소스/이미지 기준, 미완료 판정, 공개 파일 목록을 맞춘다. 현재 요청은 문서 작성이며 Git commit/push·Calendar·Notion 또는 영상 공개는 수행하지 않았다.
