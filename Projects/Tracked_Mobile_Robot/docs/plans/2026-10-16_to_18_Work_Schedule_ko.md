# 10월 16–18일 작업 일정

> 2026-10-17 마감: UR-02와 AC-S01~08 선택 zero-only 실물 시나리오는 완료했다. [최신 완료 범위와 근거](../verification/37_Zero_Only_ACS_Bench_Closeout_2026-10-17_ko.md)를 우선한다. 아래 당시 계획·미완료·실패 기록과 원래 수용 조건은 보존한다.

기준: 2026-10-16. 현재 UART 줄 폐기/부분 명령 시험의 준비 상태를 반영한 **작업 시간 예약안**이다. 캘린더 이벤트의 완료 여부나 시험 PASS를 의미하지 않는다.

- [Notion 일정표](https://app.notion.com/p/3faa7326f87b8122b119d7a9de00fe50)
- [Google 캘린더 가져오기 파일](calendar/2026-10-16_to_18_work_schedule.ics) — 11개 일정, 한국시간, 각 시작 10분 전 알림을 파일에 포함.
- **등록 상태:** Google Calendar 플러그인 설치는 확인했지만 이 대화에는 일정 조회·생성 도구가 없다. 실제 등록·기존 일정 충돌·알림 반영은 미확인이다.
- 사용 가능 시간은 12:00–00:00. 사용자 확인에 따라 **10/16(금) 17:00 이후는 러닝 때문에 비운다.** 10/17·18은 17:00–18:00 저녁, 나머지 빈 시간은 휴식·지연 여유로 남긴다.

## 각 작업의 완료 기준

### 10-16 12:00 · UART 시험 입력 설계

- 목표: ESP의 기존 UART 송신 경로를 이용해 부분 명령을 넣을 수 있는 제한된 시험 기능을 설계한다.
- 완료 기준: 기본 비활성·수동 시작·IDLE/fresh/zero·송신 경합 방지·실패 시 BLOCKED 조건과 교체 범위를 정리한다.
- 진행 조건: 보고서36의 완료 범위를 유지하고 기존 정상 재연결 시험은 반복하지 않는다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-16 13:45 · 시험 코드 입력·저장본 검토

- 목표: 검토한 연결 코드 블록을 사용자 입력 후 실제 저장본과 대조한다.
- 완료 기준: 정확한 교체 범위와 코드 설명을 확인하고 오타·상태 전이·기존 정지 조건을 검토한다.
- 진행 조건: 앞 블록의 설계가 준비되지 않으면 설계·PC 후보 검토를 이어간다. 성급히 플래시하지 않는다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-16 16:00 · PC 검사·금요일 마감

- 목표: 미완성 CMD와 LF 없는 ARM 조건을 PC에서 검사하고 다음 재개 지점을 남긴다.
- 완료 기준: 검사 결과와 미완료 항목을 기록하고 17:00에 작업을 마친다.
- 진행 조건: 17:00 이후는 저녁과 러닝을 위해 비운다. 검사 미완료는 토요일 첫 블록으로 이월한다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-17 12:00 · 사용자 빌드·시험 시작 준비

- 목표: PC 검토를 통과한 코드의 STM/ESP 빌드와 필요한 플래시·부팅 확인을 진행한다.
- 완료 기준: 사용자 빌드 결과와 READY/IDLE·fresh TEL 등 시험 시작 조건을 확인한다.
- 진행 조건: PC 검토 완료가 선행 조건이다. 사용자 보드 조작 전 현재 전원·배선과 프로브 위치를 확인한다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-17 13:15 · 부분 CMD 복구 캡처

- 목표: 미완성 CMD를 남긴 뒤 CAN+LF와 첫 DISARM 복구를 UART 양끝에서 관측한다.
- 완료 기준: 의도한 prefix·폐기·첫 DISARM의 정확한 ACK·새 정지 TEL을 한 증거 묶음에 저장한다.
- 진행 조건: 시험 입력 기능과 시작 조건이 준비됐을 때만 실행한다. 준비가 안 됐으면 앞 작업을 이어간다. 속도 0·B+ 분리 조건.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-17 15:00 · LF 없는 ARM 폐기 캡처

- 목표: 줄 끝 LF가 없는 ARM이 복구 과정에서 실행되지 않고 폐기되는지 확인한다.
- 완료 기준: 오래된 ARM 실행·ACK 없음과 새 DISARM 복구 결과를 원본 캡처·로그로 남긴다.
- 진행 조건: 앞선 시험의 예상 밖 결과는 먼저 분석한다. 속도 0·B+ 분리 조건이며 자세한 조작 순서는 실행 직전에 검토한다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-17 18:00 · UART 결과 해독·판정

- 목표: 두 부분 명령 시험의 캡처와 응답을 대조하고 보고서36·Notion에 결과를 반영한다.
- 완료 기준: 각 조건을 PASS/미확인/실패로 구분하고 원본 경로와 다음 행동을 남긴다.
- 진행 조건: 캡처가 없으면 준비·실패 원인을 정리한다. 전체 AC-S나 실제 모터 안전 완료로 확대하지 않는다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-18 12:00 · AC-S 잔여 항목 점검·보완

- 목표: 현재 이미지 CMD-only 거부와 선택적 ACK 유실·지연 등 남은 항목을 정리한다.
- 완료 기준: 실행 가능한 한 묶음의 결과 또는 필요한 시험 도구·PC 검토안을 남긴다.
- 진행 조건: UR-02가 남아 있으면 이 시간을 우선 사용한다. 선택적 ACK 시험 기능은 준비 상태에 따라 설계·PC 검토까지만 진행한다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81ea8108eeef0aedd8f8)

### 10-18 14:15 · PWM·PC7 계측 준비와 확인

- 목표: UART 결과와 실제 출력 LOW·E-stop 입력을 구분할 수 있도록 계측 계획을 세운다.
- 완료 기준: 현재 실물의 측정점을 검토하고 준비가 되면 zero-only에서 파형을 저장한다. 미준비면 다음 계측 절차를 확정한다.
- 진행 조건: 물리 연결은 사용자 확인 뒤 단계별로 진행한다. 모터 전력·주행 시험으로 확장하지 않는다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81d6ae14e64ce21019ca)

### 10-18 18:00 · 주간 결과·Notion 정리

- 목표: 완료한 시험과 남은 조건을 저장소 기록과 Notion 진행 지도에 맞춘다.
- 완료 기준: 보고서·검증 매트릭스·현재 위치·다음 체크리스트의 상태와 근거가 일치한다.
- 진행 조건: 코드·원시 증거는 저장소, 요약과 탐색은 Notion에 둔다. Git 변경 범위 점검까지만 하며 commit/push는 별도 요청을 따른다.
- [관련 Notion](https://app.notion.com/p/3faa7326f87b81d6ae14e64ce21019ca)

### 10-18 19:45 · 다음 주 작업 시간 확정

- 완료 기준: 다음 1~3개 작업, 선행 조건, 시작·종료 시간을 정리한다.
- 진행 조건: 미완료를 우선 이월한다. 실제 일정 예약과 기존 개인 일정 충돌은 캘린더 연결 확인 뒤 조정한다.

## 진행 원칙

앞 작업이 끝나지 않으면 다음 블록을 미완료 작업에 사용한다. 10/18 종료 시 UR-02/AC-S의 전체 완료를 보장하지 않는다. 현재 앱은 zero-only이고 부분 명령 주입 기능은 이 일정 작성 시 미구현이다. 설계·PC 검토 뒤 사용자가 코드 입력·빌드·플래시하고, 보드 시험 시작 전 실제 전원·배선·측정점과 구체적 절차를 확인한다. 상세 조건은 [UR 계획](2026-10-16_WiFi_UART_Recovery_Bench_Plan_ko.md), 이미 확보한 결과는 [보고서36](../verification/36_UART_Line_Cancel_Recovery_2026-10-16_ko.md)을 따른다.

## Google 캘린더 가져오기

1. PC에서 Google 캘린더를 연다.
2. **설정 → 가져오기 및 내보내기 → 컴퓨터에서 파일 선택**으로 위 ICS 파일을 선택한다.
3. 넣을 캘린더를 선택하고 **가져오기**를 누른다.
4. 11개 일정, 한국시간, 10/16 저녁 공백과 알림을 확인한다. 파일은 한 번만 가져오고 이후 수정은 등록된 일정에서 진행한다.

[Google 공식 가져오기 안내](https://support.google.com/calendar/answer/37118?hl=ko). 가져오기는 자동 동기화가 아니다. Notion 체크박스와 캘린더도 자동으로 동기화하지 않는다. 고정 UID는 이벤트 식별용이며 Google에서 반복 가져오기의 갱신/중복 방지를 보장하는 것으로 해석하지 않는다. 파일의 알림이 실제 계정/앱에서 반영됐는지는 가져온 뒤 확인한다.

이번 작업은 계획·문서·가져오기 파일 준비이며 펌웨어 수정, 보드 빌드/플래시, 실제 캘린더 등록, Git commit/push를 실행하지 않았다.
