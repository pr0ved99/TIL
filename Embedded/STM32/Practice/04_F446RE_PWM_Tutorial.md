# [STM32] 하드웨어 타이머(Timer)를 활용한 PWM LED 제어 실습

## 🎯 목표
소프트웨어적인 `HAL_Delay()` 지연 함수 없이, STM32 내부 타이머(Timer) 모듈의 **PWM(Pulse Width Modulation)** 기능을 사용하여 **초록색 LED(LD2)**를 하드웨어적으로 점멸시킨다.

## 📖 PWM(Pulse Width Modulation)이란?
디지털 신호의 켜짐(HIGH)과 꺼짐(LOW) 비율(Duty Cycle)을 자유자재로 조절하여, 아날로그와 같은 연속적인 출력을 만들어내는 기법이다.
이번 실습에서는 `while` 문 안에서 무의미한 CPU 대기 시간을 낭비하지 않고, **타이머 하드웨어가 백그라운드에서 스스로 LED를 켜고 끄도록 설정**하여 효율성을 극대화한다.

---

## 💻 실습 진행 단계

### 1. 프로젝트 생성
* 새로운 프로젝트를 생성한다. (참고 프로젝트명: `F446RE_PWM_1`)

### 2. GPIO 핀 역할 변경 (타이머 연결)
실제로 보드의 초록색 LED(LD2)는 `PA5` 핀에 연결되어 있다. 이 핀은 다행히 타이머 2(TIM2)의 채널 1(CH1)과 하드웨어적으로 직결(Alternate Function)될 수 있다.

* `Pinout & Configuration` 화면에서 **PA5** 핀을 클릭하고 `TIM2_CH1`으로 역할을 변경한다.
  * *기존 `GPIO_Output` 모드에서 타이머 제어 모드로 권한을 넘겨줌을 의미한다.*

### 3. 타이머(TIM2) 파라미터 세팅
이제 좌측 메뉴의 `Timers` > `TIM2` 탭으로 이동하여 PWM 동작을 위한 핵심 환경을 구성한다.

* **Mode (동작 모드 설정):**
  * `Clock Source`를 **Internal Clock** (내부 시스템 클럭)으로 설정한다.
  * `Channel1`을 **PWM Generation CH1**으로 활성화시킨다.

* **Configuration > Parameter Settings (주기 및 듀티 설정):**
  * 시스템 클럭(예: 64MHz)이 타이머로 공급될 때, 속도를 적절히 낮추어 우리가 눈으로 볼 수 있는 깜빡임 주파수(예: 8Hz)를 만들어낸다.
  * **Prescaler (PSC):** `127` (클럭 속도를 128로 나누어 분주하는 역할)
  * **Counter Period (ARR):** `62499` (타이머가 0부터 이 숫자까지 세고 다시 0으로 돌아올 주기)
  * **Pulse (CCR1):** `31250` (한 주기 안에서 HIGH 상태를 유지할 시간. ARR의 딱 절반이므로 **50% 비율(Duty Cycle)**로 설정됨)

### 4. 메인 코드 작성 (`main.c`)
타이머와 PWM 하드웨어 설정이 끝났으니, 이제 코드에서는 타이머를 단 한 번 '시작(Start)' 시켜주기만 하면 된다.

* `main.c` 파일 내부의 `main` 함수 안, `while (1)` 반복문에 진입하기 직전(`/* USER CODE BEGIN 2 */` 영역)에 아래 코드를 추가한다.

```c
  /* USER CODE BEGIN 2 */
  
  // Timer 2번의 Channel 1을 파라미터 설정에 맞게 PWM 모드로 시작시킴
  HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);
  
  /* USER CODE END 2 */
```

* 놀랍게도 **`while (1)` 무한 루프 내부에는 아무런 로직도 작성할 필요가 없다.** 한 번 시작 명령을 받은 PWM 모듈은 CPU의 개입 없이 내부 타이머 하드웨어에 의해 독립적으로, 완벽한 주기로 LED를 제어한다.

---

## 📌 결과 확인 및 느낀 점

* 작성한 코드를 타겟 보드에 빌드 및 업로드(Run) 한다.
* 코드가 실행되면 보드의 초록색 LED(LD2)가 일정한 속도(8Hz)로 반짝이는 것을 볼 수 있다. 
* 이전 실습까지는 `HAL_Delay()`를 사용하며 단순히 루프 안에서 CPU 자원을 붙잡아 두고 있었지만, 하드웨어 타이머를 활용하니 **소프트웨어의 부하(Overhead)를 완벽하게 줄이고 백그라운드 작업을 효율적으로 분리할 수 있다**는 점을 깨달았다.
