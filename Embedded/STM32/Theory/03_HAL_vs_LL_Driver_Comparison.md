# STM32 HAL Driver와 LL(Low-Layer) API의 차이점 완벽 정리

## 📌 개요

STM32 마이크로컨트롤러 개발 환경(STM32Cube)에서 하드웨어를 제어하기 위해 제공되는 두 가지 주요 API 스타일은 **HAL(Hardware Abstraction Layer)** 과 **LL(Low Layer)** 이다. 이 두 라이브러리는 추상화 수준, 성능, 그리고 개발 목적에 따라 명확한 장단점을 가지며, STM32CubeMX 코드 생성 시 선택할 수 있다.

## 1. HAL (Hardware Abstraction Layer)의 특징

HAL은 하드웨어의 복잡성을 "추상화"하여 레지스터에 대한 깊은 지식 없이도 직관적으로 주변장치를 제어할 수 있게 해주는 고수준(High-level) 라이브러리이다. STM32CubeMX에서 기본적으로 코드를 자동 생성해 준다.

* **쉬운 사용법 및 명확한 구조:** `HAL_GPIO_TogglePin()`과 같이 간편하고 명확한 API 함수를 제공하여 초기 개발이 매우 빠르다. 구조가 명확해 디버깅 난이도가 낮고 유지보수에 유리하다.
* **뛰어난 이식성(Portability):** 코드 구조가 하드웨어에 종속되지 않아, 다른 STM32 계열의 칩으로 프로젝트를 변경하더라도 코드의 재사용이 매우 쉽다.
* **팀 단위 및 교육용 최적화:** 가독성이 우수하므로 초보자의 학습용이나 여러 명의 팀원이 투입되는 대규모 프로젝트에 적합하다.
* **단점 (성능 저하 및 메모리 낭비):** 다양한 예외 처리와 내부 콜백(Callback) 함수를 거쳐야 하므로 오버헤드가 발생하여 실행 속도가 상대적으로 느리다. 또한, 컴파일된 코드의 크기가 크다.

## 2. LL (Low-Layer)의 특징

LL은 HAL보다 하드웨어에 훨씬 가깝게 설계된 저수준(Low-level)의 전문가 지향 라이브러리로, 실제 레지스터를 직접 제어하는 방식과 거의 동일하다.

* **압도적인 성능과 가벼운 용량:** 소프트웨어적인 오버헤드가 거의 없고 상태 저장을 위한 추가 메모리를 요구하지 않기 때문에, 코드 크기가 매우 작고 하드웨어 한계치에 가까운 빠른 실행 속도를 자랑한다. 실제로 HAL 대신 LL을 사용하여 UART 통신을 구현했을 때 코드 사이즈가 절반 이하로 줄어드는 사례도 있다.
* **정밀한 실시간 제어:** 개발자가 직접 인터럽트 핸들러를 작성하여 즉각적인 응답이 가능하므로, 속도와 타이밍이 생명인 실시간 제어(Real-time) 환경에 적합하다. 저사양 MCU에서 성능의 한계를 극복할 때 유용하다.
* **독립적 사용 가능:** HAL과 독립적으로 단독 사용하거나, HAL과 혼용하여(Mixed mode) 사용할 수 있는 유연성을 제공한다.
* **단점 (높은 진입 장벽과 낮은 이식성):** MCU의 데이터시트와 레지스터 구조에 대한 깊은 이해가 필수적이라 개발 및 디버깅 난이도가 높다. 또한, 칩의 라인업이 바뀌면 레지스터 구조가 달라지므로 코드를 대대적으로 수정해야 하는 낮은 이식성을 가진다.
* **단점 (수동 설정의 번거로움):** HAL에서는 툴이 알아서 활성화해주던 요소(예: SysTick 타이머, 특정 통신 비트 등)를 개발자가 일일이 수동으로 세팅해야 한다. USB와 같이 복잡한 소프트웨어 스택이 필요한 기능에는 LL API가 아예 제공되지 않는다.

## 3. 핵심 요약 비교표

| 항목 | HAL (Hardware Abstraction Layer) | LL (Low Layer) |
| --- | --- | --- |
| **레벨 (추상화 수준)** | 상위 레벨 (높음) | 하위 레벨 (낮음, 레지스터 근접) |
| **성능 (실행 속도)** | 상대적으로 느림 (오버헤드 발생) | 매우 빠름 (레지스터 직접 제어) |
| **코드 및 메모리 크기** | 큼 | 매우 작음 |
| **구현 및 디버깅 난이도** | 낮음 (사용 쉬움) | 높음 (데이터시트 이해 및 직접 추적 필요) |
| **이식성 (Portability)** | 매우 우수 | 제한적 (기기마다 다름) |
| **인터럽트(ISR) 처리** | 내부 처리 후 콜백 함수 실행 | 직접 핸들러 작성하여 빠른 응답 가능 |
| **추천 사용처** | 빠른 개발, 일반적인 제어, 협업 프로젝트 | 고속 실시간 제어, 메모리 최적화, 저사양 MCU |

## 💡 언제 어떻게 사용해야 할까? (실무 혼용 전략)

* 어느 한쪽이 무조건 좋다고 할 수 없으며, 프로젝트의 목적과 상황에 맞게 적절한 방식을 취하는 것이 중요하다.
* 처음 개발을 시작할 때나, 개발 속도 및 유지보수가 최우선인 상황에서는 **HAL을 기본 바탕으로 프로젝트를 구성**하는 것이 권장된다.
* **하이브리드(Mixed) 방식:** 가장 현실적이고 효율적인 최적화 전략이다. 전체적인 구조와 초기화는 다루기 쉬운 HAL로 작성하되, 응답 시간이 생명인 외부 인터럽트나 마이크로초 단위의 정밀한 통신(USART 등)이 필요한 특정 구간에서만 **LL을 혼용하여 핀포인트로 최적화**하는 방식이 실무에서 흔하게 쓰인다.
